ov-rf-tuning

SKILL 来源页码: p361-380 (RF Management and Optimization)

RF 调优参数表 (OmniVista / Stellar)

R — 原文 (Reading)

"Recommended value: 2.4G = 5, 5G = 10 [Association RSSI]... 2.4G client minimum data rate control → recommended value 12... 5G → 24... Default interval = 20 sec... Default Duration = 50 ms"

— ALE Training, RF Management, p369-373

I — 方法论骨架 (Interpretation)

  1. DRM 心智模型: 无控制器架构下每个 AP 经空中协议发现邻居、共享 RF 上下文(信道利用率/干扰、每 band 客户端数、功率)，各自基于上下文自主做 RF 动作(try/wait/retry)，作用域限于邻居 AP。排障看邻居关系与 RF Profile，而非找"控制器"。RF Profile(含国家码)挂 AP Group 或单 AP。
  2. 负载均衡双机制(正交可独立启用): Band Steering 管"频段间"——按客户端数差(阈值 10；三射频用 Pri-Diff/Sec-Diff)引导到 5/6GHz；Dynamic Load Balance 管"AP 间"——各 AP 按自身客户端数设应答定时器，并用关联 RSSI 门限拒绝/踢除过弱客户端(推荐 2.4G=5、5G=10)。信道过载官方定义: 1 分钟平均介质利用率 >70%。
  3. 可直接引用的推荐参数表 (RF Profile):
  4. Smart Air Share 最小数据速率: 2.4G=12 Mbps、5G=24、6G=24
  5. 背景扫描: 默认间隔 20s(5-10800s)/时长 50ms(50-110ms)，仅 WIPS 需要时开启
  6. SNR/信号门限: 低值 10(容纳弱客户端、吞吐低) vs 高值 25(拒弱客户端、吞吐好)
  7. 信道/功率: Auto 优于静态；密集部署窄信道宽、稀疏部署宽信道宽；SGI 默认开，RF 差且拥挤时关
  8. RSSI 判定表: RSSI 10-43 ↔ -86~-53 dBm(每 +1 RSSI=+1dBm)。10-20(-86~-76)=差，不建议音视频；21-28(-75~-68)=尚可；≥29(-67 以上)=推荐。OV 显示平均值，AP CLI wlanconfig ath002 list 看瞬时值。

A1 — 书中的应用 (Past Application)

案例 1: RF Profile 调优基线 (p361-379)

  • 问题: 网络优化需要一套可抄用、可对比的调优基线。
  • 方法论的使用: 在 RF Profile 中按推荐表设定 Band Steering 开、DLB 开(2.4G=5/5G=10)、最小速率 12/24、扫描默认 20s/50ms、信道功率 Auto。
  • 结论: 形成"优化前/后对比"的可量化基线；RSSI 速查表用于评估弱信号投诉与覆盖验收。
  • 结果: 弱信号客户端被门限拒联，低速客户端被最小速率挡住，整体空口效率提升。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 客户投诉"信号差/网慢"，需要判读 RSSI 值并给出调参方案。
  2. 高密(会议室/场馆)或稀疏部署的信道宽度/功率/最小速率规划。
  3. 弱信号客户端拖慢全网、需要关联门限或 Band Steering/DLB 调优；或纠结背景扫描开不开(安全 vs 性能)。

语言信号 (用户的话里出现这些就应激活)

  • "RSSI 多少算好 / -75dBm 什么水平"
  • "band steering / dynamic load balance 阈值设多少"
  • "信道宽度 20 还是 40 / 高密部署怎么设 / channel width"
  • "扫描要不要开 / WIPS 影响性能吗 / background scanning"

与相邻 skill 的区分

  • 与 ov-roaming-troubleshoot 的区别: 那个解决"移动中切换 AP 失败"(判定表/Neighbor AP/Roaming RSSI 2.4G=10、5G=15)；本 skill 是静态射频质量与吞吐调优(关联门限 2.4G=5、5G=10，两者不是同一个参数)。
  • 与 ov-wips-rogue-policy 的区别: 那个处理 Rogue/攻击判定与抑制；本 skill 只在"扫描权衡"处与其交界。

E — 可执行步骤 (Execution)

  1. 判读现状: 用 RSSI 判定表(10-20 差/21-28 尚可/29+ 推荐；OV 平均值 vs CLI 瞬时值)对投诉区域或客户端信号分级，确认问题属"覆盖差"还是"弱客户端拖累"。
  2. 完成标准: 给出目标对象 RSSI 分级结论与 dBm 换算值。
  3. 按推荐表出参数方案: 对照 RF Profile 推荐表逐项给值——Band Steering/DLB 开、关联门限 2.4G=5/5G=10、最小速率 12/24/24、SNR 门限按吞吐 vs 覆盖取舍(10 vs 25)、信道功率 Auto、信道宽度按密度(密窄疏宽)、SGI 按 RF 环境、背景扫描仅 WIPS 需要时开且保持 20s/50ms 默认。
  4. 判停条件: 若判读显示问题是"跨 AP 移动掉线"而非静态信号质量，转到 ov-roaming-troubleshoot。
  5. 完成标准: 每项参数给出值 + 一句取舍理由。
  6. 交代后果与验证: 说明所调参数的过高/过低后果(如关联门限过低→弱客户端拖累吞吐、过高→边缘无法关联)，并约定优化后用 QoE/Client Analytics 对比 RSSI 与吞吐。
  7. 完成标准: 参数方案 + 双向风险说明 + 验证指标齐备。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 漫游失败/粘性客户端(移动切换问题) → ov-roaming-troubleshoot(Roaming RSSI 门限 2.4G=10、5G=15 属那个 skill)。
  • Rogue AP/攻击事件处置 → ov-wips-rogue-policy。
  • 有线侧问题、设备激活问题 → 对应 skill。

作者在书中警告的失败模式

  • 关联 RSSI 门限失衡 (p370/376): 阈值过低→大量弱信号客户端接入拖累整体吞吐；过高→弱信号区域彻底无法关联，出现"覆盖死角"投诉。默认建议 2.4G=5、5G=10。
  • 背景扫描性能/安全权衡 (p373/376): 扫描期间该射频无 802.11 数据；间隔↑或时长↓→入侵漏检↑但客户端性能↑，反之亦然。保持默认 20s/50ms；高保真检测用专用扫描 AP 或开 Voice/Video Awareness 跳过有会话的 AP。
  • RSSI 原始值当 dBm 读 (p378-379): RSSI 20 实为 -76dBm；RSSI<20 区域承诺音视频业务会翻车。
  • 静态信道/功率劣于 Auto (p374-376): 手工静态指定不做邻居协同导致同频干扰；密集部署用大信道宽度加剧邻道干扰；RF 差且拥挤时应关 SGI。

作者的盲点 / 时代局限

  • 推荐值为培训基线，实际高密/高干扰环境需 site survey 后微调，不宜照抄当红线。
  • 6GHz 相关参数(6G=24 等)基于当时版本，后续版本可能调整。

容易混淆的邻近方法论

  • 关联 RSSI 门限(DLB，2.4G=5/5G=10，准入控制) vs Roaming RSSI 门限(2.4G=10/5G=15，引导切换)——名字相似、参数不同、用途不同，是同书最易混淆的一对参数。
  • RSSI(信号强度) vs SNR(信噪比)——RF Profile 门限字段名为 Signal Strength/Client SNR，汇报时勿混用单位。

相关 skills (阶段 3 填充)

  • contrasts-with ov-roaming-troubleshoot: 本 skill 管静态射频质量与吞吐（DLB 关联 RSSI 门限 2.4G=5/5G=10，准入控制）；那个管跨 AP 移动连续性（Roaming RSSI 2.4G=10/5G=15，引导切换）。名字相似、数值不同、用途不同——同书最易混淆的一对参数，两者共享 RF Profile 配置入口。
  • composes-with ov-wips-rogue-policy: 背景扫描参数（默认 20s/50ms）两边都管——性能诉求（扫描伤吞吐）归本 skill，检测保真诉求（漏检 Rogue）归 WIPS skill；"仅 WIPS 需要时开启扫描"是两者的共同结论。
