ov-device-activation-troubleshoot

SKILL 来源页码: p140-172

设备激活状态机排障

R — 原文 (Reading)

"Expected Activation Status: Up to 5 minutes. Activation Status failures: Failed To Get Certificate, Upgrade Failed, Configuring VPN Failed, Provisioning Failed, Device Validation Failed, Factory Reset Required." "Factory Reset required: The VPN profile was changed/updated."

— ALE Training, Stellar AP / OmniSwitch Onboarding, p146-147, 166-167

I — 方法论骨架 (Interpretation)

设备纳管是一条可诊断的状态链，排障入口是"先定位卡在哪个状态，再按该状态的语义定位故障域"，而非盲目重启：

正常链：Waiting for first contact → Obtaining Certificate → Registered → (Upgrade) → Assigned → VPN Configuring → Connected to OV → Provisioning → OV Managed。每个中间态最长约 5 分钟。

失败状态处置表：

失败状态 含义 / 下一步
Failed To Get Certificate 服务器证书创建失败 → 查 NTP 时间同步、设备可达性；若设备曾被其他平台管理 → 清证书
Upgrade Failed 版本升级失败 → 查镜像服务器与软件版本（低于最低版本先升级）
Configuring VPN Failed 传输通道建立失败 → 查防火墙 9093/30123-30125（Cirrus）
Provisioning Failed 设备无法处理下发配置或平台发现不了设备 → 查 Provisioning 配置与可达性
Device Validation Failed 设备验证失败
Factory Reset Required VPN profile 变更过 → 必须恢复出厂，普通重启无效
Unsupported Device Model AP1101/AP1201L/H/HL 不受支持

前置核查（先于状态机）：DHCP options 1/3/6/28/42/43（代理加 129-138）、防火墙出向 443/80/123/53、≥1 台 NTP、AWOS ≥4.0.6（Terra 4.0.7.14）/ AOS ≥8.9R1。

平台迁移特例（Cirrus→Terra）：AP 删 /.ocloud/ 下证书文件 + DHCP option 43 改 activation.myovterra.com + firstboot/reboot；交换机删 switch/cloud 下 5 个证书文件 + 改 /working/cloudagent.cfg 首行 URL。

重触发与 CLI：重启 cloud-agent 进程或整机；cloud-agent admin-state disable force 重建 VPN；cloud-agent discovery-interval 默认 30 分钟；AP 侧 ocloud_show，交换机 show cloud-agent status / show cloud-agent vpn status；OV 侧看 Activation Log。

A1 — 书中的应用 (Past Application)

案例 1: AP 从 Cirrus 迁 Terra 反复取证书失败（c06/ce09, p140-150）

  • 问题: 曾被 Cirrus 管理的 AP 指向 Terra 后显示 "Certificate Previously Issued" / 取证书失败。
  • 方法论的使用: 状态定位在 Obtaining Certificate 失败 → 根因是残留旧平台证书 → rm -rf /.ocloud/ 清证书 → option 43 改指 activation.myovterra.com → firstboot + reboot。
  • 结果: AP 以全新状态重走激活链，到达 OV Managed。

案例 2: 交换机 call-home 不生效（c07/ce07, p160-172）

  • 问题: OmniSwitch 声明后长期不上线。
  • 方法论的使用: show cloud-agent status 看 Device State/Certificate Status/Discovery Retry Count → 修正 cloudagent.cfg 或重启 cloud-agent 进程；VPN 异常用 admin-state disable force 重建。
  • 结果: 交换机 OV Managed，可接受模板下发。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 新开局：设备已声明但停在 Waiting for first contact 或某中间态超过 5 分钟无推进。
  2. 迁移：Cirrus→Terra（或任何跨平台）后设备带旧证书无法纳管。
  3. 变更后：改过 VPN profile 设备显示 Factory Reset Required；交换机 VPN 异常需重触发激活。

语言信号 (用户的话里出现这些就应激活)

  • "激活卡在 / stuck in activation / Waiting for first contact / Configuring VPN Failed"
  • "设备不上线 / call-home 不生效 / cloud-agent / ocloud_show"
  • "Certificate Previously Issued / 取不到证书 / Factory Reset Required"
  • "Cirrus 迁 Terra / firstboot / 清证书"

与相邻 skill 的区别

  • 与 ov-terra-deploy 的区别: 那个管平台地基（VM/DNS/build）；本 skill 管单台设备的状态链。批量全挂→先查平台；单台挂→本 skill。
  • 与 ov-roaming-troubleshoot 的区别: 那个管"已上线客户端的移动性"；本 skill 管"设备本身成为 OV Managed 之前"。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 过前置核查表
  2. DHCP options 1/3/6/28/42/43（代理 129-138）、出向 443/80/123/53（Cirrus 另查入向 9093/30123-30125）、≥1 NTP、软件版本门槛、型号排除（AP1101/AP1201L/H/HL）。
  3. 完成标准: 每项给出核对结论；任一不满足先修复再继续。
  4. 定位失败状态并按处置表行动
  5. 在 Device Catalog / Activation Log 确认停在哪个状态；按处置表执行对应动作（清证书/查 NTP/查端口/恢复出厂等）；AP 用 ocloud_show、交换机用 show cloud-agent status 交叉验证。
  6. 完成标准: 状态推进到下一环或到达 OV Managed。
  7. 判停条件: 若状态为 Factory Reset Required，直接走 Reset Device，不要停留在重启尝试。
  8. 重触发与确认
  9. 重启 cloud-agent 进程或整机（交换机可用 admin-state disable force 重建 VPN）；等一个 discovery-interval（默认 30 分钟）或重启加速；最终确认 OV Managed 且 Activation Log 无新失败。
  10. 完成标准: 设备 OV Managed。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 所有设备都激活失败 → 大概率平台侧（Terra DNS 四域名未配、build 部署失败），转 ov-terra-deploy。
  • 设备已 OV Managed，问题在客户端连接/漫游/信号 → ov-roaming-troubleshoot / ov-rf-tuning。
  • 许可未导入导致的功能受限 → ov-license-org-onboarding。

作者在书中警告的失败模式

  • 不识别状态含义盲目重启（ce07）: 每个失败状态对应不同根因域；超过 5 分钟无推进或反复回到同一失败项才判异常。
  • VPN profile 变更后只做普通重启（ce08）: 本地缓存 VPN 配置无法增量更新，必须恢复出厂。
  • 跨平台迁移不清证书（ce09）: "Certificate Previously Issued" 是旧平台凭据残留的明确信号。
  • 不支持型号/低版本（ce10）: AP1101/AP1201L/H/HL 永远无法纳管；低于 AWOS 4.0.6/4.0.7.14 在 Upgrade 阶段失败。

作者的盲点 / 时代局限

  • 状态名与 CLI 输出基于 Edition 10（AWOS 4.x / AOS 8.9-8.10），新固件可能增加状态或命令；5 分钟阈值是经验值，重度升级场景可放宽。

容易混淆的邻近方法论

  • "激活（Activation，设备→平台 call-home）"≠"订阅激活（Activate subscription，许可计时）"；cloud-agent admin-state 是交换机命令，不适用于 AP（AP 用 firstboot）。

相关 skills (阶段 3 填充)

  • depends-on ov-terra-deploy: 激活链路的前置是平台地基——批量设备全部激活失败时，先回到部署 skill 核对 DNS 四域名（activation.myovterra.com 等）与 build 部署状态。
  • depends-on ov-license-org-onboarding: 设备须先被声明（序列号）且许可到位才谈得上激活状态推进；迁移场景的"声明 + 等 call-home"步骤属许可/组织 skill。
  • composes-with ov-mesh-bridge-rap: RAP 五步上线的第 1 步（AP 注册/取证书）本质就是本 skill 的激活链——卡在注册阶段转来这里，VPN/配置阶段归 Mesh/RAP skill。
