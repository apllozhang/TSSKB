ov-roaming-troubleshoot

SKILL 来源页码: Roaming, p391-417

漫游判定与排障（OmniVista 漫游决策树）

R — 原文 (Reading)

"Client Context exists on the new AP? / WLAN service and ARP exist in the Client Context? / Context VLAN ID = VLAN ID mapped to the ARP on the new AP? → L2 Roaming / L3 Roaming / No Roaming, new client"（p400） "Recommended value for 2.4GHz: RSSI = 10; for 5GHz: RSSI = 15... Use in conjunction with 802.11k and 802.11v"（p416）

— ALE Training, Roaming (p391-417)

I — 方法论骨架 (Interpretation)

Stellar 无控制器架构下，漫游不是平台指令，而是 AP 间客户端上下文的接力：

  1. 上下文共享机制：AP 通过空中协议自动发现邻居；客户端关联时向所有邻居发 Add（携带 SSID/MAC/IP/VLAN/ARP/Policy List/Portal 状态），漫游时"新 AP 的 Add 触发旧 AP 的 Del"。接收端丢弃条件：来源 AP 不属同一 OmniVista，或本 AP 没有该 WLAN 服务。
  2. 三问判定表：① 新 AP 有客户端上下文？无 → 不漫游（新客户端）。② 上下文含相同 WLAN 服务/ARP？无 → 不漫游。③ 上下文 VLAN = 新 AP 上 ARP 映射的 VLAN？是 → L2 漫游；否 → L3 漫游（home/foreign AP 间 L2 GRE 隧道回原 VLAN）。
  3. 默认值：L2 漫游始终启用；L3 漫游默认关、须按 SSID 显式启用；Fast Roaming 默认关——OKC 仅限 WPA2/WPA3 Enterprise，802.11r 限 WPA2/WPA3（Personal 或 Enterprise）。
  4. 排障四步：判定漫游模式 → Heat Map 查覆盖重叠（无重叠=无漫游，注意生成热图需 ≥3 台 AP）→ 地理相邻但射频互不可见时互相静态添加 Neighbor AP → 粘性客户端用 Roaming RSSI 阈值 + 802.11k/v。

A1 — 书中的应用 (Past Application)

案例 1: VLAN 2001/2002 的 L2/L3 漫游全程推演（p393-416）

  • 问题: 同一 Employee SSID，AP Group1 映射 VLAN 2001、Group2 映射 VLAN 2002，员工跨楼移动时会发生什么。
  • 方法论的使用: 初始关联 Group1 → 上下文随 Add 共享给空中邻居 → 按判定表：进入 Group2 AP 时上下文 VLAN 2001 ≠ 新 AP 映射的 2002 → 判定 L3 漫游，home/foreign AP 间建 L2 GRE 隧道，客户端流量回 VLAN 2001；旧 AP 收到新 AP 的 Add 后发 Del 清理。
  • 结论: 跨 AP Group 不同 VLAN 移动依赖 L3 漫游，而 L3 漫游默认关闭——漏启用则表现为掉线重连/重认证。
  • 结果: 员工跨楼业务不中断；排障时可按判定表逐步定位是"不漫游"还是"L3 未启用"。

案例 2: 直角走廊漫游黑洞（p415）

  • 问题: 两台 AP 地理相邻，客户端走到交界处掉线。
  • 方法论的使用: 建筑结构（直角走廊）阻挡电波，空中邻居发现失败 → 上下文无法共享 → 判定表第一问即失败（无上下文=不漫游）。
  • 结论/结果: 在两台 AP 的 AP Registration > Access Point > Neighbor AP 里互相静态添加对方，上下文改走 LAN 共享，漫游恢复。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 客户拿着终端在楼内走动，跨 AP 时掉线、被重定向到 Captive Portal 或重新输入密码。
  2. 客户端信号已跌到 -80dBm 以下仍不切换 AP（粘性客户端），速率差、丢包。
  3. 跨 AP Group / 跨 VLAN 移动掉线——检查 L3 漫游是否启用、VLAN 映射是否一致。
  4. 语音/视频终端漫游慢、掉话——核对 Fast Roaming（OKC/802.11r）与 SSID 安全级别匹配。
  5. 走廊拐角、建筑遮挡区域的漫游断连区。

语言信号 (用户的话里出现这些就应激活)

  • "漫游断了 / 走着走着掉线 / 跨 AP 要重新认证"
  • "sticky client / 粘性客户端 / 客户端粘在远处的 AP 上"
  • "L2 L3 漫游怎么判定 / roaming RSSI 阈值设多少"
  • "802.11r / OKC / fast roaming 不生效"
  • "两台 AP 离得很近但就是不通 / corridor right angles"

与相邻 skill 的区分

  • 与 ov-rf-tuning 的区别: RF 调优管信道/功率/负载均衡/最小速率等空口参数；本 skill 只管"跨 AP 移动的连续性"。若用户问"信号弱/吞吐低但不涉及移动切换"，走 RF 调优。注意两者共享 RF Profile 这个配置入口（Roaming RSSI 也在 RF Profile 里）。
  • 与 ov-ssid-psk-selection 的区别: SSID 选型管认证方式与密钥设计；本 skill 消费其结果（安全级别决定 OKC/802.11r 可用性）。
  • 与 ov-mesh-bridge-rap 的区别: Mesh/Bridge 是回程组网问题，不涉及客户端漫游判定。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 按三问判定表定位漫游类型
  2. 检查：新 AP 是否有客户端上下文？上下文是否含相同 WLAN 服务/ARP？上下文 VLAN 是否等于新 AP 上 ARP 映射的 VLAN？输出判定：L2 / L3 / 不漫游（新客户端）。

  3. 完成标准: 给出明确的判定结论及依据（三问各自的答案）。

  4. 按判定结果核查配置与覆盖

  5. L3 判定 → 确认该 SSID 配置中已显式启用 L3 Roaming（默认关）；"不漫游" → 确认相邻 AP 由同一 OmniVista 管理、下发相同 WLAN 服务/ARP；用 Heat Map 分 2.4/5/6GHz 查覆盖重叠（无重叠=无漫游；站点 <3 台 AP 无热图，属正常限制）。Fast Roaming 需求 → 核对安全级别：Enterprise 可用 OKC，WPA2/WPA3 均可 802.11r，否则只能标准漫游。
  6. 完成标准: 每个可疑环节给出"已排除 / 需整改 + 整改动作"。

  7. 判停条件: 若 Heat Map 显示无射频重叠，则先补覆盖（加 AP/调功率，转 ov-rf-tuning），不再继续本流程。

  8. 修复与治理

  9. 覆盖重叠但地理相邻互不可见（遮挡）→ 两台 AP 互相静态添加 Neighbor AP；粘性客户端 → RF Profile 设 Roaming RSSI（推荐 2.4G=10、5G=15）并配合 802.11k/v。
  10. 完成标准: 输出整改清单（配置路径 + 参数值）及验证方法（移动测试/QoE 漫游时间指标）。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 静态位置信号差/吞吐低（无跨 AP 移动）：是 RF 调优问题（ov-rf-tuning）。
  • 设备激活/上线卡状态：走激活排障 skill（ov-device-activation-troubleshoot）。
  • 无线回程组网（Bridge/Mesh 连不上）：走 ov-mesh-bridge-rap。

作者在书中警告的失败模式

  • 漫游三重检查失败（ce21, p399-400）: 相邻 AP 不由同一 OmniVista 管理，或新 AP 无相同 WLAN 服务/ARP → Add/Del 被丢弃，客户端被当"新客户端"重认证（表现为漫游后被重定向 Portal）。VLAN 不一致则触发 L3 漫游；L3 默认关闭，漏启用即跨 VLAN 掉线。
  • Fast Roaming 前提不匹配（ce20, p395/402/413）: OKC 仅 WPA2/WPA3 Enterprise；802.11r 仅 WPA2/WPA3 加密；开放/Portal SSID 上启用无效。不开 Fast Roaming 则回落标准漫游。
  • 地理相邻互不可见（ce22, p415）: 直角走廊等遮挡导致空中邻居发现失败 → 无上下文共享 → 不漫游；须两侧互相静态添加 Neighbor AP。
  • Roaming RSSI 阈值两个方向都能坏（ce17, p416）: 太低 → 粘弱信号；太高 → 频繁漫游丢包。且漫游决策由客户端做出，网络侧只能靠 802.11k/v + 阈值引导。
  • Heat Map 下限（ce14, p337）: 少于 3 台 Stellar AP 无法生成热图，是功能限制不是故障。

作者的盲点 / 时代局限

  • 培训书以 Stellar/OV 为主视角，未覆盖第三方 AP 混布场景的漫游交互；802.11k/v 依赖客户端支持，书中未讨论终端兼容性排查。

容易混淆的邻近方法论

  • Dynamic Load Balance 的关联 RSSI 阈值（2.4G=5/5G=10，拒弱客户端接入）vs Roaming RSSI（2.4G=10/5G=15，驱动漫游）——数值相近、语义不同，勿混用（前者属 ov-rf-tuning）。

相关 skills (阶段 3 填充)

  • depends-on ov-ssid-psk-selection: 漫游能力受 SSID 安全级别约束——OKC 仅 WPA2/WPA3 Enterprise、802.11r 限 WPA2/WPA3；排障前先回看选型 skill 定下的加密/认证档位，开放/Portal SSID 上开 Fast Roaming 无效。
  • contrasts-with ov-rf-tuning: 本 skill 管"跨 AP 移动的连续性"（Roaming RSSI 2.4G=10/5G=15）；那个管静态信号质量与吞吐（关联 RSSI 2.4G=5/5G=10）。"信号弱但不移动"走 RF 调优，"移动中掉线"走本 skill；无覆盖重叠时补覆盖也转 RF 调优。
