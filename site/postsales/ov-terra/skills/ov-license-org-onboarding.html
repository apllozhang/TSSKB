ov-license-org-onboarding

SKILL 来源页码: p20-71, 93-118

许可证与组织开通流程（eBuy → Subscription → 平台导入）

R — 原文 (Reading)

"eBuy: License ordering → Subscription manager: Create the subscription → Import of licenses: Order ID, Activation code." "OVCX-68-BAS-3Y: License level — BASE: BAS, BUSINESS: BIZ, PREMIUM: PRM; License duration — 1Y/3Y/5Y (Terra 另有 7Y)."

— ALE Training, Licenses & Subscription / Account & Organization, p23-26, p95

I — 方法论骨架 (Interpretation)

许可生效是一条三方流水线，组织开通是并行轨道，两者在"平台导入"处汇合：

  1. SKU 解码：平台(OVCX/OVTX)-设备类别-级别(BAS/BIZ/PRM)-年限(1Y/3Y/5Y/7Y)。低端 AP（AP1x0x/1x1x/1x2x）买 APL，其余 AP 买 APH；交换机按型号（63xx→63…）。
  2. 订购链：eBuy 下单（Other Services & Items 区输入参考号）→ 同步延迟最长 24h → Subscription Manager 建 Create a subscription（选数量、客户信息、记 Subscription ID / Order ID）。
  3. 平台导入：Cirrus 用 Subscription ID + Activation Code；Terra 还需 Admin Center 取 OmniVista ID、下载 license file(.json)，且勾选 Activate subscription 即开始计时。
  4. 组织开通：选区域（eu/us.manage.ovcirrus.com）→ Partner(MSP)/Customer 账户 → Organization（强密码策略）→ 试用期：Cirrus 需 Request a trial period（预填时长/设备数不要改）；Terra 建组织自动 90 天试用。
  5. 迁移 OVC4→OVC：无自动迁移工具——先在新平台手工重建配置对象，旧平台删光设备（序列号不能双声明），再声明设备等 call-home（最长 30 分钟或重启 AP/cloud-agent）。

A1 — 书中的应用 (Past Application)

案例 1: Cirrus 许可订购与导入转正式（c01/c02, p23-28, p61-67）

  • 问题: 新客户要从零开通 Cirrus 并转付费模式。
  • 方法论的使用: eBuy 下单 OVCX 参考号 → 24h 后 Subscription Manager 建订阅 → OVC 中 Import licenses（CAPEX Subscription，Subscription ID + Activation Code）→ 选自动/手工分配设备 → Upgrade 弹窗确认转 paid mode。
  • 结果: License mode/duration/型号数量验证通过，组织进入付费模式。

案例 2: 一个邮箱管两个 MSP（c03/ce03, p32-59, p49）

  • 问题: 渠道工程师的公司邮箱已被第一个 MSP 使用，加入第二个 MSP 被拒。
  • 方法论的使用: 子地址寻址 MyMail+msp2@MyCompany.com 派生独立账户 ID，激活链接仍发原始邮箱。
  • 结果: 同时服务多个 MSP 门户。

案例 3: OVC4→OVC 迁移（c04, p68-70）

  • 问题: 老版本 OVC4 客户升级 OVC 10，无迁移工具。
  • 方法论的使用: 准备阶段手工重建 AP Group/Provisioning/SSID/Access Policy 并比对 → OVC4 删光设备 → OVC 声明（XLSX/CSV 批量）→ 等 call-home。
  • 结果: 设备在新平台重新纳管。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 新客户开通：下单什么 SKU、怎么建订阅、怎么导入许可证并绑定设备。
  2. 试用与转正：代客申请 trial、试用到期转 paid mode；Terra POC 直接建组织（自动 90 天）。
  3. 账户与组织运维：一个邮箱要管两个 MSP、组织 Disassociate/Change MSP、OVC4 迁移项目。

语言信号 (用户的话里出现这些就应激活)

  • "许可证下单 / license order / eBuy / Subscription Manager / 激活码 Activation Code"
  • "OVCX-68-BAS-3Y 是什么意思 / SKU 选错了吗 / APL 还是 APH"
  • "申请试用期 / request a trial period / 转正式 paid mode / 导入 .json 许可"
  • "一个邮箱加入第二个 MSP / sub-addressing / OVC4 迁移"

与相邻 skill 的区别

  • 与 ov-terra-deploy 的区别: 那个管 Terra 平台本身的安装；本 skill 管平台装好后的许可与组织开通。
  • 与 ov-device-activation-troubleshoot 的区别: 那个管设备激活状态链；本 skill 的迁移步骤只负责"声明序列号 + 等 call-home"。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 解码需求 → 确定 SKU 与数量
  2. 按设备清单映射：低端 AP→APL、其余 AP→APH、交换机按型号代码；级别 BAS/BIZ/PRM 与年限按商务选择。
  3. 完成标准: 输出参考号列表（如 OVCX-APH-BIZ-3Y ×N）并确认平台前缀（Cirrus=OVCX / Terra=OVTX，Terra 可 7Y）。
  4. 走订购与订阅链
  5. eBuy 下单 → 告知用户最长 24h 同步延迟 → Subscription Manager 建 subscription → 记录 Subscription ID 与 Order ID。
  6. 完成标准: 订阅状态为 "Created / Pending activation"。
  7. 判停条件: 若是 Terra，先确认平台已部署就绪再执行 Activate subscription（一旦激活即计时）。
  8. 平台导入并验证
  9. Cirrus: Import licenses → CAPEX Subscription → ID+Code → 选设备分配 → Upgrade 转正式。Terra: 取 OmniVista ID → 下载 .json → 上传导入。验证 mode/duration/type/数量；如涉及迁移，执行"重建配置→删旧声明→新声明→等 call-home"。
  10. 完成标准: License 页面字段全部核对无误，设备许可分配到位。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • Terra 平台本身没装好（VM/DNS/WebAdmin 问题）→ ov-terra-deploy。
  • 设备已声明但激活卡在某状态 → ov-device-activation-troubleshoot。
  • 许可导入后的 SSID/策略配置设计 → 对应业务 skill（如 ov-ssid-psk-selection）。

作者在书中警告的失败模式

  • 24h 同步延迟（ce05）: eBuy 下单后立刻在 Subscription Manager 找不到订单是正常现象，不要重复下单。
  • 激活即计时（ce06）: Terra 在客户环境未就绪时勾选 Activate subscription 白白消耗订阅年限。
  • 序列号双声明（ce01）: 迁移期间序列号同时存在于两个平台，call-home 归属冲突，设备停在 "Waiting for first contact"。
  • 无迁移工具（ce02）: OVC4→OVC 不继承配置数据库，须手工重建全部对象。
  • MSP 移除即失权（ce04）: Disassociate 后原 MSP 所有用户立即失去该组织访问权，执行前必须评估。

作者的盲点 / 时代局限

  • SKU 目录、24h 延迟、90 天试用时长、"10.4.3 一个邮箱一个 MSP"均为当前版本行为，升级后可能放宽；建议核对目标版本 Release Notes。

容易混淆的邻近方法论

  • "激活订阅（Activate subscription）"与"设备激活（Device Activation）"是两个概念——前者是许可计时，后者是 call-home 状态机，排障入口完全不同。

相关 skills (阶段 3 填充)

  • depends-on ov-terra-deploy: Terra 场景下许可导入的前提是平台已部署就绪——需先从 Admin Center 取 OmniVista ID、下载 license file；且勾选 Activate subscription 即开始计时，环境未就绪不要激活。
  • composes-with ov-device-activation-troubleshoot: 许可导入/组织开通完成后，设备的实际纳管靠"声明序列号 + 等 call-home"完成；若声明后卡状态，转激活排障 skill（注意"订阅激活"与"设备激活"是两个概念）。
