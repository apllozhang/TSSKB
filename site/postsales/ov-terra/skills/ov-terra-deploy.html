OmniVista Terra 3-VM 部署与初始化清单

R — 原文 (Reading)

"Number of Virtual Machines required: 3. Minimum EXSi version: 8. Processors: 8 vCPU @3GHz minimum. CPU must support AVX/AVX2... RAM: 32 GB. System Disk size: 200 GB. Data Disk size: 3 TB." "activation.myovterra.com / as.myovterra.com – activation server URL (Main IP); vpn.myovterra.com – VPN (VPN IP); images... myovterra.myovcloud.com – main URL."

— ALE Training, Servers Installation OmniVista Terra, p75/p90

I — 方法论骨架 (Interpretation)

Terra 是本地化 3 节点 Kubernetes 集群，部署是一条严格串行的验收链，任何一环不满足都会导致后续 build 部署失败：

  1. 硬件/虚拟化前置：ESXi ≥8、3 台 VM，每台 8vCPU@3GHz（必须支持 AVX/AVX2；vCenter 集群需开 EVC，基线推荐 Ice Lake、最低 Broadwell）、32GB RAM、SSD（≥50MB/s）、系统盘 200GB + 数据盘 3TB。
  2. 每台 VM 初始化：部署 OVA → 控制台配键盘/hostname（如 ovtx-100）/IP/DNS（须能解析 myovterra.myovcloud.com）/ovtx 密码 → 重启后 ip addr 核对。
  3. WebAdmin 初始化（任一节点 IP:3000）：建 admin 账号 → General Info + 第 2/3 节点 IP 校验 → 定义 4 个 IP（Main / VPN / UPAM Portal / UPAM Radius）→ SMTP → 上传 build(.7z) 部署。
  4. DNS 四域名（客户 DNS 服务器上）：activation/as/images.myovterra.com→Main IP；vpn.myovterra.com→VPN IP；myovterra.myovcloud.com→Main IP。
  5. 验证：Dashboard 节点状态 + Install 菜单部署状态；失败则 "Download the logs"。

核心思维：DNS 是激活链路的前置依赖——漏配 DNS，设备永远无法 call-home。

A1 — 书中的应用 (Past Application)

案例 1: Terra 3-VM 从零安装（c05, p74-91）

  • 问题: 客户要求本地化部署 Terra，从裸 vSphere 环境到可登录管理台。
  • 方法论的使用: 按 OVA×3 → 控制台初始化 → WebAdmin(:3000) 四 IP 定义 + SMTP → build(.7z) 上传 → DNS 五条记录的顺序执行。
  • 结论: 全程每步有验证点（ip addr、节点校验、Install 状态页）。
  • 结果: 集群上线，首次登录 https://myovterra.myovcloud.com，组织自动进入 90 天试用（p110）。

案例 2: EVC 基线不足导致部署失败（ce26, p75/p89）

  • 问题: vCenter 集群 CPU 基线低于 Broadwell（无 AVX/AVX2），build 部署失败。
  • 方法论的使用: 核对 CPU 指令集要求 → EVC 基线设 Ice Lake（最低 Broadwell）→ 用 Install 菜单 "Download the logs" 定位。
  • 结果: 修正基线后部署成功。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 售前/安装前环境验收：客户机房只有 Broadwell 基线集群，问能否装 Terra。
  2. 安装中：OVA 已部署，不知道 WebAdmin 入口、4 个 IP 怎么定义、build 从哪上传。
  3. 安装后排障：Install 菜单显示 Failure、3000 端口不通、AP 无法激活——先查 DNS 四域名是否配齐。

语言信号 (用户的话里出现这些就应激活)

  • "Terra 怎么装 / install OmniVista Terra on-premise"
  • "3 台 VM 的规格 / EVC baseline / AVX 指令集"
  • "WebAdmin 3000 端口 / build .7z 上传失败 / deployment failed"
  • "activation.myovterra.com / myovterra.myovcloud.com 解析"

与相邻 skill 的区别

  • 与 ov-license-org-onboarding 的区别: 那个管 Terra 装好之后的许可证导入与组织开通（.json 许可文件、OmniVista ID）；本 skill 管装到能用。
  • 与 ov-device-activation-troubleshoot 的区别: 那个管单台设备激活状态机排障；本 skill 是平台侧地基——若批量设备全部激活失败，先用本 skill 核对 DNS 四域名与端口。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 核对硬件与虚拟化前置
  2. 逐项检查: ESXi≥8、3×VM、8vCPU@3GHz+AVX/AVX2（EVC 基线 Ice Lake/Broadwell）、32GB RAM、SSD≥50MB/s、200GB 系统盘 + 3TB 数据盘。
  3. 完成标准: 每项有明确"满足/不满足"结论；不满足项给出升级建议。
  4. 执行部署序列
  5. OVA×3 → 控制台初始化（hostname/IP/DNS/ovtx 密码，DNS 须解析 myovterra.myovcloud.com）→ <Node_IP>:3000 WebAdmin（admin 账号、General Info、4 IP、SMTP、build .7z）。
  6. 完成标准: Install 菜单状态为 Success。
  7. 判停条件: 若状态为 Failure，立即 "Download the logs" 分析，不要盲目重试。
  8. 配置并验证 DNS 四域名 + 首次登录
  9. 在客户 DNS 配 activation/as→Main、vpn→VPN、images→Main、myovterra.myovcloud.com→Main；nslookup 逐一验证；浏览器登录 https://myovterra.myovcloud.com 看 Dashboard 三节点正常。
  10. 完成标准: 四域名全部解析正确且 Dashboard 节点健康。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • Cirrus（公有云）开通：无 VM/DNS 步骤，走 ov-license-org-onboarding。
  • 平台已上线、个别设备激活卡状态：这是设备侧问题，走 ov-device-activation-troubleshoot。
  • Terra 交换机侧出向端口要求（443/80/123/53）属设备网络前提，不在平台安装清单内重复展开。

作者在书中警告的失败模式

  • EVC 基线低于 Broadwell（ce26）: 无 AVX/AVX2 则 build 部署必失败；DNS 未预解析四域名导致初始化/激活卡住。
  • 部署失败不取日志: 书中明确失败时用 "Download the logs" 取安装日志定位，而非反复重装。
  • 容量口径（p14/p17）: Terra 官方上限 2000 台（1600 AP + 400 交换机），架构页标注可至 5000——报价按 2000 口径。

作者的盲点 / 时代局限

  • 只覆盖 VMware ESXi 虚拟化，未提其他 hypervisor 或裸金属；版本号（ESXi 8、AWOS 4.0.7.14）随版本迭代需核对新版 Release Notes。

容易混淆的邻近方法论

  • Cirrus 的入向端口 9093/30123-30125 不适用于 Terra（激活服务器在本地，只需出向 443/80/123/53）——不要照搬 Cirrus 清单。

相关 skills (阶段 3 填充)
