这本书在讲什么

这本 478 页的售后培训教材讲的是 ALE OmniVista 云管平台（Cirrus 公有云 / Terra 本地化）从零部署到日常运维的完整生命周期:平台安装、许可证开通、设备纳管、SSID 与策略设计、RF 调优、漫游排障、WIPS 安全、Mesh/RAP 特殊组网。

它的真正价值不在"操作步骤"本身,而在背后一套贯穿全书的平台范式——理解了这四条,所有章节都是同一套思维的不同切面:

  1. 声明式纳管: 工程师不逐台 CLI 配置设备,而是在平台上"声明"意图(声明序列号、建 AP Group、配 Profile 模板),设备通过 call-home 拉取配置。管理流量(certificate + VPN 隧道)与业务流量(数据面)分离。
  2. 状态机思维: 设备激活是一条可诊断的状态链,每个失败状态对应明确的故障域与处置动作——排障入口是"先定位卡在哪个状态",而非盲目重启。
  3. 策略分层模型: SSID(入口) → 认证 → Access Role Profile(角色) → Policy List(规则),一层层收敛用户权限;三层带宽合同有明确的裁决顺序。
  4. 分布式智能: Stellar 无控制器架构下,DRM 让每个 AP 与邻居共享 RF 上下文自主决策信道/功率;漫游靠 AP 间客户端上下文接力,而非控制器指挥。

还有一个贯穿性的实用特点: 书中大量给出可直接引用的推荐参数(RSSI 判定、最小速率、扫描间隔、门限值),本文末尾整理成速查表。

⚠️ 全书最大同名异义陷阱: 本书中 ARP = Access Role Profile(网络角色对象),与地址解析协议 ARP 无关。读到 ARP 一律按"角色"理解。

一、平台部署与开通 (Platform & Onboarding)

这部分回答的问题是: 平台从裸环境到"可以开始声明设备"要走过哪些验收关?

Terra 3-VM 部署是一条串行验收链

Terra 是本地化 3 节点 Kubernetes 集群,部署严格串行,任何一环不满足后续必失败:

  1. 硬件/虚拟化前置: ESXi ≥8、3 台 VM、每台 8vCPU@3GHz(必须支持 AVX/AVX2;vCenter 集群开 EVC,基线推荐 Ice Lake、最低 Broadwell)、32GB RAM、SSD(≥50MB/s)、系统盘 200GB + 数据盘 3TB。
  2. 每台 VM 初始化: OVA → 控制台配 hostname/IP/DNS(须能解析 myovterra.myovcloud.com)/ovtx 密码 → ip addr 核对。
  3. WebAdmin 初始化(:3000): 建 admin → 节点校验 → 定义 4 个 IP(Main / VPN / UPAM Portal / UPAM Radius)→ SMTP → 上传 build(.7z)。
  4. DNS 四域名(客户 DNS 服务器上): activation/as/images.myovterra.com → Main IP;vpn.myovterra.com → VPN IP;myovterra.myovcloud.com → Main IP。
  5. 验证: Dashboard 三节点健康;失败则 "Download the logs" 定位,不要盲目重装。

核心认知: DNS 是激活链路的前置依赖——漏配四域名,设备永远无法 call-home。容量口径: Terra 官方上限 2000 台(1600 AP + 400 交换机),报价按此口径。

→ 深入: ov-terra-deploy

许可证与组织开通是一条三方流水线

许可生效(订购轨道)与组织开通(账户轨道)并行,在"平台导入"处汇合:

  • SKU 解码: 平台前缀(OVCX/OVTX)-设备类别(APL/APH/交换机型号)-级别(BAS/BIZ/PRM)-年限(1Y/3Y/5Y,Terra 另有 7Y)。例: OVCX-68-BAS-3Y。低端 AP(AP1x0x/1x1x/1x2x)买 APL,其余 AP 买 APH。
  • 订购链: eBuy 下单 → 同步延迟最长 24h(下单后立刻查不到订单是正常现象,不要重复下单) → Subscription Manager 建订阅(记 Subscription ID / Order ID)。
  • 平台导入: Cirrus 用 Subscription ID + Activation Code;Terra 需从 Admin Center 取 OmniVista ID、下载 license file(.json),且勾选 Activate subscription 即开始计时——客户环境未就绪就激活,白白烧订阅年限。
  • 组织与试用: 选区域(eu/us.manage.ovcirrus.com)→ Partner(MSP)/Customer 账户 → Organization;Cirrus 需手工 Request a trial(预填参数不要改),Terra 建组织自动 90 天试用。
  • 迁移 OVC4→OVC: 无自动迁移工具——先在新平台手工重建全部配置对象,旧平台删光设备(序列号不能双声明,否则 call-home 归属冲突),再批量声明等设备回连。

一个很实用的账户技巧: 一个邮箱只能属一个 MSP,但可用子地址寻址 MyMail+msp2@MyCompany.com 派生独立账户加入第二个 MSP,激活链接仍发原始邮箱。

二、设备纳管与激活 (Device Onboarding & Activation)

这部分回答的问题是: 设备声明之后为什么不上线?卡住的那个状态在告诉我什么?

激活状态机: 先定位状态,再按语义排障

正常链: Waiting for first contact → Obtaining Certificate → Registered → (Upgrade) → Assigned → VPN Configuring → Connected to OV → Provisioning → OV Managed,每个中间态最长约 5 分钟。超过 5 分钟无推进或反复回到同一失败项才判异常。

七种失败状态处置表:

失败状态 含义 / 下一步
Failed To Get Certificate 查 NTP 时间同步、设备可达性;设备曾被其他平台管理 → 清证书
Upgrade Failed 查镜像服务器与软件版本(AWOS ≥4.0.6 / AOS ≥8.9R1)
Configuring VPN Failed 查防火墙端口(Cirrus 入向 9093/30123-30125)
Provisioning Failed 查下发配置与设备可达性
Device Validation Failed 设备验证失败
Factory Reset Required VPN profile 变更过 → 必须恢复出厂,普通重启无效
Unsupported Device Model AP1101/AP1201L/H/HL 不受支持

前置核查(先于状态机): DHCP options 1/3/6/28/42/43(option 43 指向 activation URL;代理环境另加 129-138)、防火墙出向 443/80/123/53、≥1 台 NTP、版本门槛。

跨平台迁移特例(Cirrus→Terra): AP 删 /.ocloud/ 下证书文件 + option 43 改指 activation.myovterra.com + firstboot;交换机删 switch/cloud 下 5 个证书文件 + 改 /working/cloudagent.cfg 首行 URL。看到 "Certificate Previously Issued" 就是旧凭据残留的明确信号。

CLI 工具箱: AP 侧 ocloud_show;交换机 show cloud-agent status / show cloud-agent vpn status、cloud-agent admin-state disable force 重建 VPN;discovery-interval 默认 30 分钟,重启设备/进程可立即触发。

批量全挂 → 先查平台(DNS 四域名/build 状态);单台挂 → 走状态机。另注意两个"激活"是不同概念: 订阅激活(许可计时)≠ 设备激活(call-home 状态机)。

→ 深入: ov-device-activation-troubleshoot

三、SSID / 策略 / 认证设计 (SSID, Policy & Authentication)

这部分回答的问题是: 谁用什么钥匙进门?进门后有多少权限和带宽? 这三件事分别由 SSID 选型、策略分层、有线认证四步链承担。

SSID 设计是三层决策

第一层 — Usage 矩阵(决定向导后续参数模板):

Usage 安全级别 Captive Portal
Guest Network Open 或 MAC Y
Employee BYOD Network 802.1X 或 MAC→802.1X Y
Protected Network PSK N
Protected for Employees (BYOD) PSK→Portal Y
Enterprise Network for Employee 802.1X N

第二层 — 认证安全阶梯: Open+Portal(无安全) < MAC(可欺骗、不加密,仅适合打印机/扫描仪等哑设备) < PSK(全网一把钥匙,泄露即全员暴露、无法按人吊销) < 802.1X Enterprise(最强,需服务器+用户库)。选型逻辑 = 设备类型 × 安全需求。

第三层 — PSK 四变体矩阵(密钥粒度递进):

变体 粒度 关键约束
全局 PSK 全员一把钥匙 最简单、风险最大,泄露即全员暴露
DSPSK 每设备一钥匙(MAC 认证后从 Company Property 库取本机专属密码) 必须启用 MAC 认证;加密不能选 AUTO_WPA_WPA2;Force 模式 SSID 级无全局 PSK,Prefer 模式可回退全局
PPSK 每条密码绑一个预配置 Access Role Profile DSPSK 须为 Disable 或 Prefer
Dynamic PPSK 每条密码同时绑 VLAN ID + ARP Dynamic VLAN Selection 二选一: Priority ARP over VLAN-ID / Priority VLAN-ID over ARP

经典应用: 打印机→DSPSK,承包商/部门→PPSK 或 Dynamic PPSK——一套 SSID 按口令分权分 VLAN,避免 SSID 爆炸。配套: 创建向导三段式(SSID Settings → Network Assignments → Schedule & VLAN Mappings);大网用 VLAN Pooling(≤256 个 VLAN)防单一广播域淹没空口与骨干。

注意边界: 密钥选型决定的是"进门身份"与落点 VLAN/ARP;进门后的限速与配额是下一个方法论的事,不要混为一谈。

→ 深入: ov-ssid-psk-selection

策略分层与三层带宽合同

权限与带宽由一条自底向上构建、自顶向下生效的分层链收敛: SSID(入口) → 认证(UPAM/RADIUS/本地库) → Access Role Profile(角色 = VLAN + 默认 Policy List + 每用户带宽) → Policy List(Accept/Drop、限速、802.1p/DSCP 标记,双向执行)。配置顺序永远是: 先建原子 Policy → 组装 Policy List → 挂到 ARP。

三层带宽合同裁决顺序(粗层兜底、细层收敛):

  1. 流量先匹配 Policy List ACL → 命中则按 ACL 限速(每用户每应用,最细);
  2. 未命中 → 看 ARP 是否设每用户带宽;
  3. 再看 SSID 合同 —— 每 AP 每 SSID 全体用户共享,不是每用户限速(最常被误解的一条,误用即"限速不生效"投诉);
  4. 都没有 → 不限速。

访客运营体系: Registration Profile 定义配额(数据 MB + 时长)与耗尽处理(阻断或降速)——配额与耗尽处理必须成对设计,只配配额则超量行为不可预期。典型设计: 100MB/4H,超量降速 UP=100kB/s、DOWN=1000kB/s(酒店式"降速不断网")。Service Level(最多 5 个)把 ARP + Policy List + Registration Profile 打包成分级套餐;Guest Operator 供前台批量发号审批。Guest 账户三要素缺一不可: 登录名/密码、过期日期、Service Level。

→ 深入: ov-policy-bandwidth-design

有线客户端认证四步链

AP 下联口(Eth1)或 OmniSwitch 接入口上做打印机/IP 电话等哑终端的 MAC 准入,是一条固定四步链外加一个前置:

  • [前置] 预配两个 Access Role Profile 并挂到 AP Group: 受限角色(如 ARP_DEFAULT,兜底) + 全权角色(如 ARP_PASS)——角色先行,否则链路配不完整。
  • 1. AAA Server Profile: 选认证服务器(内置 UPAMRadiusServer)+ 方法(MAC)。
  • 2. Access Auth Profile: 启用方法、绑 AAA Profile、设默认角色(受限 ARP)、指派 AP Group 并启用物理口。
  • 3. Access Policy: 映射条件 Type=MAC、Source=Local Database、命中角色 ARP_PASS、Web Redirection=None。
  • 4. 本地库声明: Company Property 登记客户端 MAC。

思维: 自下而上配置,身份命中升权、未命中由默认 ARP 兜底。忘记第 4 步是最高频失误——客户端永远落受限角色,被误判为"认证不生效"。支持下联口认证的 AP: AP1251/AP1301H/AP136x/AP1311;IoT 自动识别(MAC OUI + DHCP 指纹→自动指派 ARP)是此流程的自动化补充。两个库不要混: 设备纳管"声明序列号"(Device Catalog) vs 终端准入"声明 MAC"(Company Property)。

四、RF / 漫游 / 安全 / 特殊组网 (RF, Roaming, WIPS & Special Topology)

网络跑起来之后,投诉集中在四个方向: 信号差、移动掉线、可疑 AP、没网线的地方要覆盖。四个方法论各管一摊,边界清晰。

RF 调优: DRM 心智模型 + 可引用参数表

DRM(Distributed Radio Management)心智模型: 无控制器架构下,每个 AP 经空中协议发现邻居、共享 RF 上下文(信道利用率/干扰、每 band 客户端数、功率),各自基于上下文自主做 RF 动作(try/wait/retry),作用域限于邻居 AP。排障看邻居关系与 RF Profile,不要去找"控制器"。RF Profile(含国家码)挂 AP Group 或单 AP。

负载均衡双机制(正交、可独立启用): Band Steering 管"频段间"——按客户端数差(阈值 10)引导到 5/6GHz;Dynamic Load Balance 管"AP 间"——各 AP 按负载设应答定时器,并用关联 RSSI 门限拒绝/踢除过弱客户端。信道过载官方定义: 1 分钟平均介质利用率 >70%。

RSSI 判定表(每 +1 RSSI = +1dBm;RSSI 10-43 ↔ -86~-53dBm):

RSSI dBm 判定
10-20 -86~-76 差,不建议音视频
21-28 -75~-68 尚可
≥29 -67 以上 推荐

OV 界面显示平均值,AP CLI wlanconfig ath002 list 看瞬时值;把 RSSI 原始值当 dBm 读是常见错误(RSSI 20 实为 -76dBm)。

同书最易混淆的一对参数: DLB 关联 RSSI 门限(2.4G=5/5G=10,准入控制,拒弱客户端接入) vs Roaming RSSI 门限(2.4G=10/5G=15,引导切换)——名字相似、数值不同、用途不同。"静态信号差"走前者(RF 调优),"移动中掉线"走后者(漫游排障)。

→ 深入: ov-rf-tuning

漫游排障: 上下文接力 + 三问判定表

Stellar 架构下漫游不是平台指令,而是 AP 间客户端上下文的接力: 客户端关联时向所有空中邻居发 Add(携带 SSID/MAC/IP/VLAN/ARP/Policy List/Portal 状态),漫游时"新 AP 的 Add 触发旧 AP 的 Del"。接收端丢弃条件: 来源 AP 不属同一 OmniVista,或本 AP 没有该 WLAN 服务——丢弃即被当"新客户端"重认证(表现为漫游后被重定向 Portal)。

L2/L3 漫游三问判定表:

  1. 新 AP 有客户端上下文? 无 → 不漫游(新客户端)。
  2. 上下文含相同 WLAN 服务/ARP? 无 → 不漫游。
  3. 上下文 VLAN = 新 AP 上 ARP 映射的 VLAN? 是 → L2 漫游(始终启用);否 → L3 漫游(home/foreign AP 间 L2 GRE 隧道回原 VLAN,默认关闭,须按 SSID 显式启用——漏启用即跨 VLAN 移动掉线/重认证)。

排障四步: 判定漫游模式 → Heat Map 查覆盖重叠(无重叠=无漫游;生成热图需 ≥3 台 AP,少于此无热图是功能限制不是故障) → 地理相邻但射频互不可见(直角走廊遮挡)→ 两台 AP 互相静态添加 Neighbor AP → 粘性客户端用 Roaming RSSI(2.4G=10/5G=15)+ 802.11k/v 引导(漫游决策由客户端做出,网络侧只能引导)。

Fast Roaming 前提: 默认关。OKC 仅限 WPA2/WPA3 Enterprise;802.11r 限 WPA2/WPA3(Personal 或 Enterprise)——开放/Portal SSID 上启用无效。SSID 设计期的安全档位直接约束了漫游排障期可用的选项。

→ 深入: ov-roaming-troubleshoot

WIPS: 默认宽松、逐级升级的分类决策

三分类基线: 空中发现的一切外部 AP(本 OVC 管理的除外)默认归 Interfering(仅干扰,不上纲);命中 Rogue Policy 任一条才升级 Rogue;手工或按 OUI(默认含 ALE OUI)标记为 Friendly 的不再上报。

Rogue 判定四策略(任一命中即 Rogue): ① 信号强度超门限(默认 -70dBm,范围 -50~-90,调门限即控误报/漏报);② 广播了本网配置的有效 SSID(仿冒/钓鱼);③ SSID 名命中关键字黑名单;④ MAC OUI 命中 Rogue OUI 列表。

处置: Rogue Containment 默认启用——扫描 AP 向 Rogue 的关联客户端发 de-auth 反制(主动反制,波及邻居网络需客户知情);攻击检测灵敏度分 Custom/High/Medium/Low;Client Blocklist 默认关闭,且只对"真实无线客户端"的源 MAC 有效——盲目拉黑 AP MAC/BSSID 无效果。

前提依赖与代价: WIPS 硬依赖 AP 背景扫描(默认 20s/50ms);扫描期间该射频无 802.11 数据——间隔↑或时长↓ = 漏检↑但性能↑。共同结论: 仅 WIPS 需要时开扫描并保持默认值,高保真检测用专用扫描 AP 或 Voice/Video Awareness。

一个易踩的交叉陷阱: Auto Mesh root AP 广播的隐藏 SSID "Stellar-MESH"(5GHz)是合法行为,不是 Rogue/钓鱼——反制自家 Mesh 前先定性。

→ 深入: ov-wips-rogue-policy

Mesh / Bridge / RAP: 没有网线的三种方案

选型决策: 只需回程替代线缆(隔街楼宇)→ Bridge(纯回程,不能给 WiFi 客户端提供服务;两端 SSID/Band/Passphrase 必须完全一致);回程+客户端服务兼得(仓储/营地)→ Mesh(另需指定 Is Root);把企业网延伸到家庭/分支 → RAP。临时展会 4-5 台 AP 直接用 Auto Mesh: 接 LAN 的 root AP 自动广播隐藏 SSID "Stellar-MESH"(5GHz),未接 LAN 的 AP 自动加入,免配置。

Mesh 五项硬限制(超限拓扑不稳定或无法加入):

限制项 上限
全网 Mesh AP 总数 ≤16
slave AP 总数 ≤8
跳数 ≤4
单跳点对多点 ≤5 AP
每 AP 广播客户端 SSID ≤5

最佳实践: 回程锁 5GHz 且信道号 >100(避开常用客户端信道与雷达)。型号注意: AP1101 不兼容 RAP;AP1101/AP1201/AP1201H 桥接不支持 VLAN tagging。

RAP 三方配置 + 五步上线: 依赖 OVC(声明序列号、RAP 模式、VPN Server 公网 IP、OV2500 IP、客户端 IP 池)+ ALE VPN Server VM(eth0 公网/eth1 私网,导入 OVC 导出的 VPN 设置)+ OV2500(客户端流量 VPN + AP 配置)——配置顺序上第 1 方的导出物是第 2 方的导入物,跳步即失败。运行时五步: AP 凭序列号注册 → OVC 下发 VPN/OV2500 设置 → 建管理 VPN 隧道 → 经隧道从 OV2500 取配置 → 建第二条客户端数据 VPN 隧道(双隧道分离管理与数据面)。排障按五步定位: 卡注册→序列号/云连通(转激活排障);拿不到配置→管理 VPN 与 OV2500;用户不通→第二条隧道。

另注意区分: Guest Tunneling(GRE 按 ARP 卸载访客流量)是"客户端流量走隧道",RAP 双 VPN 是"AP 回程走隧道"——同为隧道,拓扑与用途不同。

→ 深入: ov-mesh-bridge-rap

陷阱与反例 (全书杀伤力 Top 8)

  1. SSID 级带宽合同误当每用户限速: 它是"每 AP 每 SSID 全体用户共享"——用户互相挤占后投诉"限速不生效",排查时先走三层裁决链。
  2. VPN profile 变更后只做普通重启: 本地缓存 VPN 配置无法增量更新,必须恢复出厂;状态显示 Factory Reset Required 时直接走 Reset,不要停在重启尝试。
  3. DSPSK 硬约束三条全踩: 没开 MAC 认证、加密选了 AUTO_WPA_WPA2、Force 模式下配全局 PSK——任一条 SSID 行为即异常。
  4. eBuy 下单后 24h 内查不到订单就重复下单: 同步延迟最长 24h,是正常现象。
  5. 跨平台迁移不清证书: "Certificate Previously Issued" 是旧平台凭据残留的明确信号;序列号双声明则 call-home 归属冲突,设备停在 Waiting for first contact。
  6. 关联 RSSI 门限(5/10)与 Roaming RSSI 门限(10/15)混用: 数值相近、语义不同——前者准入控制,后者引导切换;两个方向设错都能坏(过低粘弱信号/漏检,过高覆盖死角/频繁漫游丢包)。
  7. L3 Roaming 默认关闭: 跨 AP Group 不同 VLAN 移动的掉线,九成是忘了按 SSID 显式启用 L3 漫游。
  8. 背景扫描的双刃剑被忽视: 扫描期间该射频无 802.11 数据——为 WIPS 灵敏度收紧扫描会伤吞吐,关闭扫描即失去 WIPS;保持默认 20s/50ms。

10 步开局路线图

按依赖图排序,从叶子到根,一个新项目照此走:

  1. 部署平台 — Terra: 3-VM 硬件验收(EVC/AVX)→ WebAdmin :3000 → build → DNS 四域名;Cirrus 跳过此步。
  2. 开通许可与组织 — 解码 SKU → eBuy → (≤24h) → Subscription Manager → 平台导入(Terra 环境就绪后才 Activate)。
  3. 纳管设备 — 声明序列号 → 等 call-home;卡状态按七种失败状态处置表排障,别盲目重启。
  4. 建 Site 与 AP Group — Site/Building/Floor + 平面图(为 Heat Map 做 ≥3 AP 的准备);AP Group 是逻辑分组,不依赖物理网络。
  5. 设计 SSID — 按客户端画像套 Usage 矩阵 → 定认证档位 → 按分钥匙需求选 PSK 粒度;大网上 VLAN Pooling。
  6. 设计策略与带宽 — Policy → Policy List → ARP 自底向上构建;按三层裁决顺序验证;访客配额+耗尽处理成对设计。
  7. 配置有线准入 — 预配两个 ARP 兜底 → AAA Server Profile → Access Auth Profile → Access Policy → Company Property 声明 MAC。
  8. RF 调优 — RF Profile 按推荐参数表设定(见下表);RSSI 判定表评估覆盖验收。
  9. 漫游与安全加固 — 确认 L3 漫游/Fast Roaming 按 SSID 启用与安全级别匹配;WIPS 按四策略定性外部 AP、开背景扫描。
  10. 特殊场景收尾 — 无布线区域 Mesh/Bridge(核对五项硬限制、回程 5GHz 信道>100);远程办公 RAP 三方配置五步上线。

如果只带走三句话

  1. 一切排障先定位状态/层级: 设备看激活状态链,带宽看三层裁决链,漫游看三问判定表,WIPS 看四策略定性——平台范式给了每类问题明确的决策入口。
  2. 默认值不可靠,推荐值可抄: L3 漫游、Fast Roaming、Blocklist、L3 场景的 DNS 都默认关闭;而 RSSI 门限、最小速率、扫描参数、Mesh 限制这些 ALE 推荐值可以直接引用进方案。
  3. 设计期的一个决定,决定排障期能用的工具: SSID 安全档位决定 Fast Roaming 可用性,PSK 粒度决定能否吊销单把钥匙,DSPSK 的硬约束决定 SSID 能否建起来——先想清楚再点下一步。
