一、一页看懂 Express 模式

Express = 没有控制器（OV2500）、没有云管（Cirrus）时的"AP 自组织集群"：同 VLAN 里多台 AP 同时上电，自动选举出管理者，之后所有配置、射频、漫游都在 AP 集群内部完成，不依赖任何外部网管平台（p37、p77-80）。

  • 角色三分：PVM（主管理虚拟机，Highest Model Type + Highest MAC 者当选）、SVM（MAC 第二高，负责接管救援）、其余全是 Member（p79-80）。
  • 适用规模：单集群上限 255 台，定位 SMB/小微交付；超出迁 Enterprise（OV2500）或 Cloud（Cirrus），两者均 4000 台，差别只在本地还是云端（p41、p81）。
  • 能力不残缺：802.1X、WPA3、WIPS、DFS、TPC、内置 DHCP/DNS/NAT、Mesh、证书、ZTP 都有；缺的是 UPAM 这类网管级统一策略认证（p41）。

一句话：小项目要快、现场没网管，Express 就够用；规模或策略需求上来再迁云管。

二、开箱到上线主线（六步 + 默认值表）

主线四层递进：单台上线 → 集群成形 → 分域设计 → 运维收敛（p48-86）。

单台六步：核对供电上电 → DHCP 拿 IP → 连出厂 SSID mywifi → 进 Web → 向导式初始配置 → 放入同 VLAN/同 Group ID 等选举完成。

运维两条要点：远程管理要在防火墙给 Group Mgt IP 放行 32767/32768，唯一做不了的远程操作是 AP Group 镜像升级，升级计划必须排现场批次（p86）。

三、SSID / Portal / DHCP 内置服务速查

业务层三条线：员工网走 802.1X（内置用户库或外接 RADIUS）；访客网走开放加密 + Captive Portal；AP 本地内置 DHCP/DNS/NAT 和防火墙，无外部基础设施也能放号出网（p70-105、p140-151）。

排障速查：

  • 802.1X 失败三侧法：用户侧（账号密码）→ AP 侧（Web 上 tools-ping 验 RADIUS 连通）→ 服务器侧（shared key / client IP / 端口 / 证书四项）（p140-141）。
  • Portal 不弹页四查：功能开关 → 认证开关 → 白名单/walled garden 命中 → https 限制。注意：内置 Portal 不支持 https 跳转，让访客手输 http 网址；四查后仍不弹，ps | grep eag 查进程（p142-143）。
  • 老用户正常、新用户连不上：先怀疑 MaxClients 顶满，再查 blocklist 黑名单（p148-150）。
  • 访客账户"消失"：过期账户会从列表里直接不见，这是设计行为，不是被删号（p151）。

四、Bridge / Mesh 部署要点

选型口诀：只做两点连线选 Bridge（纯回程，不给客户端供 WiFi）；要延伸覆盖选 Mesh（回程与服务并存，可多根）（p110-115）。

Bridge 四属性 = 三同一根：SSID、Band、Passphrase 双端一致，Is Root 只有一端为 Yes——任何一项不满足桥建不起来，双根或无根是常见根因（p113）。

Auto Mesh 零配置：只配接 LAN 的根节点（自动广播隐藏 SSID "Stellar-MESH"，5GHz），其余 AP 断 LAN、摆位、通电即自动入网（p115）。回程最佳实践：5GHz 或 6GHz、信道 >100。

Mesh 硬限制表：

限制项 上限
级联跳数 最多 4 跳
点对多点单跳 最多 5 台 AP
全网 Mesh 节点 最多 16 台 AP
每节点对客户端 SSID 最多 5 个

另外三条：AP1101/AP1201/AP1201H 做 Bridge 不支持 VLAN 标签（p112 星号脚注）；Mesh 只做最后几跳，超 16 节点回有线；识别现场是否走了 Auto Mesh，搜隐藏 SSID "Stellar-MESH"。

五、排障案例地图（15 案例三域分类）

排障章 p126-160 共 15 案，接单先归域再套案例，每案固定"现象→分步检查→命令验证"。通用救援梯度：Web（默认 IP 192.168.1.254）→ Console（115200）→ tcpdump 抓包存 /tmp、tftp 上送 Wireshark（p129-132）。

  • AP 侧域：Case 1 不上电（LED 九态判读，p128）；Case 2 DHCP 拿不到 IP——经典根因是 option proto 残留 static，改过静态地址的设备入新网不发 DHCP 请求（p129-132）；Case 4 入不了集群四查：cluster ID 一致（cluster_mgt -x show=self）→ 32767 报文可达 → joining 需 PVM 手工批准 → 集群是否达上限 + 抓 32768 确认 AP 在发（p136-138）。
  • 客户端侧域：Case 7 拿不到 IP 抓包三分法——同报文反复重发=VLAN 配错；没发=终端静态残留；发了收不到=空中抓 beacon 比信道（p144-147）；认证/Portal/黑名单类见 ssid-portal-auth skill。
  • 性能侧域：低吞吐/高时延五查（限速→协商速率→ACS→换信道→ISP 带宽，p155-156）；Case 13 PoE 不供电五查（开关→短线→水晶头→换交换机→对调 AP，p157）；端口三板斧（换线、ifconfig br-wan、ethtool eth0）。

射频侧另有三步勘测 SOP：平面图 → 观测五问 → 纠正（p172-175）。量化基准：4 米穿 1-4 堵墙 RSSI 掉到 -70dBm，已不够 VoWLAN；衰减大户排序混凝土 > 木材 > 金属 > 钢构（p168）。覆盖优化五招里最反直觉也最有效的一条：删低速率，逼边缘终端贴近期 AP（p175）。

六、能力红线

  • 255 是硬上限且静默失效：第 256 台无报错地永远停在 joining，现场极易误判为网络问题——看到 joining 卡死先数集群规模，再查 Group ID 与子网（p81）。
  • 实际上限随型号组合浮动（32/64/255 三档），混入低端型号会拉低整组，排障勿默认 255（p136-138）。
  • 跨集群无 L2/L3 漫游：终端跨集群必掉线重连，多集群设计要把移动连续区域（仓储搬运、移动查房）划进同一集群，边界放在低移动区（p81）。
  • 机型例外：AP1101/AP1201/AP1201H 桥上不支持 VLAN 标签（p112）；教材 p82 型号清单原文 "1350" 按谱系应为 AP1351，p157 "802.3af or 802.3af" 为笔误应为 af/at——引用时保留校注。
