- id: g01
  term: WORKING / CERTIFIED / RUNNING 目录
  full_name: Working Directory / Certified Directory / Running Configuration
  type: term
  source_chapter: Managing Files/Directories, p81–83, p92
  author_definition: |
    "The working directory is a holding place for new files. Files in the working directory must be tested."
    "The certified directory contains files that have been certified by an authorized user as the default files."
    "Running configuration (RAM): current operating configuration of the switch retrieved from the running
    directory in addition to any configuration changes made by the user."
  key_distinction: |
    ≠ 一般交换机的单一 startup-config —— AOS 有两级 flash 目录 + RAM 三态：
    WORKING(待验证) / CERTIFIED(已认证的默认启动文件) / RUNNING(RAM 当前)。
    `reload` 默认从 CERTIFIED 启动（天然回滚机制）；`reload from working no rollback-timeout` 才从 WORKING 启动。
    `write memory` 只同步 RAM→WORKING；`write memory flash-synchro` = write memory + copy running certified（三态全同步）。
  why_it_matters: |
    所有配置/升级类 skill 的基础。若沿用 Cisco 的 copy run start 直觉，会漏掉认证( certify )
    与回滚语义，导致升级失败后无法回退。
  related: [g02a-issu, g29-lightning]
  tags: [term, core-concept, aos-specific]

- id: g02
  term: VC (Virtual Chassis)
  full_name: Virtual Chassis
  type: term
  source_chapter: Virtual Chassis, p102–115
  author_definition: |
    "Virtual Chassis = Group of switches which appears as a single router or bridge.
     Single Point of management; Single Logical Switch; No STP/VRRP between Access and Core switches;
     Upgrade via ISSU; No license needed."
  key_distinction: |
    ≠ 通用"堆叠"：VC 拓扑由私有 ISIS-VC 协议维护（TLV 通告能力/编号、等价路径确定性打破 ala SPBM）。
    Master/Slave 选举顺序：最高 chassis priority → 最长 uptime(差>10min) → 最小 Chassis ID → 最小 MAC。
    Takeover 后 "MAC retention is always enabled"，原 Master 回来不重新选举。
    机型限制：如 OS6900 最多 6 台、OS6360 最多 8 台（见 p104–105 支持表）。
  why_it_matters: |
    VC 是 ALE 接入/核心互联的默认形态；售后排障必须理解 Master 选举、同步(reboot required after a slave update)
    与 split chassis 行为。
  related: [g03-vfl, g02a-issu, g02b-split, g26-auto-fabric]
  tags: [term, core-concept, aos-specific]

- id: g03
  term: VFL
  full_name: Virtual Fabric Link
  type: term
  source_chapter: Virtual Chassis, p103–105, p110
  author_definition: |
    VC 成员间的互联链路/堆叠口。"Switches inter-connected via dedicated or optional SFP+, QSFP ports;
    Mesh or Ring topology." Auto VFL 端口："Automatically detect whether an auto VFL port can become VFL;
    Dynamically assign VFL ID…; Both ends of the link must be auto VFL ports."
  key_distinction: |
    ≠ 通用堆叠线：VFL 速率与可用端口因机型差异巨大（OS6465 2×1G、OS6560 20G 专用口、OS6870 2×40/100/200G QSFP56）。
    auto VFL 有默认 eligible 端口集（如 OS6360-24 为 27/28 口），且仅在出厂首启无 vcsetup.cfg 时自动运行。
  why_it_matters: |
    "VFL" 在 VC 相关 skill 中高频出现；误当通用词会导致端口规划与故障定位错误。
  related: [g02-vc, g26-auto-fabric]
  tags: [term, aos-specific]

- id: g02a
  term: ISSU
  full_name: In Service Software Upgrade
  type: term
  source_chapter: Virtual Chassis, p113
  author_definition: |
    "Used to upgrade the software on a VC with minimal network disruption. Each element is upgraded
    individually." 步骤：上传新代码/vcsetup.cfg/vcboot.cfg 到新目录(如 issu_dir) → 专用 issu 命令 →
    文件复制到所有 Slave → Slave 按 chassis ID 从低到高逐台从 ISSU 目录重启。
  key_distinction: |
    ≠ 单机软件升级；ISSU 是 VC 级别的逐成员滚动升级，Master(ID=1) 最后受影响。VC 的核心卖点之一。
  why_it_matters: |
    升级类 skill 的核心流程；漏掉 vcsetup.cfg/vcboot.cfg 同步会导致成员启动不一致。
  related: [g01-directories, g02-vc]
  tags: [term, aos-specific]

- id: g02b
  term: Split Chassis（RCD / VCSP）
  full_name: VC Split Chassis / Remote Chassis Detection / VC Split Protocol
  type: term
  source_chapter: Virtual Chassis, p111–112
  author_definition: |
    "Failures on VFL links cause potential MAC/IP duplication." 两个机制：
    Out of Band：EMP 上的 RCD 协议；In Band：VC Split Protocol（需上/下游 helper switch，VCSP LAG）。
    检测到 split 后："The former Slave chassis will shutdown all its front-panel user ports… chassis status
    modified from Running to Split-Topology"，VFL 恢复后原 Slave 重启并以 Slave 角色重新加入。
  key_distinction: |
    ≠ 双活：AOS 的处理是"伪 Master 关闭所有用户口"牺牲可用性换唯一性。RCD 依赖 EMP 管理网可达。
  why_it_matters: |
    "VC 脑裂"是售后最严重的故障场景之一；排障 skill 必须知道 RCD/VCSP 两种检测路径与恢复行为。
  related: [g02-vc, g03-vfl]
  tags: [term, aos-specific, troubleshooting]

- id: g04
  term: UNP (User Network Profile)
  full_name: User Network Profile（课件 p643 亦写作 Universal Network Profile）
  type: term
  source_chapter: Access Guardian, p142–155, p642–662
  author_definition: |
    端口用户画像机制：UNP profile = VLAN ID + Policy List(ACL/QoS) + Location/Period 有效性条件。
    "Role Based Access Control with UNP; Auto-sensing, multi-client authentication on a port."
    配置套路：`unp port 1/1/1 port-type bridge` + `802.1x-authentication`/`mac-authentication` →
    `unp profile X map vlan N` → 分类规则(binding rules) → Radius Filter-ID 返回 UNP 名。
    选择顺序(p646)：认证通过→Filter-ID 指定 UNP；无认证/失败→Classification Rules 匹配→否则 Default UNP；
    服务器超时→Timeout UNP；非法→Block。
  key_distinction: |
    ≠ Cisco 动态 VLAN：UNP 是 profile 而不仅是 VLAN 映射，还携带 ACL/QoS/时间/位置策略；
    未启认证的端口也能靠分类规则（如 MAC OUI）落到非默认 profile —— 这是 AOS 特有的"多客户端自动感知"。
    p1001 警告：SAP 上多 VLAN 复用同一 I-SID 会引发 mac-move，建议一个 access VLAN 一个 SAP+I-SID。
  why_it_matters: |
    "UNP" 是接入认证/动态 VLAN 类 skill 的骨架词；不区分 profile/分类规则/默认 UNP 三层会导致配置顺序错误。
  related: [g05-access-guardian, g16-mac-move]
  tags: [term, core-concept, aos-specific]

- id: g05
  term: Access Guardian
  full_name: Access Guardian（AOS 的 802.1X/MAC 认证框架）
  type: term
  source_chapter: Access Guardian, p642–662
  author_definition: |
    AOS 对接入认证的统称：端口(UNP port-type bridge) + UNP profile + 分类规则/policy + Port-Templates +
    Authentication server(Radius)。认证方式 "MAC-based (non-supplicant) or 802.1x-based (supplicant)"。
    非_supplicant 流程：交换机截获帧，用源 MAC 作 login/password 构造 Radius 请求。
  key_distinction: |
    ≠ 通用"网络准入"：Access Guardian 是 ALE 产品名，配置对象是 `unp` 命令族而非 `dot1x` 命令族；
    Radius 下发 Filter-ID=UNP 名（不是 VLAN 名）。
  why_it_matters: |
    售后最常见求助场景；skill 必须按 AOS 命令体系（unp …）而非 IEEE 术语来组织。
  related: [g04-unp]
  tags: [term, core-concept, aos-specific]

- id: g06
  term: SPB-M
  full_name: Shortest Path Bridging MAC mode（IEEE 802.1aq）
  type: term
  source_chapter: SPB-M, p912–936
  author_definition: |
    "All network links are used with no loops; Spanning Tree Protocol replacement; Uses the shortest path
    end to end; 100's ms convergence times; Address isolation through mac-in-mac."
    控制面 = IS-IS L1（"ISIS-SPB control packets populate SPB-M bridging/forwarding tables"），
    数据面 = MAC-in-MAC(PBB, 802.1ah)。边缘学 MAC、核心只看 BMAC。
  key_distinction: |
    ≠ IEEE 标准泛论：书中 SPB-M 是 ALE 园区方案核心（iFab），叠加宏/微分段、IP-VPN lite、L3 VPN。
    组件角色：BEB(Backbone Edge Bridge, 服务终结/边缘学MAC) vs BCB(Backbone Core Bridge, "unaware of
    services, forwarding only by looking at BMAC header")。
  why_it_matters: |
    ALE 特色、外部资料少；所有织构类 skill 的根基。与 STP/MSTP skill 的对比论证也以此为准。
  related: [g07-isid, g08-bvlan, g09-sap, g10-vpn-lite, g26-auto-fabric]
  tags: [term, core-concept, aos-specific]

- id: g07
  term: I-SID
  full_name: Service Instance Identifier（I-SID = Service ID）
  type: term
  source_chapter: SPB-M, p918–920
  author_definition: |
    "Backbone services instance identifier; Identifies a MAC-in-MAC service instance; Used to identify and
    transmit any virtualized traffic in an encapsulated SPB-M frame; Delivers service abstraction."
    Service = "A flooding domain for customer traffic"。
  key_distinction: |
    ≠ VLAN：I-SID 标识的是"服务实例"（宏分段单位），一个 I-SID 可横跨多台 BEB、绑定多个 SAP；
    VLAN 只是客户侧 C-VID。p1001：多个 VLAN 映到同一 I-SID 会导致边缘 mac-move，建议 1 VLAN : 1 SAP+I-SID。
  why_it_matters: |
    微分段/IP-VPN lite 都以 I-SID 为单位；术语混淆会直接导致服务规划错误。
  related: [g06-spb, g08-bvlan, g09-sap, g16-mac-move]
  tags: [term, core-concept, aos-specific]

- id: g08
  term: B-VLAN (BVLAN)
  full_name: Backbone VLAN（B-VID = Backbone VID）
  type: term
  source_chapter: SPB-M, p918–919
  author_definition: |
    "Special VLAN provides the physical path and propagation of network control; Expansion of Layer 2
    Ethernet domains; No source @mac learning of Customer data traffic; Each B-VLAN calculates its own
    Shortest Path Tree." 封装栈：Payload/C-VID(802.1q) → I-SID + B-VID(802.1ad) → BMAC(802.1ah)。
  key_distinction: |
    ≠ 业务 VLAN：B-VLAN 是"隧道标识/路径计算单位"（与 ECT 等价树相关，用于 B-VLAN 间的流量工程分散），
    不承载客户 MAC 学习；客户 VLAN 是 CVLAN。
  why_it_matters: |
    SPB 配置第一步就是 spb bvlan；与 I-SID 的层级关系必须分清。
  related: [g06-spb, g07-isid]
  tags: [term, aos-specific]

- id: g09
  term: SAP
  full_name: Service Access Point（SPB 语境）
  type: term
  source_chapter: SPB-M, p919–920
  author_definition: |
    "Used to specify what type of CVLAN traffic is allowed to enter/exit from/to the SPB network;
    Associate a traffic to a SPB service based on Vlan-TAG." 配套 SDP（Service Distribution Point）=
    "Far-End Node (Unicast SDP) or group of far-end nodes (Multicast SDP)"。
  key_distinction: |
    ≠ SDP 语境的其它含义；SAP 在 SPB-M 中只存在于 BEB 上，定义"C-VID → I-SID"的入出口；
    同一 SAP 上复用多 VLAN 到一个 I-SID 会触发 mac-move（p1001）。
  why_it_matters: |
    SPB 服务配置的最小单位；skill 中"创建服务"即创建 SAP↔I-SID 关联。
  related: [g06-spb, g07-isid, g16-mac-move]
  tags: [term, aos-specific]

- id: g10
  term: IP-VPN Lite
  full_name: IP-VPN Lite over SPB-M
  type: term
  source_chapter: SPB-M, p925–927
  author_definition: |
    "Routing L3 traffic over a L2 SPBM backbone network." AOS 支持两种机制：IP-VPN Lite 与
    L3/IP-VPN(VRF)。与完整 L3VPN 的区别：不需要 MPLS，直接用 I-SID 承载 VRF 间的 L3 流量。
  key_distinction: |
    ≠ MPLS L3VPN：Lite 版本无标签栈，靠 SPB 服务+VRF 实例完成路由隔离；是 SPB"服务框架"的一部分。
  why_it_matters: |
    园区多租户/分段设计的关键选项；与 VRF 条目联动。
  related: [g06-spb, g07-isid, g20-vrf]
  tags: [term, aos-specific]

- id: g11
  term: Auto-Fabric / Intelligent Fabric (iFab)
  full_name: Intelligent Fabric：Auto-VC、Auto-LACP、Auto-Routing、Auto-SPB、Auto-MVRP、Auto-Network Profiling
  type: term
  source_chapter: Intelligent Fabric, p1013–1030
  author_definition: |
    "Plug-n-Play Zero Touch Deployment"：首次启动时 1-Auto-VC(同族设备自动成VC) 2-自动远程配置下载
    3-Auto-LACP 4-Auto-Routing(发现 OSPF/IS-IS，"IP interface must exist; Neighbor relationship must
    establish… If not established configuration deleted & disabled") 5-Auto-SPB Fabric(发现 SPB 邻居)
    6-Auto-Network Profiling(环路检测/端口画像) 7-Auto-MVRP(VLAN 传播)。
    启动时提示 "Do you want to disable auto-configurations on this switch [Y/N]?"，默认 N=启用。
  key_distinction: |
    ≠ 通用 intent-based：Auto-* 每项都有"预定义默认值+失败即回退删除"的保守语义；
    auto-VC 依赖 boot.cfg/vcsetup.cfg 不存在 + 有效 Advanced/Demo license。
  why_it_matters: |
    "fabric" 在书中特指这组自动化协议族；售后判断"为什么端口自动变成 VFL/LACP"必须回到这套机制。
  related: [g02-vc, g03-vfl, g06-spb, g13-mvrp]
  tags: [term, core-concept, aos-specific]

- id: g12
  term: MSTP 区域 / MSTI / CIST
  full_name: Multiple Spanning Tree Protocol Region / MST Instance / Common and Internal Spanning Tree
  type: term
  source_chapter: MSTP, p287–305
  author_definition: |
    "A MSTP region is: A collection of switches; Sharing the same view of physical topology; Partitioning
    into the same set of logical topologies. MSTP Region seen as one switch for the rest of the world."
    MSTI = VLAN→实例的映射单位；"If a VLAN is not mapped to any MSTI, it is associated to the MSTI 0 (aka IST)"；
    区域间靠 CST/CIST 交互。`spantree [cist | msti id | vlan id] …`。
  key_distinction: |
    作者把 CIST/MSTI/CST 当"REMINDER"讲——假设读者已有标准 MSTP 知识，增量只在 AOS CLI
    （cist 关键字、restricted-role 等）。同一 region 需同名+同 revision+同 VLAN 映射。
  why_it_matters: |
    二层排障 skill 中 STP/MSTP 是基础；AOS 用 `spantree cist` 而非 `spanning-tree` 命令族。
  related: [g06-spb]
  tags: [term, protocol]

- id: g13
  term: MVRP
  full_name: Multiple VLAN Registration Protocol
  type: term
  source_chapter: MVRP, p317–324
  author_definition: |
    IEEE 802.1ak 动态 VLAN 注册/传播："Enable VLAN propagation with MVRP"（Auto-Fabric 第 7 步）；
    拓扑变化时 "Flushing of learnt attributes during topology change"（p318）。
  key_distinction: |
    ≈ GVRP 的继任者；在 AOS 语境中常与 Auto-MVRP 绑定，作为 SPB/VC 环境下 VLAN 动态跟随的手段，
    而非手工逐 trunk 放 VLAN。
  why_it_matters: |
    动态 VLAN 类 skill 与 iFab skill 共用此概念。
  related: [g11-auto-fabric]
  tags: [term, protocol]

- id: g14
  term: DHL
  full_name: Dual-Home Links（Dual-Home Link）
  type: term
  source_chapter: Dual-Home Links, p377–388
  author_definition: |
    "High availability feature; Provides fast failover between Core/Aggregation and Access switches
    without using STP. DHL Active-Active splits VLANs between two active links; The forwarding status of
    each VLAN is modified by DHL to prevent network loops and maintain connectivity to the core when one
    of the links [fails]." 配套 MAC 冲刷：`mac-learning flush vlan N port … dynamic`（p373）。
  key_distinction: |
    ≠ 普通 dual-homing：DHL 按 VLAN 拆分双上行（LinkA/LinkB VLANs），故障时全 VLAN 收敛到剩余链路；
    是 STP 的替代而非叠加。
  why_it_matters: |
    ALE 接入层高可用特色；与 STP/VRRP/VC 分别覆盖不同故障域，排障 skill 需按层级选择。
  related: [g15-erp, g12-mstp]
  tags: [term, aos-specific]

- id: g15
  term: ERP / RPL / RPL Owner
  full_name: Ethernet Ring Protection (ERPv2, G.8032) / Ring Protection Link / RPL Owner / R-APS
  type: term
  source_chapter: Ethernet Ring Protection, p819–833
  author_definition: |
    "Protection switching mechanism; Maintains a loop-free topology in a ring; Fast recovery times
    (~50 ms); Dedicated Protocol APS; AOS OmniSwitch supports ERPv2; Works on single and multiple
    independent and laddered rings."
    "Ring Protection Link (RPL): Link between 2 ring switches that is blocked to prevent a loop in the ring;
    RPL Owner: Switch hosting the RPL Port, blocks traffic on the RPL Port during normal ring operations."
    R-APS 消息：SF(Signal Fail)/NR(No Request)；Service VLAN 传 R-APS，Protected VLAN 受 ERP 控制转发状态。
  key_distinction: |
    RPL ≠ "Resilient Packet Loop" 等其它含义；RPL Owner 是逻辑角色非物理位置。
    laddered rings（主环+子环）是 AOS 支持的重点拓扑。
  why_it_matters: |
    环网排障（SF/NR 状态机、RPL 阻塞口判断）必须用这套术语。
  related: [g14-dhl]
  tags: [term, protocol]

- id: g17
  term: Route Map
  full_name: Route Map（redistribution 用）
  type: term
  source_chapter: Route Redistribution & Route Map, p474–476, p498–510；BGP p865–901
  author_definition: |
    "A Route Map is composed of: Action (permit/deny); Route map name; Sequence number; Match (criteria
    that a route must match); Set (modify route information before being redistributed; applied if all the
    route-map criteria is met and the action permits)."
    重分发两步：STEP 1 建 Route Map → STEP 2 `redistribute` 源协议到目的协议（"Redistribution configured >
    Router becomes ASBR"）。
  key_distinction: |
    语义同 Cisco route-map，但 AOS CLI 布局不同（`ip route-map …`，策略条件/动作分离）；书中强调
    permit/deny 作用于"是否重分发"，而非 packet 过滤。
  why_it_matters: |
    OSPF/BGP/VRF leak 所有策略类 skill 的公共构件；match/set 与 ACL 的分工要写清。
  related: [g20-vrf, g18-pim]
  tags: [term, protocol]

- id: g20
  term: VRF / VRF Route Leak
  full_name: Virtual Routing and Forwarding / Route Leak
  type: term
  source_chapter: VRF, p769–780
