这本书在讲什么

这套官方培训教材要解决一个问题：一名售后/支持工程师如何在 ALE OmniSwitch（AOS Release 8）上独立完成园区 LAN 的部署、配置、验证与故障定位。全书 1900 余页幻灯片按"接入 → 二层 → 冗余 → 三层路由 → SPB 织构 → 安全 → 组播 → 运维"递进，每个特性都是"概念 → CLI 序列 → show 验证"的固定套路。协议理论（OSPF、BGP、IS-IS）来自标准，ALE 的增量在于命令体系、默认值和四套自家范式——不懂这四套范式，书就读不懂、设备也配不对：

  1. 三态配置目录（WORKING / CERTIFIED / RUNNING）：AOS 没有 Cisco 式单一 startup-config。RAM 里的 running、flash 上待验证的 working、已认证定版的 certified 构成三态。reload all 无条件从 certified 启动——未 certify 的改动重启即丢，这是回滚保险而不是 bug；write memory 只落 working，write memory flash-synchro 才三态全同步（VC 下还同步所有成员）。一切配置/升级类事故都先回到这个模型解释。
  2. UNP 分类（User Network Profile）：AOS 不用"动态 VLAN"这个泛称。端口上落一个终端后，沿固定决策链决定它进哪个 profile：认证通过 → RADIUS Filter-Id（=UNP 名）；认证失败/未启用 → 本地分类规则（MAC/OUI/LLDP/IP…，Port > Domain > MAC > MAC-OUI > MAC range > LLDP > Auth-type > IP > VLAN tag，规则形态 Extended > Binding > Simple）；再兜底 default-profile → auth-server-down profile → Block。每个 UNP = VLAN + policy list (ACL/QoS) + 位置/时段策略的容器。
  3. VC 设备级冗余（Virtual Chassis）：多台物理机经 VFL 链路虚拟成一台——单一管理面、无 STP/VRRP、ISSU 滚动升级。Master 选举判定链：最高 priority → 最长 uptime（差 >10min）→ 最小 Chassis ID → 最小 MAC；脑裂防护靠带外 EMP RCD + 带内 VCSP helper 双机制，伪 Master 直接关闭全部前面板口。
  4. SPB-M 织构（Shortest Path Bridging MAC）：ALE 替代 STP 的答案——IS-IS 做控制面算最短路，MAC-in-MAC 在 B-VLAN 里转发，全链路全活、百毫秒级收敛。服务以 I-SID 为单位（BEB 配 service/SAP，BCB 零配置），可叠加微分段与 IP-VPN Lite；配套 Auto-Fabric 七阶段零接触部署。

下面按 INDEX 的五组展开。每节给决策框架、关键规则、高频陷阱。

一、开局与管理面

这一组回答："怎么安全地把一台/一组新交换机接入生产网，并保证配置不丢、故障能查。"——所有后续工作的入场券。

1.1 管理接入与开局加固

它解决什么问题: 新设备安全开局；"改完配置重启就丢了"；管理面攻击面收敛。

决策框架: 开局 = 三层叠加——① 管理面收敛：RADIUS（能 TLS 就 TLS，local 兜底放列表末尾）+ ASA 管理站白名单（≤64 个源 IP）+ 关 telnet/http/ftp/snmp + SSH strong-ciphers + session login-attempt/timeout/limit + 密码策略与 command-log；② 配置生命周期按三态目录管理（见开篇范式 1）；③ Lightning Config 开局铁律。

关键规则: - write memory 只同步 RAM→working；copy running certified / write memory flash-synchro 才定版。运行目录为 certified 时 write memory 直接报错。 - Lightning Config：开箱机禁止先接网络/DHCP/其它交换机；笔记本连 port 1 → https://192.168.0.1 → 先点 Recommended Defaults（勿跳过）→ 最小配置 → 改 admin 密码 → 保存并 certify。两台未开局出厂机绝不能直连。 - 备份：configuration backup（tar ≤10 份）+ USB（拔前必须 usb disable）。 - 实验沙箱：mkdir labdir → reload from labdir no rollback-timeout——与 reload all（回安全基线）目的相反。

高频陷阱: 未 certify 重启全丢（信号 = CERTIFY NEEDED）；未验证就 certify 不可逆覆盖安全基线；console disable 前不留管理通道只能 RMA。

→ 深入: aos-switch-access-mgmt

1.2 Virtual Chassis（设备级冗余）

它解决什么问题: 多台变一台——设备级故障切换 sub-second、统一管理面、不中断升级（ISSU）。

决策框架: VC vs LAG vs DHL 分层选（详见 2.2）；要"设备+链路双冗余"就 VC + 跨成员 LAG。

关键规则: - 组建：开机查 vcsetup.cfg——不存在走 Auto-VC（两端均为 auto-VFL 口才协商成 VFL），存在按配置进入。手工四步：chassis ID（VC 内唯一）→ group + priority（全网同 group）→ VFL → 从含 vcsetup.cfg/vcboot.cfg 的目录重启。改 chassis-id/priority 必须 reload 才生效。 - 脑裂双保险：带外 EMP 跑 RCD（IP 优先级 CMM NVRAM > EMP）；带内 helper 交换机 VCSP LAG（建议每成员 ≥1 口）。VFL 恢复后原 Slave 重启以 Slave 重入；原 Master 恢复不触发重选。 - ISSU：新目录放 code+vcsetup.cfg+vcboot.cfg → issu 命令 → Slave 按 chassis ID 低→高逐台重启，Master 最后。 - 一致性硬约束：chassis type、group、hello interval、control VLAN、license 必须一致（show virtual-chassis consistency 带 * 项）。

高频陷阱: show running-directory 见 "Flash Between CMMs: NOT SYNCHRONIZED" 即成员 flash 落后（用 flash-synchro）；拓扑缺成员时 write memory 确认 Y 会永久清除该成员配置；无 EMP 口机型 VC 内每台都要 USB dongle。

→ 深入: aos-virtual-chassis

1.3 诊断与运维工具箱

它解决什么问题: "排障第一入口看什么"；升级窗口怎么执行/回退；PoE 与 SLB 部署。

决策框架: 工具按侵入性从低到高——swlog 日志 → command-log（谁改了什么，最近 100 条）→ RMON/接口计数 → sFlow（receiver/sampler/poller 三件，源地址用 Loopback0）→ port-mirroring 逐包（与 monitoring 同口互斥）。

关键规则: - swlog appid <app> subapp <n> level debug3 分子系统调级——比全局 debug 快且不冲击 CPU（OSPF 邻居不上先看 HELLO 子模块）。syslog 最多 12 台；swlog 8 文件轮转。 - PoE：优先级 critical/high/low，预算不足先断 low；重要设备设 critical；delayed-start 与 FPoE/PPoE 互斥且必须 write memory。 - SLB：VIP 必须与服务器同网段（proxy-ARP 兜底）；每机 16 cluster；WRR 总权重 ≤32；weight 0 = 备份机（主全挂才接管）。 - 升级六步法：release note（内存/uboot/FPGA 要求）→ FTP 镜像 → reload from working no rollback-timeout → show version 验证 → 稳定后 certify → 按需 update uboot/fpga-cpld。certify 之前都可回退。

高频陷阱: 跳过 release note 直接刷镜像可能变砖；镜像会话互斥（"please remove other configuration" 时按互斥清单反查）；日志已指向协议故障后应转对应协议 skill。

→ 深入: aos-diagnostics-ops

二、L2 基础与冗余

这一组回答："二层怎么通、怎么不出环、断了怎么活。"

2.1 VLAN / 802.1Q / 动态 VLAN / MVRP

它解决什么问题: 园区二层的基础供给——静态划分、按终端自动分 VLAN、跨交换机自动传播。

决策框架: 三层动态化——静态 VLAN+trunk → UNP 分类（终端身份驱动）→ MVRP（协议声明驱动）。

关键规则: - 铁律：每个物理口永远有一个 untagged 默认 VLAN（trunk 其余打 tag）；VLAN 无 active 成员即 oper down，绑定的 IP 接口随之 DOWN（不响应 ping 但广播域还在）——排"IP 接口 down"先查 VLAN 成员再查物理口。VLAN1 不可删只能禁用。 - VLAN 间路由 = 给 VLAN 绑 IP 接口即自动开转发（第一个为 primary）。 - MVRP 三前提：STP flat 模式 + 全局 enable + 端口 enable；动态 VLAN 上限默认 256（mvrp maximum-vlan，调小需 disable→enable MVRP）。

高频陷阱: 动态 VLAN（type=dyn）本地 no vlan 删不掉且被立即重建——必须先在声明侧删或先禁 MVRP 端口；MVRP 不能配 mirror/unp/VPLS access/stacking user 口；mobile 口不支持静态 802.1Q tag，必须走 UNP mobile-tag。

→ 深入: aos-vlan-mvrp

2.2 L2 冗余三角：LAG / STP(MSTP) / DHL / ERP

它解决什么问题: "双上行该用 STP 还是 LACP 还是 DHL"——接入-核心二层冗余统一选型。

决策框架（四问）: 链路冗余？带宽利用率？收敛时间？交换机冗余？ - 对端是 ALE 且参数两端一致 → 静态 LAG；跨厂商（服务器/存储/它牌）→ 动态 LACP；对接第三方不用 LACP 会乱序/丢包/单通。 - 双上行双核心不想跑 STP → DHL（按 VLAN 拆到 A/B 两条链路 active-active）；环网 → ERP（G.8032，~50ms）；与第三方 MST 域互通 → MSTP。 - 设备级冗余 → VC（见 1.2），可叠加跨成员 LAG。

关键规则: - LAG：建 agg 预留 size；VLAN 挂 linkagg 而非物理口；哈希 brief vs extended（机型默认不同：6900/6465/6360=brief，9900/6860=extended）；组播默认走主端口，需 hash-control load-balance non-ucast。 - STP：默认 per-VLAN(1x1) RSTP、priority 32768、全默认则最低 MAC 当根——必须手工定根；1x1 可按 VLAN 分根负载分担。MSTP 七步：flat 模式 → protocol mstp → region(name+revision+映射三要素全网一致) → 建 MSTI → VLAN→MSTI 映射 → 按 MSTI 设 priority → 验证；priority 须 4096 倍数。边缘保护三招：restricted-role / restricted-tcn / BPDU 过滤。 - DHL 硬限制：每机 1 session、仅 2 链路、同一 default VLAN、禁 mobile/802.1x/GVRP/UNI 口、DHL 口自动关 STP（无 TCN）→ 必须显式选 MAC 冲刷（raw / MVRP enhanced / none——默认 none 有黑洞风险）；pre-emption 默认 30s。 - ERP：全环恰一个 RPL Owner（常态阻塞 RPL）；WTR 默认 5 分钟；每环 ≤16 节点。

高频陷阱: 端口残留 VLAN 配置加不进 linkagg（售后最高频报错，先 no vlan X members port）；1x1 与 MSTP 不能同配，MSTP 用 32-bit path cost（与 16-bit 差 65536 倍）；根桥漂移到接入层老设备；无 RPL 成环风暴、多 RPL 错切流量。

→ 深入: aos-lag-stp

三、安全与策略

这一组回答："谁能让流量进来（认证），进来的流怎么处理（策略），不问身份时怎么防（L2 防御）。"

3.1 Access Guardian (802.1X/MAC) + UNP 分类流水线

它解决什么问题: 员工 802.1X、哑终端 MAC 认证、话机零配置、访客隔离——"认证失败/服务器挂了终端去哪"。

决策框架: 沿开篇范式 2 的判定链设计兜底：Filter-Id → pass-alternate → 分类规则 → default-profile（通常指向隔离 VLAN）→ auth-server-down profile（默认 60s 重试）→ Block。配置链：aaa radius-server → VLAN + UNP profile (map vlan) → port-template（802.1x-authentication + pass-alternate）→ unp port port-type bridge + default-profile → policy list 挂 unp profile → auth-server-down 兜底。

关键规则: - RADIUS 下发的 Filter-Id = UNP 名（不是 VLAN 名）；默认 retransmit 3 / timeout 2s / auth 1812 / acct 1813。 - 话机场景：LLDP-MED network-policy TLV 下发 voice VLAN + l2-priority 5 + dscp 46，话机据此打 tag，交换机 mobile-tag profile + trust-tag 分类收流。

高频陷阱: 认证禁用/失败时端口不会关闭而是回落分类/default profile——"没认证就没策略"是错觉，安全预期必须按兜底 profile 设计；PVLAN 下 UNP 口的 isolated/community 角色由首个学到的 MAC 决定，落错永不翻身。

→ 深入: aos-access-guardian-unp

3.2 Consistent Security：非认证 L2 防御

它解决什么问题: 不问身份的端口级护栏——防 ARP 欺骗、流氓 DHCP、广播风暴、私接设备、同子网窃听。

决策框架: 按攻击面选型——欺骗类走链条（DHCP 信任分级→snooping binding 表→Option-82→IP source filter→DAI），隔离类二选一（MFF vs PVLAN），资源类（flood-limit + LPS），加密类（MACsec）。

关键规则: - DHCP 链条逻辑：trusted 口全放、untrusted 只放 Discover/Request（流氓服务器被隔离）；服务器/上级 relay 口必须 trust，否则 OFFER/ACK 全被丢；DAI = snooping + source-filter 组合，binding 表为空会大量误杀。 - LPS：默认 max MAC=1、filtered=5、violation=restrict；convert-to-static 必须在终端 MAC 已学到之后执行；不支持 LAG 口。 - 隔离选型：要 DHCP 网关代理 → MFF（Port Mapping + dynamic proxy ARP + snooping）；纯静态 → PVLAN（先 capability shared-vlan-learning enable；一个 primary 只能 1 个 isolated）。 - MACsec：先核对端口能力/机型矩阵（6860N 仅 dynamic、VFL 口不支持）+ 免费 site license；动态 SAK 按时间 5–120min 或流量 5–1000GB 先到先换；静态 SA ≤4 key 且两端 sci-tx/rx 交叉。

高频陷阱: 服务器口忘 trust → 全网 DHCP 失败；Port Mapping 双向会话的 network 口不能共享；两端 SAK/SCI 不匹配则口 up 不通。

→ 深入: aos-l2-security

3.3 QoS / ACL / PBR 统一策略引擎

它解决什么问题: 标记、限速、封堵、重定向、策略镜像——AOS 把它们全收敛到一个三段式引擎。

决策框架: 一切策略 = condition（L1–L4 任意组合）→ action（priority/802.1p/DSCP/cir/redirect/mirror/port-disable/disposition）→ rule（precedence + 可选 validity-period 时段），端口级修改后必须 qos apply 才生效（revert 撤销 / flush 清空）。

关键规则: - 端口默认 untrusted（打 default 802.1p），trusted 口才保留入站标记——信任边界设错是一切标记问题的根源。 - 话机自动加速：qos phones 默认开启，按内置 MAC 组（00:80:9F 等）强制 priority 5；新厂商话机需重定义 MAC 组。 - PBR 旁挂防火墙两段式防环：去程 permanent gateway 指防火墙；回程 condition 必须加 source port（防火墙回连口），否则被去程规则反复抓住成环。 - 保留组：UserPorts 丢源 IP 欺骗可叠加 filter/shutdown spoof|rip|ospf|bgp|bpdu；DropServices 丢指定 TCP/UDP 服务。

高频陷阱: 默认不匹配任何 policy 的流是 ACCEPT——把 QoS/ACL 当白名单防火墙会落空；不 qos apply 配置停在 pending；策略镜像同时仅 1 会话（普通镜像 4 会话/4 MTP，机型相关）。

→ 深入: aos-qos-acl-pbr

四、L3 路由

这一组回答："三层怎么通、怎么快、怎么隔离。协议是标准的，增量在 AOS CLI、默认值与排障范式。"

4.1 IGP：静态 / RIP / OSPF / IS-IS + VRRP

它解决什么问题: 园区 IGP 开局、边缘区域裁剪、路由引入、邻居排障、网关冗余。

决策框架: - 选路仲裁：Local 1 < Static 2 < OSPF 10/110 < ISIS 115/118 < RIP 100/120 < EBGP 190 < IBGP 200（以 show ip route-pref 为准）；主备默认路由用 metric 1/2；下一跳随动用递归 follows；Loopback0 做 router-id/peering/服务源地址。 - 区域阶梯（问题驱动"LSA 太多/路由表太大"）: standard → stub（拒 Type4/5，ABR 注默认）→ totally-stubby（再拒 Type3）→ NSSA（本区要挂 ASBR，Type7 进 ABR 转 Type5 出）。每种区域 = 一组 LSA 白名单；合格标准："stub 交换机路由表以默认路由收尾"。 - 收敛路由表按位置选动作：内部路由在 ABR 做 Summarization，外部路由在 ASBR 做 Aggregation。 - 重分布两步法：先 route-map 后 redist（有序语句命中即停；同字段多 match=或、跨字段=与；配了重分布即成 ASBR）；双向重分布必配 tag/过滤防环。

关键规则: - OSPF 七步：router-id → ip load ospf → area（定类型）→ interface → 接口入 area + enable（R8 逐接口）→ 重分发（如需）→ 全局 enable。 - 邻居排障范式：show ip ospf interface 比对两端（Hello/Dead、认证、area、MTU）→ swlog appid ospf_0 subapp all level debug3 → 日志找 discard 原因——第一嫌疑永远是定时器/认证不匹配（"invalid helloInterval"）。 - IS-IS：DIS 选举=最高优先级→最高 MAC 且可抢占（后上线高优先级立即抢走 DIS 触发 LSP 突增）；L1 邻接要求 area-id 相同。 - VRRP：双核心双 VRID 互为主备做负载分担；track 对象关联上行故障扣优先级（治"网关活着但出口死了"）；改 priority 前必须先 disable 实例。

高频陷阱: ECMP 最多 4 条且仅 per-flow——单流永远走哈希选定的单链路；RIP invalid ≥ 3×update 硬约束；GR 对 OSPF/IS-IS 默认关闭、BGP 默认开启（升级前检查）；OSPF DR 选举方向（最高优先）与 STP 根桥/VC Master（最低优先）相反。

→ 深入: aos-igp-routing

4.2 BGP 与 VRF/Route Leak

它解决什么问题: 双出口选路控制、IBGP 黑洞、多租户隔离与跨 VRF 共享服务。

决策框架: BGP 本质"策略优先于度量"——七级属性瀑布逐级比较，改选路从瀑布顶端找第一个可操纵属性：LocalPref 高 → AS-Path 短 → Origin（IGP<EGP<Incomplete）→ MED 低 → 下一跳 IGP 度量近 → EBGP 优于 IBGP → 最低 RID。方向化旋钮：出向引流改 LocalPref（AS 内有效），入向改 MED（只告知相邻 AS、不跨 AS 传递、再通告归零），批量打标用 Community；载体统一为三层组装（原子 list → route-map → 挂 neighbor in/out）。

关键规则: - IBGP 水平分割：IBGP 学到的路由不传第三个 IBGP 邻居（AS_PATH 在 AS 内不增长）→ full-mesh 或 RR；关同步时用 next-hop-self 补下一跳可达性。 - VRF：一个 VLAN（及其 IP 接口）同一时刻只属一个 VRF，归属由首个接口决定，VRF 名大小写敏感；跨 VRF/到 GRT 共享必须 Route Leak——源 VRF export route-map 与目标 VRF import route-map 成对；仅 6860E/N、6900、9900 支持 leak。

高频陷阱: "邻居全 Established 却缺前缀"= 水平分割或下一跳不可达；MED 与 LocalPref 方向搞反是最常见错配；本机两 VRF 接口互 ping 不通是安全设计而非故障（验证要 ping 对端客户端）；双向泄漏不加 route-map 会成环。

→ 深入: aos-bgp-vrf

五、SPB Fabric 与组播

这一组回答："ALE 的进阶答案——不用 STP 的全活骨干怎么建，组播怎么从 L2 一路做到 RP 冗余。"

5.1 SPB-M 织构

它解决什么问题: 用 IS-IS + MAC-in-MAC 替代 STP 建全活骨干；园区 L2/L3 VPN；零接触部署。

决策框架: 配置天然分两层—— - 骨干四步法（每节点）：① 建 BVLAN 关联 ECT-ID；② 协议 disabled 时指定 control BVLAN；③ 互联口设 SPB IS-IS 接口（=网络口，BVLAN 上无 STP）；④ 全局 enable。铁律：BVLAN/ECT 全网一致，且先配好再 enable。 - L2 服务五步法（只在 BEB，BCB 零配置）：接入侧建 VLAN → 声明 service access port →（可选 profile）→ service spb <本地号> isid <全局号> bvlan <BVLAN> → 定义 SAP（端口:encap）。service 号仅本地有效，I-SID/BVLAN 跨 BEB 必须一致。

三条核心设计准则: 1. BVLAN 数量 = 物理等价路径数（上限 16；配满 16 无收益反增 SPF 负担，ECT-ID 是树分化 tie-breaker）。 2. 一个 VLAN 一个 I-SID——多 VLAN 映同一 I-SID 会打通 L2 隔离并触发持续 mac-move（虚拟化环境尤甚）。这是 SPB 服务规划第一红线。 3. L3 选型：域内用 L3 VPN（复用 IS-IS、路由由 TLV 按 I-SID 自动承载免配路由协议），边界用 VPN Lite（OSPF/BGP 对接外部；不能与 MPLS 直接互通）。

配套: BUM 复制三选——Head-end（默认，省资源费带宽）/ Tandem(S,G)（每 I-SID 一棵树）/ Tandem(*,G)（每 BVLAN 共享树）；链路 metric 默认一律 10，调整必须两端同改。Auto-Fabric 七阶段（Auto-VC → 取配置 → Auto-LACP → Auto-Routing → Auto-SPB → Network Profiling(UNP+LBD) → Auto-MVRP 兜底）每阶段"探测-预置-验证-不成立即回退"——解释"端口自己变 LAG/UNP"类工单的钥匙。

高频陷阱: 先 enable 再改配置 → 邻接在错误拓扑上计算（"adjacency up 但服务不通"的第一嫌疑）；各 BEB I-SID/BVLAN/SAP encap 不一致导致单通；控制 BVLAN 接口不支持 OSPF/VRRP/ARP；LBD 检到环直接关物理口需人工恢复（不做阻塞-转发状态机）。

→ 深入: aos-spb-fabric

5.2 组播：IPMS / IGMP / PIM-SM / Anycast RP

它解决什么问题: IPTV/视频会议部署、"换台黑屏"、RP 单点故障。

决策框架: 收到组播包先二分——同 VLAN → L2 交换（IPMS，AOS 的 IGMP snooping 实现）；跨 VLAN → L3 路由（PIM/DVMRP 转发表）。L3 再选型：接收者密集小网 → PIM-DM（flood-prune 3 分钟一轮、无 RP）；稀疏 → PIM-SM（显式 join + RP 共享树 + SPT 切换默认开启）。

关键规则: - IPMS 最小三件套：全局 ip multicast admin-state enable → 接服务器者 querying enable（多台选一台 querier）→ 其余 querier-forwarding enable。不开 IPMS 时 VLAN 内洪泛。IGMP 默认 v3、查询间隔 125s、router-timeout 90s、TTL 恒 1。 - 限组：max-group 全局/VLAN/端口三级（端口覆盖上级）；超限动作 none/drop/replace（换台场景用 replace）。首包缓冲（默认 4、最多 10）治 IPTV 换台黑屏/首帧丢失。 - RP 两套机制：BSR 自动选举（先选 BSR：priority→IP；再为每组算 RP：priority 最小 → (组,RP) hash 最大 → IP 最大，不同组天然散到不同 RP）；静态 RP（ip pim static-rp）可覆盖 BSR。 - Anycast RP 冗余：多台 RP 共享一个 Loopback 以主机路由宣告进 IGP，全域静态指该地址，RP 间独立 Loopback 组 RP set 互相同步 register（RFC 4610 PIM 方式，非 MSDP）；失效收敛速度 = IGP 收敛。

高频陷阱: Anycast RP 硬边界——仅 PIM-SM（DM/BIDIR/SSM 不支持）、静态 RP set ≤8 台、SPT 必须开启；一个接口只能跑 PIM 或 DVMRP 之一；警告信号"源注册到一台 RP、接收端只查另一台 RP 收不到流"。

陷阱与反例（杀伤力 Top 6）

  1. "改完配置重启就丢了"——机制：reload all 无条件回滚 certified，未 certify 的改动被丢弃；预警信号 = show running-directory 的 CERTIFY NEEDED。同理"运行在 certified 目录时 write memory 报错"。
  2. PBR 回程不加 source port → 路由环路——机制：回程流量再次命中去程规则被反复抓回防火墙；预警 = TTL 递减的 traceroute 环。这是"策略按匹配而非按流会话生效"的必然。
  3. IBGP 邻居全 estab 却缺前缀——机制：水平分割（AS_PATH 在 AS 内不增长）+ 下一跳不可达；人会掉进去是因为"邻居起来了=路由会通"的 IGP 直觉。预警 = 部分前缀缺失、next-hop 非 reachable。
  4. SPB adjacency up 但服务不通——机制：先 enable 后改配置在错误拓扑上计算，或各 BEB 的 I-SID/BVLAN/SAP encap 不一致；人多认为"邻接起来就万事大吉"。预警 = 单通、mac-move 告警持续。
  5. DHCP 服务器口忘 trust → 全网取不到地址——机制：untrusted 口只放 Discover/Request，OFFER/ACK 全被丢；连锁反应是 snooping binding 表为空 → DAI 大量误杀。预警 = 客户端 Discover 不断、服务器侧正常。
  6. VC write memory 弹 "Chassis X missing" 就按 Y——机制：确认 Y 会永久清除该成员配置；拓扑判断失误（如 VFL 半断）时误操作不可逆。预警 = 先 show virtual-chassis 核实成员真实状态。

作者的局限（读这套教材要打的折扣）

  1. 版本绑定: 一切命令、默认值、支持矩阵（MACsec 机型表、SLB 8.9R4 新特性、镜像会话数）随 AOS 版本漂移；R9/R10 与新平台（6900/6865 等）已有变化。现场务必以对应版本配置指南为准。
  2. 厂商立场: SPB、UNP、VC、Auto-Fabric 被表述为理所当然的最优解，未与主流（VXLAN/EVPN 等）公平对比，回避了 SPB 生态锁定风险。
  3. 体裁缺陷: 提纲式幻灯片 + 大量图示（文本提取丢失），很多结论未展开论证；假设读者已有通用网络基础（OSPF/BGP/组播以 "REMINDER" 开讲）。
  4. 覆盖缺口: IPv6 仅组播一章带过，对双栈园区不足；管理生态停留在 OV2500/Cirrus 时代（Terra 之后的演进不在本书内）。

如果只带走三句话

  1. AOS 的回滚语义是一切配置工作的地基: write memory 只落 working，reload all 无条件回 certified——certify 是显式的定版动作，验证之前永远别 certify。
  2. 终端落点沿固定决策链走完: 认证 Filter-Id → pass-alternate → 分类规则 → default → server-down → Block；安全预期必须按兜底路径设计，而不是按理想路径。
  3. 高可用是分层的机制叠加: LAG（链路）/ DHL-ERP（链路组/环）/ VC（设备）/ VRRP（网关）/ Anycast RP（组播服务）各管一个故障域——先定故障域，再选机制；而 SPB-M 是 ALE 把"二层全活 + 服务化"一把梭的答案，理解它就理解了这套教材的终点。
