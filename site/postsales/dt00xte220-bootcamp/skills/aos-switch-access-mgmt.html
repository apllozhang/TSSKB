SKILL 来源页码: 220 p36-90, p1121-1145 (连接交换机/用户/AOS 文件管理/Lightning Config)

OmniSwitch 管理接入与开局加固 (AAA / 目录回滚 / Lightning Config)

R — 原文 (Reading)

"IF THE OMNISWITCH IS REBOOTED WITH THE 'RELOAD ALL' COMMAND, IT WILL REBOOT FROM THE CERTIFIED DIRECTORY, NO MATTER WHAT THE CONTENT OF THE RUNNING DIRECTORY IS" (220 p93-95) "Do not pre-cable the ALE switch to the network... Do NOT skip the Recommended Defaults!" (220 p1127, p1133)

— ALE Training, OmniSwitch LAN R8 Bootcamp Ed23, p93-95 / p1121-1145

I — 方法论骨架 (Interpretation)

AOS R8 的开局 = 三层叠加的守则：

  1. 管理面收敛：出厂 admin/default 双账号，8.10R04 起首登强制改密；外部认证走 RADIUS（能 TLS 就 TLS，local 放列表末兜底，fail-through）；ASA 用 aaa switch-access management stations 白名单管理源 IP（≤64 个）；关不安全服务（telnet/http/ftp/snmp）、SSH strong-ciphers/strong-hmacs、session login-attempt/login-timeout/session-limit。
  2. 配置生命周期 = RAM → working → certified 三态：write memory 只落 working；copy running certified（或一步 write memory flash-synchro）才定版。冷启动时 running 与 certified 不一致即回滚 certified；reload all 无条件从 certified 启动；以 certified 为 running 目录时 write memory 直接报错。备份用 configuration backup（tar 最多 10 份）+ USB 镜像（拔前必须 usb disable）。
  3. Lightning Config 开局铁律：开箱机禁止先接网络/DHCP/其它交换机/摄像头；笔记本 DHCP 连 port 1 → https://192.168.0.1 → 先点 Recommended Defaults（勿跳过）→ 最小配置（IP 全网唯一）→ 改 admin 密码（≥8 位含大小写数字特殊字符，避开 ! $）→ 保存并 certify。两台未开局出厂机绝不能直连。

A1 — 书中的应用 (Past Application)

案例 1: AAA 加固完整配置 (220 p38-59, c01/c02)

  • 问题: 生产交换机管理面暴露（默认口令、telnet、任意源登录）。
  • 方法论的使用: aaa authentication default Radius01 Radius02 local 多服务器 fail-through；ASA 增强模式逐条加管理站 IP；ip service telnet/http/ftp admin-state disable；ssh strong-ciphers enable；session login-attempt 5 / login-timeout 20 / session-limit 2；user password-policy + command-log enable。
  • 结论: 管理面攻击面收敛为"白名单源 + SSH-only + 审计留痕"。
  • 结果: 教材给出的安全基线 checklist，所有后续实验的前提。

案例 2: 实验目录切换与回滚 (220 p80-98, c03/ce01)

  • 问题: 实验改动不能污染稳定配置。
  • 方法论的使用: mkdir <labdir> → 拷贝初始化文件 → reload from <labdir> no rollback-timeout → 实验后 rm -r <labdir> → reload from working。
  • 结论: 双目录天然提供回滚沙箱；未 certify 的改动重启即丢，这是特性不是 bug。
  • 结果: 全书所有 RLAB 的标准开工/收尾流程。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 新 OmniSwitch 到场，要安全地接入生产网（Lightning Config + 加固基线）。
  2. 工程师报告"改完配置重启就丢了"或"write memory 报 certified mode 错误"。
  3. 做安全审计/基线核查：管理源限制、服务关闭、密码策略、备份策略（tar/USB）。
  4. 升级或实验前需要确认当前运行目录与 certify 状态。

语言信号 (用户的话里出现这些就应激活)

  • "为什么 reload 之后配置全没了 / reload all 回滚"
  • "write memory 报错 not permitted certified mode"
  • "Lightning Config 怎么做开局 / 192.168.0.1 连不上"
  • "管理口只允许某些 IP 登录 / ASA management stations"
  • "certify / certified directory / flash-synchro"

与相邻 skill 的区分

  • 与 aos-virtual-chassis 的区别: VC 场景下同步是多成员 certified 层面（flash-synchro 语义），本 skill 只管单机目录模型；VC 选举/ISSU 归 VC skill。
  • 与 aos-diagnostics-ops 的区别: 软件镜像升级六步法、swlog/镜像等诊断工具归后者；本 skill 覆盖配置（非镜像）的保存/回滚/备份。
  • 与 aos-access-guardian-unp 的区别: 那是用户/终端 802.1X 准入；本 skill 是管理员对交换机的 AAA。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 判定场景类型（开局 / 加固 / 配置丢失排障 / 备份）
  2. 完成标准: 明确说出属于哪类，并引用对应原文页码。
  3. 配置丢失类: 先 show running-directory 看 Certify/Restore Status 与 Running Configuration 来源
  4. 完成标准: 能指出是否 CERTIFY NEEDED / 是否运行在 certified 目录；解释 reload all 的无条件回滚语义。
  5. 判停条件: 若设备为 thin-client 模式（配置在 OV2500），转向"本地不可保存"结论。
  6. 加固类: 按 checklist 输出命令集——RADIUS(TLS)+authentication/accounting、ASA 管理站、ip service 关闭、SSH 强化、session 参数、密码策略、banner、command-log
  7. 完成标准: 给出可粘贴的命令序列，并标注高危项（console disable 前必须确认保留管理通道，否则只能 RMA，220 p48）。
  8. 开局类（Lightning Config）: 输出前置禁令清单（不接网络/不接 DHCP/不连其它交换机/只连 port 1）+ 步骤（Recommended Defaults → 最小配置 → 改密 → 保存 certify）
  9. 完成标准: 用户可按清单独立完成，且知道 192.168.0.1 只在保存配置前有效。
  10. 备份类: configuration backup（≤10 份 tar）、usb backup admin-state enable、拔 USB 前 usb disable
  11. 完成标准: 说明各备份的恢复路径（usb auto-copy copy-config）。
  12. 每次变更后: 验证 → copy running certified 或 write memory flash-synchro
  13. 完成标准: 提醒"只在验证后 certify"（覆盖安全基线不可逆）。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • VC 多成员配置同步/ISSU 升级流程——用 aos-virtual-chassis（本 skill 的 flash-synchro 只是入口）。
  • 软件镜像（.tar 固件）升级与 uboot/FPGA——用 aos-diagnostics-ops。
  • 终端用户 802.1X/MAC 认证准入——用 aos-access-guardian-unp（AAA 命令形似但对象不同）。

作者在书中警告的失败模式

  • ce01: reload all / 断电重启无条件回滚 certified，未 certify 改动全丢；信号 = CERTIFY NEEDED。
  • ce02: 运行目录为 certified 时 write memory 报错，须先 reload from working。
  • ce03: 未验证就 copy running certified 会不可逆覆盖安全基线，失去回滚保险。
  • ce04: 拔 USB 前未 usb disable 可损坏备份介质。
  • ce34: 开箱机禁止先接网络/DHCP/其它交换机；跳过 Recommended Defaults、留默认密码、两台未开局机直连都是事故源。

作者的盲点 / 时代局限

  • 教材基于 8.9R4~8.10R4，R9+ 命令与默认行为可能变化；Lightning Config 单机流程不覆盖 OV2500/Cirrus 集中开局场景。
  • 密码策略/IEC62443 内容较浅，仅点到命令。

容易混淆的邻近方法论

  • "reload from working no rollback-timeout"（实验沙箱）vs "reload all"（回安全基线）——目的相反。
  • management AAA（本 skill）vs 网络 AAA 802.1x（Access Guardian）。
