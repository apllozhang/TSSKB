SKILL 来源页码: IP 路由 p396-555; IS-IS p1071-1088

AOS 园区 IGP 路由与 VRRP 网关冗余

R — 原文 (Reading)

"HELLO from 192.168.0.2 discarded...invalid helloInterval 10 ... Stub & Totally Stubby: reduce the resource utilization ... Type 7 LSAs = Type 5 LSAs in disguise ... THE VRRP INSTANCE MUST BE DISABLED BEFORE CHANGING THE PRIORITY"

— ALE Training, OSPF / Areas / VRRP (220 p496, p455-456, p413)

I — 方法论骨架 (Interpretation)

园区 IGP 的 AOS 实现骨架： 1. 基础: 静态路由默认优于动态（Local 1 < Static 2 < OSPF 10/110 < ISIS 115/118 < RIP 100/120 < EBGP 190 < IBGP 200，以 show ip route-pref 为准，可用 ip route-pref 改）；主备默认路由用 metric 1/2 区分；下一跳随动态路由变化用递归 follows。Loopback0 做 router-id/BGP peering/服务源地址。 2. OSPF 七步: router-id → ip load ospf → area（定类型）→ interface → 接口入 area 并 admin-state enable（R8 逐接口）→ 重分发（如需）→ 全局 enable。 3. 区域阶梯（问题驱动: LSA 太多/路由表太大）: standard → stub（拒 Type4/5，ABR 注默认）→ totally stubby（再拒 Type3）→ NSSA（本区要挂 ASBR，Type7 进、ABR 转 Type5 出）。每种区域 = 一组允许进入的 LSA 白名单。 4. 收敛路由表: 内部路由在 ABR 做 Summarization，外部路由在 ASBR 做 Aggregation——位置决定动作。 5. 重分布两步法: 先 route-map（有序语句，命中即停；同字段多 match=或、跨字段=与），后 ip redist <源> into <目的> route-map <名>；配了重分布即成 ASBR。 6. 邻居排障范式: show ip ospf interface → swlog appid ospf_0 subapp all level debug3 → 日志找 discard 原因（Hello interval/认证/area/MTU 两端不一致）→ 修正到 Full。 7. IS-IS: NSAP(AFI 49, ≥8 字节) / system-id 全网唯一；DIS 选举=最高优先级→最高 MAC，可抢占，L1 要求 area-id 相同。 8. VRRP: 双核心用两个 VRID 互为主备做出向负载分担；track 对象关联上行故障自动降优先级，治"网关活着但出口死了"；改 priority 前必须先 disable。

A1 — 书中的应用 (Past Application)

案例 1: OSPF 七步配置+重分布（c18, 220 p477-482）

  • 问题: 园区标准 OSPF 开局并把 RIP 路由引入。
  • 方法论的使用: router-id 192.168.254.7 → load → area 0 + area 1 type normal|stub|nssa → interface → 接口入 area + enable → route-map RipIntoOspf 过滤 → redist rip into ospf → 全局 enable。
  • 结果: 邻居 Full，仅 route-map 允许的前缀被引入。

案例 2: 邻居卡非 Full 排障（c19, 220 p495-496）

  • 问题: 两台交换机 OSPF 邻居起不来。
  • 方法论的使用: 开 ospf_0 debug3 日志 → grep 得 "HELLO ... discarded...invalid helloInterval 10"（一端 20s 一端 10s）。
  • 结论: 统一两端参数。
  • 结果: "# of Full State Neighbors = 1"。该"日志级别旋钮换协议内部视图"法可复用到所有协议排障。

案例 3: Route Map 重分布控制（c20, 220 p501-509）

  • 问题: static→rip 只放行默认路由、拒绝 10/8。
  • 方法论的使用: seq 1 deny match 10.0.0.0/8（命中即停不重分发）→ seq 2 permit 0.0.0.0/0 → 挂到 ip redist；ACL 辅助聚合前缀；set metric effect add 改属性。
  • 结果: show ip redist 只见预期路由。

案例 4: VRRP + track 联动（c15, 220 p403-404）

  • 问题: 双核心网关冗余且上行故障要联动切换。
  • 方法论的使用: ip vrrp 1 interface int_20 address 192.168.20.254 + priority/preempt → track 3 priority 30 port 1/1/3 → track-association。
  • 结果: 上行口 down 时优先级被扣减触发主备切换，虚拟 MAC 00-00-5E-00-01-{VRID} 保证终端无需重 ARP。

案例 5: IS-IS 单区域最小配置（c43, 220 p1086-1087）

  • 问题: 纯 IP IS-IS 或理解 SPB 控制面。
  • 方法论的使用: ip load isis → area-id 49.0001 → activate-ipv4 → 逐 vlan enable + address-family v4。
  • 结果: show isis adjacency 正常。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 园区 IGP 选型与开局: 静态/RIP/OSPF/IS-IS 怎么选、OSPF 七步怎么落。
  2. 边缘区域裁剪: "stub 交换机路由表应以默认路由收尾"，四种区域类型怎么选。
  3. 协议间引入路由: route-map 先行，防误全网重分发成环。
  4. 邻居排障: 卡 Init/2-Way/EXSTART 不上 Full。
  5. 网关冗余: VRRP 双 VRID 分流 + track 上行联动。

语言信号 (用户的话里出现这些就应激活)

  • "OSPF 邻居 Full / EXSTART / helloInterval / router-id / area 0 / 虚链路"
  • "stub / totally stubby / NSSA / LSA / 路由表太大"
  • "重分布 / redist / route-map / ASBR / 路由引入"
  • "静态默认路由 / metric 主备 / follows 递归"
  • "IS-IS / NSAP / DIS / L1L2"
  • "VRRP / master backup / 网关冗余 / track 上行口"

与相邻 skill 的区分

  • 与 aos-bgp-vrf 的区别: AS 间/外部路由与 VRF 隔离在那边；本 skill 是域内 IGP 与网关冗余。
  • 与 aos-spb-fabric 的区别: SPB 用 IS-IS 做 L2 织构控制面（spb isis），本 skill 是纯 IP 路由的 IS-IS。
  • 与 aos-lag-stp 的区别: LAG/DHL 是链路冗余；VRRP 是网关冗余，层次不同。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 需求定位: 判定是开局配置、区域设计、重分布还是邻居排障/网关冗余。
  2. 完成标准: 明确任务类型与涉及的协议。
  3. 开局（OSPF 七步）: router-id（手工指定或稳定 Loopback0）→ load → area 定类型 → interface → 接口入 area + enable → 重分发（如需）→ 全局 enable。
  4. 完成标准: show ip ospf neighbor 全 Full，show ip routes 出现预期前缀。
  5. 区域裁剪决策两问: 该区域要不要看外部路由？要不要自己重分发？——据此选 stub/totally-stubby/NSSA；不直连骨干的区域用虚链路补救（新设计应避免）。
  6. 完成标准: stub 交换机路由表以指向骨干 ABR 的默认路由收尾。
  7. 重分布: 先建 route-map（deny 即停、全不命中隐式丢弃），再 ip redist ... route-map ... enable；需要收敛路由表时按位置选 ABR Summarization / ASBR Aggregation。
  8. 完成标准: show ip redist 与 route-map 序列一致，无环（双向重分布必配 tag/过滤）。
  9. 邻居排障范式: show ip ospf interface 比对两端（Hello/Dead、认证、area、MTU）→ swlog appid ospf_0 subapp all level debug3 → 日志定位 discard 原因 → 修正复查 Full 计数。
  10. 完成标准: 邻居 Full 且日志无 discard。
  11. VRRP: 建 VR+虚地址；双核心分流配两个 VRID 互为主备；track 对象（PORT/IP/VLAN）关联扣减优先级；改 priority 先 admin-state disable 再 enable。
  12. 完成标准: show ip vrrp 角色符合设计，拔上行口演练切换成功。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • BGP 邻居/属性策略、VRF 与 route leak → aos-bgp-vrf。
  • SPB 织构（BVLAN/I-SID/spb isis）→ aos-spb-fabric；SPB 场景 IS-IS 由 spb isis 接管。
  • 二层链路冗余（LAG/DHL/STP）→ aos-lag-stp。

作者在书中警告的失败模式

  • ce17: OSPF 邻居起不来的第一嫌疑是 Hello/Dead 定时器或认证参数不匹配（日志 "invalid helloInterval"）；区域不直连骨干需虚链路。
  • ce18: ECMP 最多 4 条且仅 per-flow，per-packet 不支持——单流永远走哈希选定的单链路。
  • ce16: RIP 定时器硬约束 invalid ≥ 3×update，违反被 AOS 拒绝。
  • ce15: VRRP 改 priority 前必须先禁用实例，否则不生效。
  • ce33: IS-IS DIS 选举可抢占——后上线的高优先级路由器会立即抢走 DIS 触发全网 LSP 突增；L1 邻接要求两端 area-id 相同；克隆配置导致 system-id 重复会邻接异常。
  • p52: 任何重分布都应挂 route-map；Loopback0 与 OSPF 接口网段自动通告，local VLAN 网段需 redist local。
  • p53: GR 对 OSPF/IS-IS 默认关闭、BGP 默认开启——升级/主控切换前要检查。

作者的盲点 / 时代局限

  • 偏好值课件两处数值略异（如 OSPF 10 vs 110），实机以 show ip route-pref 为准。
  • 教材仅覆盖 IPv4 IGP；IPv6 仅零散提及不成体系。

容易混淆的邻近方法论

  • OSPF DR 选举（最高优先级→最高 RID）方向与 STP 根桥/VC Master（最低者优先）相反；与 IS-IS DIS 的差别是后者可抢占。
  • ABR Summarization vs ASBR Aggregation: 同是收敛，位置决定动作。
  • VRRP track vs DHL pre-emption: 都是故障联动，前者扣网关优先级、后者是链路回切防抖。
