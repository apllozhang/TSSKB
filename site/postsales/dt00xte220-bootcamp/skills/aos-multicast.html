aos-multicast

SKILL 来源页码: Multicast (p692-761) / Anycast RP (p1031-1040)

组播体系：IPMS / IGMP / PIM-SM / Anycast RP

R — 原文 (Reading)

"If in same VLAN, switch packet — use IPMS forwarding table; If in different VLAN, route packet — use DVMRP/PIM forwarding table" (p706)

"Calculation steps for selecting the RP: ...best priority (lowest value), Highest Hash value using the group address, the RP address... This feature will only be supported with PIM-SM... SPT must be enabled when supporting Anycast-RP."

— OmniSwitch LAN R8 Bootcamp Ed23, Multicast/Anycast RP, p746/p749-750, p1035

I — 方法论骨架 (Interpretation)

收到组播包先二分：目的端口与入端口同 VLAN → L2 交换（IPMS/IGMP snooping 转发表）；跨 VLAN → L3 路由（DVMRP/PIM 转发表，改写源 MAC 为路由器口 MAC）。IPMS 通过截获 IGMP query/report 把"按网络跟踪成员"细化为"按端口跟踪成员"硬件转发。

L2 最小三件套：全局 ip multicast admin-state enable（可按 VLAN）→ 接服务器的交换机开 querying enable（多台选一台 querier）→ 其余开 querier-forwarding enable。不开 IPMS 时组播在 VLAN 内洪泛。IGMP 默认 v3、查询间隔 125s、router-timeout 90s、TTL 恒 1 不跨路由器。

限组与体验：max-group 可按全局/VLAN/端口设，端口级覆盖 VLAN/全局；超限动作 none/drop/replace（换台场景用 replace，新请求替换旧成员）。路由环境为每流缓冲首批组播包（默认 4、最多 10）防加入前首包丢失——治 IPTV 换台黑屏。

组播路由选型：一个接口只能跑一个组播路由协议（PIM 或 DVMRP，各限 128 接口）。接收者密集小网用 PIM-DM（flood-prune 每 3 分钟一轮、无 RP）；稀疏用 PIM-SM：显式 join + RP 共享树 + SPT 切换（最后 DR 收到首包即自动 (S,G) join，默认开启）。

RP 的两套机制：BSR 自动选举——先选 BSR（C-BSR 比 priority→IP），C-RP 向 BSR 通告，全网为每组算 RP（priority 最小 → (组地址,RP 地址) hash 最大 → IP 最大），不同组天然散到不同 RP 且全网一致；静态 RP（ip pim static-rp）可覆盖 BSR。RP 冗余用 Anycast RP：多台 RP 共享一个 Loopback 地址以主机路由宣告进 IGP，全域所有 PIM 路由器静态指 RP，RP 间独立 Loopback 组 RP set 互相同步 register；失效收敛速度 = IGP 收敛。

A1 — 书中的应用 (Past Application)

案例 1: PIM-SM 四核心实验（216 p447-448, p510-518 背景）

  • 问题: 跨核心/跨 VLAN 分发组播流。
  • 方法论的使用: ip load pim → 全局 sparse enable → 接口逐个 ip pim interface → cbsr 各指本机 loopback、C-RP 按组段划分。
  • 结论: BSR/RP 声明一次成型，无需逐台指 RP。
  • 结果: show ip pim group-map/groute/sgroute 验证 SPT Bit=True、Register State=Pruned，即 RPT→SPT 切换完成（c32）。

案例 2: Anycast RP 冗余设计（220 p1033-1039）

  • 问题: 单 RP 是组播域单点故障。
  • 方法论的使用: 多台 RP 配同一 Anycast Loopback（如 10.10.10.1）宣告进 IGP；ip pim static-rp <组段> 10.10.10.1 必须存在于域内所有 PIM 路由器；RP 间 ip pim anycast-rp <anycast地址> <本机Loopback0> 同步 register。
  • 结论: 源/接收者按 IGP 最近路径选 RP，RP 失效收敛 = IGP 收敛。
  • 结果: RP 故障无感知切换；约束满足（仅 SM、≤8 台、SPT 开启）（f32/ce32）。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. IPTV/视频会议部署：VLAN 内按端口下发（IPMS+querier）、端口限频道数、换台黑屏。
  2. 跨 VLAN/跨核心组播路由：PIM-SM 选型、BSR/C-RP 规划、SPT 行为解释。
  3. RP 可靠性：单 RP 挂了整域断流的担忧，需要 Anycast RP 冗余设计或排障（源注册到一个 RP、接收端查另一个 RP 收不到流）。

语言信号 (用户的话里出现这些就应激活)

  • "IPMS / IGMP snooping / querier 怎么配"
  • "throttling / max-group / 机顶盒限频道"
  • "PIM / BSR / candidate-RP / static-rp / SPT 切换"
  • "Anycast RP / RP 冗余 / RP 挂了"
  • "组播不通 / 洪泛 / 换台黑屏 / 首帧丢失"

与相邻 skill 的区分

  • 与 aos-spb-fabric 的区别: 本 skill 管组播成员管理与路由（IGMP/PIM/RP）；SPB 骨干里 BUM 怎么复制（head-end/tandem）属 SPB skill。
  • 与 aos-qos-acl-pbr 的区别: 组播流量带宽保障/标记走 QoS skill；加入/剪枝/选 RP 走本 skill。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 判定转发层级
  2. 确认接收者与源是否同 VLAN：同 VLAN → L2 方案（步骤 2）；跨 VLAN → L3 方案（步骤 3）。

  3. 完成标准: 明确回答"交换还是路由"并给出对应配置族。

  4. L2 组播（IPMS）配置

  5. 输出三件套（admin-state enable → 接服务器者 querying enable、其余 querier-forwarding enable）；按需加 throttling（端口级 max-group + replace 动作）与 initial-packet-buffer（默认 4 包）治首帧丢失；验证 show ip multicast group/neighbor/forward。
  6. 完成标准: 采样口不再收到未订阅组、换台无黑屏。

  7. 判停条件: 若需跨 VLAN，跳步骤 3。

  8. 组播路由与 RP 规划

  9. 按接收者密度选 DM/SM（DM 仅小密网）；SM 下规划 BSR（cbsr 指本机 loopback）与 C-RP 按组段划分，或全域 static-rp（可覆盖 BSR）；确认 SPT 默认开启；验证 show ip pim interface/neighbor/candidate-rp/cbsr/group-map/groute/sgroute。

  10. 完成标准: group-map 显示每组 RP 与设计一致，sgroute 的 SPT Bit=True。

  11. RP 冗余核查（如需高可用）

  12. 硬约束预检：仅 PIM-SM、静态 RP set ≤8 台、SPT 必须开（ce32）；输出 Anycast Loopback + IGP 主机路由 + 全域 static-rp + RP set 互联配置。
  13. 完成标准: 拔任一 RP 后接收端收敛时间 ≈ IGP 收敛，源注册与成员查询不再同 RP 也不丢流。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • SPB 骨干内的 BUM 复制模式选型（head-end/tandem）——属 aos-spb-fabric，本 skill 只管到成员管理与 PIM 层。
  • 组播流量的带宽保障/限速策略——属 aos-qos-acl-pbr。

作者在书中警告的失败模式

  • Anycast RP 硬边界（ce32）: 在 PIM-DM/BIDIR/SSM 网络里部署不生效；SPT 未启用时注册转发模型不成立；静态配置超 8 台 RP 超限。警告信号：源注册到一台 RP、接收端只查另一台 RP 收不到流。
  • 接口协议互斥: 一个接口只能跑 PIM 或 DVMRP 之一，混配直接冲突。

作者的盲点 / 时代局限

  • 教材以 IPv4 PIM-SM 为主，SSM/BIDIR 仅提及不支持 Anycast RP；DVMRP 属旧协议兼容（现网少用），新设计不应选它。

容易混淆的邻近方法论

  • BSR 自动 RP vs 静态 RP：两者可共存且静态优先；Anycast RP 一定基于静态 RP 地址，不是 BSR 的替代品而是叠加的冗余构造。
  • PIM-DM 的 flood-prune 与 L2 洪泛：前者跨网段周期泛洪（3 分钟一轮），后者是未开 IPMS 时的 VLAN 内行为。
