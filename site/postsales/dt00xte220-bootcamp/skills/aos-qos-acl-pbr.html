SKILL 来源页码: QoS/ACL/PBR p581-632

AOS QoS/ACL/PBR 统一策略引擎

R — 原文 (Reading)

"a policy (or a policy rule) is made up of: 1. a condition 2. an action ... The rule is not active on the switch until it has been applied (qos apply) ... Adding the source port to the condition allows traffic to not get caught in a loop"

— ALE Training, QoS (220 p589-594, p603-604)

I — 方法论骨架 (Interpretation)

AOS 把标记、限速、ACL、重定向、镜像全部收敛到一个三段式策略引擎： 1. condition（L1-L4 任意组合: ip/mac/port/vlan/network group/port group/服务）→ 2. action（priority/802.1p/DSCP 标记、cir 限速、redirect、mirror、port-disable、disposition accept|drop）→ 3. rule（condition+action+precedence+可选 validity-period 时段）。规则不匹配默认放行；改端口级配置必须 qos apply 才生效（qos revert 撤销 / qos flush 清空）。

配套旋钮： - 端口信任模型: 默认 untrusted（打 default 802.1p），trusted 口才保留入站 802.1p/ToS——信任边界设错是一切标记问题的根源。 - 话机自动优先级: qos phones 默认开启，按内置 MAC 组（00:80:9F 等）给 priority 5，trusted/untrusted 口都生效。 - PBR 防环: 去程 rule 用 permanent gateway 指向防火墙；回程规则的 condition 必须加 source port（防火墙回连口），否则路由环路。硬件转发。 - 策略镜像: action 里 ingress/egress mirror 端口，可叠加 disposition drop（丢弃原流量但副本仍送出）；整机同时仅 1 会话。 - 保留组: UserPorts 自动丢源 IP 欺骗并可叠加 filter/shutdown spoof|rip|ospf|bgp|bpdu；DropServices 丢指定 TCP/UDP 服务。

A1 — 书中的应用 (Past Application)

案例 1: QoS policy 全流程（c23, 220 p586-597）

  • 问题: 按源 IP/端口组标记优先级并限速。
  • 方法论的使用: policy condition（source ip / port group / network group）→ policy action（priority 7 / 802.1p 7 / cir / redirect）→ policy rule 绑定 + precedence + validity-period → qos apply。
  • 结论: 一切策略流量处理共用此框架。
  • 结果: show active policy rule 含 Green/Yellow/Red 三色计数可见匹配。

案例 2: PBR 旁挂防火墙两段式防环（c25, 220 p603-604）

  • 问题: 源 10.10/16 的流量强制经旁挂防火墙上网。
  • 方法论的使用: 去程 condition Traffic10(source ip) + action Firewall permanent gateway 192.168.99.254；回程 condition TrafficFromFW 加 source port 2/1/1 + action To_Internet permanent gateway 出口网关。
  • 结论: 回程不加 source port 会被去程规则再次抓住成环。
  • 结果: 流量硬件转发经防火墙往返，无环路。

案例 3: 话机自动加速与策略镜像（c24/c26, 220 p599, p608）

  • 问题: VoIP 快速保障；按 IP 精细抓包取证。
  • 方法论的使用: qos phones priority 5（默认开）；镜像: condition c1 source ip 1.1.1.1 + action a1 ingress egress mirror 1/1/1（例 2 加 disposition drop 丢弃留证）。
  • 结果: 话机流量自动 priority 5；目标流量副本到抓包口。

案例 4: ACL 与用户口防护（c27, 220 p622-631）

  • 问题: 封 MAC 主机、禁网段、拦 ICMP/蠕虫端口。
  • 方法论的使用: L2 condition（source mac+vlan）disposition deny；network group 批量；policy service group DropServices（tcp135/445/udp137）；UserPorts 保留组 filter spoof/rip/ospf/bgp；port-disable 动作 + violation-recovery-time。
  • 结果: 规则命中计数增长、风险端口被丢弃。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. "话机流量要自动加速/语音优先"——qos phones + 信任边界。
  2. "旁挂防火墙/上网行为管理，流量强制走它"——PBR 两段式防环设计。
  3. "按 IP/协议限速、封端口、封网段"——三段式 policy + qos apply。
  4. "只想镜像某个 IP 的流量/取证时丢弃并留证"——policy mirror。
  5. "配了 QoS/ACL 不生效"或"没匹配的流量被拦截了？"——apply 纪律与默认放行。

语言信号 (用户的话里出现这些就应激活)

  • "QoS / 优先级 / 802.1p / DSCP / 标记 / trust / trusted 口"
  • "policy condition / policy action / policy rule / qos apply"
  • "ACL / deny / disposition / 封 IP / 封端口"
  • "PBR / permanent gateway / 重定向到防火墙 / redirect"
  • "限速 cir / 带宽限制 / 策略镜像 policy mirror"

与相邻 skill 的区分

  • 与 aos-access-guardian-unp 的区别: 那是"谁能进、进哪个 VLAN"；本 skill 是"进来的流怎么处理"。
  • 与 aos-l2-security 的区别: 专用安全特性（snooping/DAI/LPS/PVLAN/MACsec）在那边；本 skill 是通用策略引擎，UserPorts 等保留组在本 skill 编写。
  • 与 aos-diagnostics-ops 的区别: 端口镜像/monitoring 的会话规格与抓包工具在那边；基于策略的镜像在本 skill。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 先定信任边界: 判断入端口是否 trusted（决定保留还是重打 802.1p/ToS）；话机场景确认 qos phones 状态。
  2. 完成标准: 明确每个相关端口的 trust 配置与预期标记。
  3. 搭三段式: policy condition（可先建 ip/mac/network/port group 复用）→ policy action（标记/限速/redirect/mirror/disposition）→ policy rule（precedence 冲突时小值优先，需要时段加 validity-period）。
  4. 完成标准: show qos policy 显示规则完整、无序号冲突。
  5. qos apply 提交: 端口级修改后必须 apply；改错用 qos revert 撤销、qos flush 清空重来。
  6. 完成标准: show active policy rule 规则状态为 active 且计数器开始走。
  7. PBR 场景强制两段: 去程 permanent gateway 指防火墙；回程 condition 必须加 source port（防火墙回连口）+ 出口网关动作；打流验证去回路径。
  8. 完成标准: traceroute 去程经防火墙、回程走正常网关，无 TTL 递减环路。
  9. 验证与计数: show active policy rule count packets/bytes 看三色计数；未匹配流量按默认 accept 复核安全预期。
  10. 完成标准: 测试流命中预期规则，非目标流不受影响。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 终端身份认证/动态 VLAN（802.1X/UNP）→ aos-access-guardian-unp。
  • DHCP snooping/DAI/LPS/PVLAN/MACsec 等专用安全特性 → aos-l2-security。
  • 普通 port-mirroring/port-monitoring 会话规划与诊断工具 → aos-diagnostics-ops。

作者在书中警告的失败模式

  • ce21: (1) 默认不匹配任何 policy 的流是 ACCEPT——把 QoS/ACL 当白名单防火墙会落空；(2) 修改端口 QoS 后不 qos apply 配置停在 pending 不生效。
  • p63/c25: PBR 回程规则不加 source port → 路由环路（流量被去程规则反复抓住）。
  • ce22: port mirroring 与 monitoring 不能同口；基于策略的镜像同时仅 1 个会话。
  • p60: 端口默认 untrusted，trusted 口才保留入站 802.1p——信任边界设错导致话机标记被盖。
  • p61: qos phones 默认开启且优先级是"强制 priority 5"而非仅 trust；加新厂商话机需重定义 alaPhones MAC 组。
  • p62: violation-recovery-time 0 表示不自动恢复——port-disable/shutdown 类动作需规划恢复窗口。

作者的盲点 / 时代局限

  • 教材 policy 语法绑定 AOS 8.x；镜像会话上限（4 会话/4 MTP）仅适用于 6860/6865/6900 8.9R3+，其他机型需查 spec。
  • 三色计数（Green/Yellow/Red）依赖 cir 配置，不限速时仅看 packet/byte 计数。

容易混淆的邻近方法论

  • disposition deny 的 ACL vs 专用安全特性: ACL 是通用引擎，snooping/DAI 有自己的表与信任模型，混配时注意 DAI 依赖 binding 而非 policy。
  • qos apply 纪律 vs 全局 QoS 设置: 全局参数立即生效，端口级才需要 apply。
