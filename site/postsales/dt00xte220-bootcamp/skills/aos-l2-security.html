SKILL 来源页码: 网络与安全 p331-363; DHCP p556-574; ACL p618-632(部分); Private VLAN p848-857; MACsec p789-818

AOS Consistent Security 二层安全特性集

R — 原文 (Reading)

"Untrusted ports only accept DHCP Discover and Request messages; DHCP Offer and ACK are dropped ... DAI is implemented by combining both DHCP snooping and IP source filtering capabilities ... Default violation is restricted"

— ALE Training, Network Security / DHCP (220 p566-568, p573, p356-359)

I — 方法论骨架 (Interpretation)

AOS 把 L2 安全做成一组可独立开关、可层层叠加的特性，按攻击面选型： 1. 欺骗类: DHCP 信任分级（trusted 口全放、untrusted 只放 Discover/Request → 流氓服务器被隔离）→ snooping 建 binding 表 → Option-82 插入位置信息 → IP source filter 按表校验源 MAC/IP → DAI（snooping+source-filter 组合）校验 ARP 防中间人。链条逻辑: 信任分级→绑定表→源校验→ARP 校验。 2. ARP/CPU 类: 内建 DoS 过滤（ICMP 5s 均值>100pps 判攻击）+ ARP defense（未解析下一跳 12 次×5s 建 drop-entry）+ poisoning detection（只接受自己发起请求的 Reply）+ restricted-address 静态钉网关。 3. 隔离类: Port Mapping（user↔network 口，user 间永不通；双向 MFF=Port Mapping+dynamic proxy ARP+DHCP snooping）、Private VLAN（primary/secondary community/isolated，先 capability shared-vlan-learning enable）。 4. 资源类: 风暴控制（bcast/mcast/uucast 按 pps/mbps/容量百分比，动作 shutdown/trap）、LPS（默认 max MAC=1、filtered=5、violation=restrict；shutdown 300s 自动恢复）。 5. 加密类: MACsec（先核对端口能力/免费 site license/机型 static|dynamic 模式矩阵；动态 SAK 按时间 5-120min 或流量 5-1000GB 先到先换；静态 SA ≤4 key，sci-tx/rx 两端交叉）。

A1 — 书中的应用 (Past Application)

案例 1: 安全特性集全套配置（c13, 220 p336-361）

  • 问题: 接入层防 ARP 中间人、限端口 MAC、抑风暴。
  • 方法论的使用: ip dos arp-poison restricted-address 钉关键地址；arp filter sender block；port-mapping session user/network 口；flood-limit bcast rate pps 500 action shutdown；port-security maximum 1 violation shutdown。
  • 结论: 每特性独立开关，按攻击面组合。
  • 结果: show ip dos / show port-security 验证各特性计数。

案例 2: DHCP 全家桶防欺骗（c22, 220 p558-579）

  • 问题: 跨网段 DHCP 且防私接服务器与 ARP 欺骗。
  • 方法论的使用: relay（global 与 per-interface 互斥二选一）→ dhcp-snooping vlan enable + mac-address-verification + option-82-data-insertion → port trust 只给服务器口 → ip-source-filter → dynamic-arp-inspection。
  • 结论: 服务器/上级 relay 口必须 trust，否则 OFFER/ACK 在非信任口被丢。
  • 结果: show dhcp-snooping binding 有表项、客户端取到地址、DAI 正常放行合法 ARP。

案例 3: MACsec Dynamic SA 实验（c34, 220 p808-818）

  • 问题: 机房间敏感链路加密。
  • 方法论的使用: 先查 capability/license → 明文 ping 基线 → security key/key-chain → 端口 macsec mode dynamic key-chain + key-rotation → 验证 Key Server/Operation Status UP。
  • 结论: 平台矩阵碎片化（6860N 仅 dynamic、VFL 口不支持），license 免费但必须先 apply。
  • 结果: 加密后 ping 仍通，show interfaces macsec dynamic 状态 UP。

案例 4: Private VLAN 同子网隔离（c36, 220 p852-853）

  • 问题: 酒店式同子网用户互相隔离。
  • 方法论的使用: pvlan 100 + secondary 101 community / 103 isolated，promiscuous 口接网关。
  • 结果: MAC 全学在 primary VLAN 100，isolated 口互相不可达。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. "ARP 欺骗/中间人怎么防"——选型 poisoning detection / DAI / restricted-address。
  2. "私接 DHCP 服务器 / 客户端拿不到地址"——DHCP snooping 信任模型与 DAI 组合。
  3. "端口下限制终端数/防私接 hub"——LPS；"广播风暴打挂交换机"——flood-limit。
  4. 同子网用户隔离（酒店/宿舍/医院）——Port Mapping/MFF vs Private VLAN 选型。
  5. 敏感链路二层加密——MACsec 可行性核对与部署。

语言信号 (用户的话里出现这些就应激活)

  • "ARP 欺骗 / ARP poisoning / 中间人 / DAI / dynamic ARP inspection"
  • "DHCP snooping / Option-82 / 流氓 DHCP / binding 表"
  • "port-security / LPS / 限 MAC / 风暴控制 / storm control / broadcast 抑制"
  • "Private VLAN / PVLAN / 用户二层隔离 / MFF / port mapping"
  • "MACsec / 链路加密 / SAK / key-chain"

与相邻 skill 的区分

  • 与 aos-access-guardian-unp 的区别: 那按"终端身份"动态给策略；本 skill 是不问身份的端口级防护特性。
  • 与 aos-qos-acl-pbr 的区别: 那是 policy condition/action 统一引擎（标记/限速/重定向/ACL 规则编写）；本 skill 是专用安全特性（部分 ACL 实例会引用 policy 框架，但选型判断在此）。
  • 与 aos-switch-access-mgmt 的区别: 那是管理员登录/管理面加固；本 skill 面向用户数据面。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 攻击面定位: 明确威胁（欺骗/泛洪/私接/隔离/窃听），映射到特性组。
  2. 完成标准: 列出候选特性及其防御的攻击面。
  3. 按链条配置而非单点: 如 DHCP 方向 → relay 二选一 → snooping + binding → 服务器口 port trust → Option-82（按需）→ ip-source-filter → DAI。
  4. 完成标准: 每步有对应 show 命令输出验证（show dhcp-snooping [vlan|port|binding]）。
  5. 资源类参数落地: flood-limit 选单位（pps/mbps/cap%）+ 动作（shutdown 配 recovery）；LPS 设 maximum/violation，需要锁定时先让终端流量到达再 convert-to-static。
  6. 完成标准: show port-security 显示 MAC 上限与状态；违例动作演练过。
  7. 隔离类选型: 需要 DHCP 网关代理→MFF（Port Mapping+dynamic proxy ARP+snooping 组合）；纯静态→PVLAN（先 capability shared-vlan-learning enable；一个 primary 只能 1 个 isolated）。
  8. 完成标准: 用户口间不通、到网关/promiscuous 口通。
  9. MACsec 前置核对: show interfaces capability 的 Macsec 列 → license apply（免重启）→ 机型模式（static/dynamic）→ dynamic 配 key-chain+key-rotation；static 配 ≤4 key 且两端 sci-tx/rx 交叉。
  10. 完成标准: 加密后业务仍通，show interfaces macsec 状态 UP。
  11. 整体验证: 模拟攻击面（伪造 ARP/假 DHCP/超限 MAC）确认拦截计数增长。
  12. 完成标准: 各特性 show 计数反映测试流量被处置。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 按用户身份动态放行/分 VLAN（802.1X/UNP）→ aos-access-guardian-unp。
  • 编写复杂 policy condition/action 规则（限速/重定向/镜像）→ aos-qos-acl-pbr。
  • 管理员登录、SSH、管理站白名单 → aos-switch-access-mgmt。

作者在书中警告的失败模式

  • ce20: DHCP 服务器不在 trust 口 → OFFER/ACK 被 untrusted 口丢弃，全网 DHCP 失败；snooping 没配好，DAI 依赖的 binding 表为空会大量误杀。
  • ce38: LPS convert-to-static 必须在终端 MAC 已学到之后执行，否则无 MAC 可锁、换设备仍能上网；LPS 不支持 LAG 口、仅固定口。
  • ce37: Port Mapping 双向会话的 network 口不能与任何会话共享（单向可共享）；同会话 user 口之间永远不能直通。
  • ce25: MACsec 平台矩阵碎片化——6870 VFL 口/6465T 11-12 口不支持、6860N 仅 dynamic、需免费 site license；两端 SAK/SCI 不匹配则口 up 不通。
  • ce35(后半): PVLAN 下端口 isolated/community 角色由首 MAC 决定，首 MAC 落普通 VLAN 则角色不可再变。
  • p82: 一个 Primary VLAN 只能有 1 个 isolated secondary；PVLAN 前须 shared-vlan-learning。

作者的盲点 / 时代局限

  • 教材安全特性以 AOS 8.x 为准；ARP 防御阈值（12 次×5s）、ICMP 100pps/5s 为固定或半固定参数，实际攻击工具速率远超时更依赖风暴控制与 quarantine 联动。
  • LPS 不支持 LAG，与"单链路也建 LAG"的最佳实践(p108)冲突时需取舍。

容易混淆的邻近方法论

  • MFF vs Private VLAN: 都做同子网隔离；MFF 需 DHCP+snooping 组合且网关代理 ARP，PVLAN 静态、需 shared-vlan-learning。
  • qos user-port filter bpdu（属 policy 框架）与 LPS/shutdown 类端口处置容易被混为一谈。
