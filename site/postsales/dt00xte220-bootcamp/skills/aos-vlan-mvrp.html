SKILL 来源页码: 220 p135-155 (VLAN/动态 VLAN), p317-324 (MVRP)

VLAN / 802.1Q / 动态 VLAN (UNP 分类) / MVRP

R — 原文 (Reading)

"This VLAN CANNOT be deleted, but it can be disabled... Without members the VLAN will be Operationally down." (220 p157, p167) "sw5 -> no vlan 40 → ERROR: Dynamic vlan 40 cannot be deleted... the VLAN 40 has been automatically re-created." (220 p328)

— ALE Training, OmniSwitch LAN R8 Bootcamp Ed23, p147-167 / p320-328

I — 方法论骨架 (Interpretation)

AOS 的 VLAN 体系分三层，逐层动态化：

  1. 静态 VLAN + 802.1Q: 建 VLAN → 加 untagged/tagged 成员 → enable/name（支持范围 vlan 10-15）。铁律：每个物理口永远有一个 untagged 默认 VLAN（trunk 上其余打 tag）；VLAN 无 active 成员即 oper down，绑定的 IP 接口随之 DOWN（不响应 ping 但 L2 广播域还在）。VLAN1 是默认 VLAN，不可删只能禁用。VLAN 间路由 = 给 VLAN 绑 IP 接口即自动开启 IP 转发（第一个绑定的接口为 primary）。
  2. 动态 VLAN = UNP 分类: 无认证场景下按终端特征自动选 VLAN——unp profile X map vlan N + unp classification-rule（单条 mac-address / mac-address-range / ip-address mask；组合 binding rule；扩展规则可带 precedence 与多条件）。分类匹配次序固定：Port/Linkagg > Domain > MAC > MAC-OUI > MAC range > LLDP > Auth-type > IP > VLAN tag；规则形态优先级 Extended > Binding > Simple。未匹配流量落端口的 default-profile（通常指向隔离 VLAN）。
  3. MVRP 跨交换机传播 VLAN: 前提三件——STP flat 模式 + mvrp enable 全局 + 端口/linkagg 级 enable。动态 VLAN 上限默认 256（mvrp maximum-vlan，调小需重启 MVRP 才生效）；registration normal/fixed/forbidden 与 applicant 模式控制声明行为。动态 VLAN（type=dyn）的生命周期归协议管：本地 no vlan 删不掉，必须先在声明侧删 VLAN 或先禁 MVRP 端口。MVRP 不能配在 mirror/unp/VPLS access/VLAN stacking user 口。

A1 — 书中的应用 (Past Application)

案例 1: 静态 VLAN + trunk + VLAN 间路由 (220 p138-152, c05)

  • 问题: 两个业务部门隔离并互访。
  • 方法论的使用: vlan 2 → vlan 2 members port 1/1/2 untagged → 上联 vlan 2-4 members port 1/1/24 tagged → ip interface Data address 10.1.20.254 mask 255.255.255.0 vlan 20。
  • 结论: 接入口 untagged、上联口 tagged、网关绑 VLAN 的三段式是所有 L2 开局模板。
  • 结果: show vlan 20 / show vlan members / show ip interface 验证通过。

案例 2: UNP 按 MAC 范围自动分 VLAN (220 p142-145, c06)

  • 问题: 无认证环境下按终端类型分流到 corporate/隔离 VLAN。
  • 方法论的使用: 建 VLAN10(隔离)/VLAN20(业务) → unp profile corporate map vlan 20、default-profile 指向 vlan10 → unp classification-rule rule1 mac-address-range 08:00:27:00:98:0A ... 98:FF → 端口 port-type bridge。
  • 结论: 未匹配终端落默认隔离 VLAN，实现"未知终端即隔离"。
  • 结果: 教材验证终端按 MAC 段自动进 VLAN20。

案例 3: MVRP 动态注册与"删不掉" (220 p320-328, c12/ce06)

  • 问题: 跨交换机手工配 trunk VLAN 太繁琐。
  • 方法论的使用: mvrp enable → mvrp port 1/1/24 enable → mvrp maximum-vlan 100；实验中删 VLAN40 报错，show vlan 确认 type=dyn 被 MVRP 立即重建。
  • 结论: 动态 VLAN 要在声明侧删或先禁 MVRP，本地强删无意义。
  • 结果: 排障路径固化为"查 type=dyn → 查声明侧 → 查 MVRP 端口状态"。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 新建/迁移 VLAN、规划 trunk 的 tagged/untagged，出现"同 VLAN 两端口不通"或"IP 接口 oper down"。
  2. 要按终端 MAC/OUI/IP 自动分配 VLAN（打印机体、访客隔离），不引入认证。
  3. MVRP 部署/排障：动态 VLAN 学不到、删不掉、maximum-vlan 调整不生效。
  4. 安全整改：想处理 VLAN1 默认广播域。

语言信号 (用户的话里出现这些就应激活)

  • "vlan tagged untagged / trunk 上哪个口不打 tag"
  • "动态 VLAN 删不掉 / Dynamic vlan cannot be deleted"
  • "MVRP / mvrp maximum-vlan / dynamic vlan"
  • "按 MAC 自动分 VLAN / UNP classification"
  • "VLAN1 能不能删"

与相邻 skill 的区分

  • 与 aos-access-guardian-unp 的区别: 那个是"认证驱动的 UNP"（802.1X/MAC 认证 + RADIUS Filter-Id + 兜底链）；本 skill 是"分类驱动的 UNP"（无认证、本地规则）。RADIUS/认证出现即转那边。
  • 与 aos-lag-stp 的区别: trunk 上跑哪个 VLAN 是本 skill；链路冗余/成环/聚合是那边。
  • 与 aos-l2-security 的区别: VLAN 隔离的设计属本 skill；ARP 欺骗/端口安全等防护特性属那边。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 判定是静态 VLAN、UNP 动态 VLAN 还是 MVRP 问题
  2. 完成标准: 三选一明确，并说出判断依据（是否涉及认证/是否跨交换机传播）。
  3. 静态 VLAN 路径: 输出建 VLAN → members（接入口 untagged / 上联 tagged）→ enable → IP 接口绑 VLAN 的命令序列
  4. 完成标准: 序列可直接粘贴；提醒"每口必有一个 untagged 默认 VLAN"；验证命令 show vlan members port X（1 untagged + N tagged）。
  5. 判停条件: 若故障是"IP 接口 down"，先查 VLAN 是否无 active 成员（oper down），再查物理口。
  6. UNP 动态 VLAN 路径: 建 VLAN（含隔离 VLAN）→ 建 profile + map vlan → 建 default-profile → classification-rule（选 simple/binding/extended）→ 端口 port-type bridge + default-profile
  7. 完成标准: 说明规则匹配次序与 Extended>Binding>Simple；未匹配流量去向明确。
  8. MVRP 路径: 核对三前提（flat 模式/全局 enable/端口 enable）→ mvrp port ... registration 按需 → maximum-vlan（提醒调小需 disable/enable MVRP）
  9. 完成标准: 若涉及删动态 VLAN，明确"先声明侧删或先禁端口 MVRP"，禁止本地 no vlan 硬删。
  10. 收尾验证: show vlan（type 列 dyn/static）、show vlan members、show ip interface、show unp user port X
  11. 完成标准: 每条改动有对应 show 验证点。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 802.1X/MAC 认证、RADIUS Filter-Id 下发 profile、auth-server-down 兜底——用 aos-access-guardian-unp。
  • LLDP-MED 话机 mobile-tag 语音 VLAN——用 aos-access-guardian-unp（ce23 属那边）。
  • 链路聚合/STP 防环/双上行冗余——用 aos-lag-stp。
  • SPB 骨干上的 BVLAN/I-SID 服务——用 aos-spb-fabric（那是私有织构体系，不是 802.1Q）。

作者在书中警告的失败模式

  • ce05: VLAN1 不可删只能禁用；出厂所有端口默认在 VLAN1，安全加固应禁用 VLAN1 并显式规划端口归属。
  • ce06: MVRP 动态 VLAN no vlan 报错且会被立即重建；正确做法是先在声明侧删 VLAN 或先 disable MVRP 端口。
  • ce07: MVRP 只能配在 fixed/802.1Q/aggregate 口（不能配 mirror/unp/VPLS access/VLAN stacking user 口）；调小 maximum-vlan 后旧动态 VLAN 不回收，须 disable→enable MVRP。
  • ce23: mobile 口不支持传统 802.1Q tag，必须用 UNP mobile-tag 机制。

作者的盲点 / 时代局限

  • 教材对 UNP 分类与 Access Guardian 的边界靠页码划分，实际配置中两者常交织（认证失败回落分类规则），需按"是否涉及认证服务器"现场判断。
  • MVRP 计时器给出推荐值（join≥250ms 等）但缺少大规模部署的收敛数据。

容易混淆的邻近方法论

  • GVRP（旧协议）vs MVRP——AOS R8 用 MVRP，且 DHL 场景禁 GVRP 端口。
  • UNP "分类规则" vs Access Guardian "认证"：同一个 unp profile 容器，两种触发路径。
