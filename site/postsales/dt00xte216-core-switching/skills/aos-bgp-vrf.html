BGP 选路策略与 VRF/Route Leak

R — 原文 (Reading)

"Route selection process: Highest Local preference / Shortest AS-Path / lowest origin (IGP>EGP>Incomplete) / Lowest MED / Closer Next-Hop / EBGP > IBGP > IGP / Lowest RID. … Routes learned via IBGP should never be propagated to other IBGP peers."

— OmniSwitch LAN R8 Bootcamp Ed23, BGP, p889/p893

"A single IP interface, as well as the VLAN associated with the interface, can only belong to one VRF instance … We will not be able to ping an IP interface of another VRF instance … due to security reason."

— 同书, VRF, p775/p785

I — 方法论骨架 (Interpretation)

BGP 的本质是"策略优先于度量"：路径好坏不由跳数决定，而由七级属性瀑布逐级比较——LocalPref 高者胜 → AS-Path 短 → Origin（IGP<EGP<Incomplete）→ MED 低 → 下一跳 IGP 度量近 → EBGP 优于 IBGP → 最低 Router ID。想改选路，从瀑布顶端往下找第一个可操纵属性。

属性是方向化的流量工程旋钮：出向流量用 LocalPref（AS 内有效、越高越优），入向流量用 MED（只告知相邻 AS、越低越优、不跨 AS 传递），批量打标用 Community。过滤走三层组装：原子 list（aspath/community/prefix）→ route-map → 挂到 neighbor 的 in/out 方向。

IBGP 有水平分割：IBGP 学到的路由不再传给其他 IBGP 邻居（防环，因为 AS_PATH 在 AS 内不增长），由此产生 full-mesh/RR 需求与"邻居 estab 却缺前缀"的经典黑洞；关闭同步时用 next-hop-self 补下一跳可达性。

VRF 是 L3 多租户隔离：一个 VLAN（及其 IP 接口）同一时刻只属一个 VRF，归属由首个接口决定，VRF 名大小写敏感。跨 VRF/到 GRT 共享服务必须 Route Leak——源 VRF export route-map 与目标 VRF import route-map 成对；同一交换机不同 VRF 的接口间即使有泄漏路由也不能互 ping（安全设计），但两端客户端可通。仅 6860E/N、6900、9900 支持 leak。

A1 — 书中的应用 (Past Application)

案例 1: 双 AS eBGP 互联实验（216 p510-518）

  • 问题: 4 台交换机分属 AS100/AS200，域内跑 OSPF，域间需互通业务网段。
  • 方法论的使用: IGP 先行（OSPF 建 loopback 可达）→ 声明 AS 与 eBGP 邻居 → ip redist ospf/local into bgp route-map 受控重分发 → 在邻居上挂 route-map 做 in/out 过滤。
  • 结论: 策略与路由生成解耦：路由来自重分发，策略来自 route-map，二者独立演进。
  • 结果: 对端 show ip routes 出现 EBGP 路由，验证通过。

案例 2: 共享服务跨 VRF 泄漏（220 p778-779）

  • 问题: 两个租户 VRF 需要访问共同的 Internet/DNS 出口（在 GRT）。
  • 方法论的使用: 出口侧 ip export route-map R1（match protocol static）只泄漏默认路由；租户侧 ip import vrf + ip route-pref import 100 控制导入与偏好。
  • 结论: Route Leak 是白名单式单向授权，成对配置、route-map 界定范围。
  • 结果: 租户到共享服务通，租户之间仍隔离；本机两 VRF 接口互 ping 不通属预期。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 双出口/双上游选路设计或排障：想知道为什么走了次优出口、怎么把流量切到指定链路。
  2. IBGP 部署中邻居全部 Established 但部分前缀学不到，或下一跳不可达路由无效。
  3. 多租户 VRF 规划：VLAN 归属、共享服务泄漏、或配 VRF 接口报 not allowed。

语言信号 (用户的话里出现这些就应激活)

  • "BGP 选路顺序 / 为什么走这条而不是那条"
  • "local preference / MED / as-path / community / route-map 过滤"
  • "IBGP 学不到路由 / split horizon / next-hop-self"
  • "VRF 隔离 / route leak / 跨 VRF 共享出口 / import export route-map"

与相邻 skill 的区分

  • 与 aos-igp-routing 的区别: OSPF/IS-IS 邻居、区域、重分发进 IGP 的问题走 IGP skill；BGP 属性与对等策略才走本 skill。
  • 与 aos-spb-fabric 的区别: SPB 域内 L3 VPN/VRF 路由由 IS-IS TLV 承载，是 SPB 服务模型；本 skill 处理传统 BGP 对等与手工 VRF leak。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 定位选路判定层级
  2. 让用户在两台设备上 show ip bgp routes <prefix> 对比 LocalPref/AS-Path/MED/下一跳差异，按七级瀑布（LocalPref↑→AS-Path→Origin→MED→Next-Hop→EBGP>IBGP→RID）指出第一分叉点。
  3. 完成标准: 能指名"决策在第 N 级分出胜负"及该级属性当前值。

  4. 判停条件: 若路由根本不存在于 BGP 表，跳到步骤 3 查过滤/水平分割。

  5. 按影响方向选属性

  6. 出向引流改 LocalPref、入向引流改 MED（提醒 MED 只在相邻两 AS 间比较、再通告归零）；批量策略用 community；实现载体统一为 route-map 挂 neighbor in/out。

  7. 完成标准: 给出 ip bgp policy <list> → route-map → ip bgp neighbor <ip> route-map <map> in|out 三层配置片段。

  8. 排查 IBGP 黑洞

  9. 核对拓扑是否 full-mesh/RR；IBGP 学到的路由不传第三个 IBGP 邻居（ce27）；检查下一跳可达性，必要时 ip bgp neighbor <ip> next-hop-self。

  10. 完成标准: 明确指出缺失前缀卡在水平分割还是 next-hop 不可达，并给出对应修复。

  11. VRF 归属与泄漏核查

  12. 确认一个 VLAN/IP 接口只属一个 VRF（首个接口决定归属，ce28）；跨 VRF 配 export route-map + import vrf route-map 成对；告知本机 VRF 接口互 ping 不通是安全设计而非故障；核对机型（6860E/N、6900、9900）。
  13. 完成标准: 给出成对 leak 配置，并说明两端客户端验证方法（ping 对端客户端而非对端 VRF 接口）。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • OSPF/IS-IS 邻居卡态、区域设计、IGP 重分发问题——用 aos-igp-routing。
  • SPB 骨干上的 L3 VPN/VPN Lite 设计——用 aos-spb-fabric（那是 IS-IS TLV 承载的 VRF，不是手工 leak）。

作者在书中警告的失败模式

  • IBGP 水平分割黑洞（ce27）: 部分互联 IBGP 下"邻居全 estab 却缺前缀"；AS_PATH 在 AS 内不增长，防环靠水平分割，解法是 full-mesh 或路由反射器。
  • VLAN/VRF 绑定唯一性（ce28）: 同一 VLAN 横跨两个 VRF 或在另一 VRF 上下文建接口被拒；不同 VRF 复用相同 VLAN 号也不支持——共享必须走 Route Leak。

作者的盲点 / 时代局限

  • 教材实验基于小型双 AS 拓扑，未覆盖大规模 RR 分层与 route dampening；VRF leak 的路由循环风险（双向泄漏）需用户自行用 route-map/tag 防环。

容易混淆的邻近方法论

  • MED vs LocalPref：一个管入向（告知对端）、一个管出向（本 AS 内）；两者方向搞反是最常见错配。
