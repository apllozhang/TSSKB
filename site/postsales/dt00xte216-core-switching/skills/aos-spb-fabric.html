SPB-M 织构构建与设计准则

R — 原文 (Reading)

"Backbone configuration entails: Creating one or more BVLANs with their associated ECT-IDs... Defining the control BVLAN, Defining one or more SPB IS-IS interfaces, Enabling the SPB IS-IS protocol." (p965)

"In short: Only create as many BVLANs as there are equal-cost-paths in the physical topology... duplicate MAC addresses... constantly learned, re-learned and flushed. This is known as a 'mac-move' and should be avoided."

— OmniSwitch LAN R8 Bootcamp Ed23 / SPB Tech Brief §18, p938-940, p1001-1002

I — 方法论骨架 (Interpretation)

SPB 用 IS-IS 算最短路、用 MAC-in-MAC 封装在 BVLAN 里转发，取代 STP 做全活骨干。它的配置天然分两层：

骨干四步法（每节点）：① 建 BVLAN 并关联 ECT-ID（spb bvlan 2000 + spb isis bvlan 2000 ect-id 1）；② 在协议 disabled 时指定 control BVLAN；③ 把互联口设为 SPB IS-IS 接口（自动挂所有 BVLAN，即"网络口"，BVLAN 上无 STP）；④ 全局 enable。铁律：BVLAN/ECT 分配全网一致，且必须先配好再 enable。

L2 服务五步法（只配在 BEB，BCB 零配置）：接入侧建 VLAN → BEB 声明 service access port →（可选 profile）→ service spb <本地号> isid <全局号> bvlan <BVLAN> → 定义 SAP（端口:encap）。service 号仅本地有效，I-SID 与 BVLAN 必须跨 BEB 一致。

三条核心设计准则：BVLAN 数量 = 物理等价路径数（上限 16，多余只增加 SPF 负担和收敛时间，ECT-ID 是树分化的 tie-breaker）；一个 VLAN 一个 I-SID（多 VLAN 映同一 I-SID 会打通 L2 隔离并引发 mac-move 震荡）；L3 选型域内 L3 VPN（复用 IS-IS、单实例收敛快）、边界 VPN Lite（OSPF/BGP 对接外部）。

BUM 复制三选：Head-end（默认，省资源费带宽）、Tandem(S,G)（每 I-SID 一棵树，省带宽费资源）、Tandem(*,G)（每 BVLAN 一棵共享树，折中）。链路 metric 默认一律 10，按速率反比调整且必须两端同改。

Auto-Fabric 七阶段：Auto-VC → RCD 取配置 → Auto-LACP → Auto-Routing → Auto-SPB → Auto-Network Profiling（UNP+LBD）→ Auto-MVRP（仅 SPB 失败兜底）；每阶段"探测-预置-验证-不成立即回退删除"，自动学习配置默认不存 vcboot.cfg。

A1 — 书中的应用 (Past Application)

案例 1: SPB-M 骨干实验（220 p937-941）

  • 问题: 用 SPB 替代 STP 建全活骨干并验证逐 BVLAN 分流。
  • 方法论的使用: 每节点建 3 个 BVLAN 配不同 ECT（2000 兼做控制），协议禁用状态下配 control-bvlan，网络口设 ISIS 接口，最后 enable。
  • 结论: 顺序正确则邻接一次建立；用 show spb isis spf bvlan <id> 对比可见不同 BVLAN 长出不同树。
  • 结果: 骨干全活、流量按服务分担（c38）。

案例 2: 跨站点 L2 VPN 实验（220 p942-949）

  • 问题: 两个站点的 VLAN2/VLAN3 需跨骨干二层互通。
  • 方法论的使用: 接入交换机建 VLAN 并 uplink tagged；BEB 上 service spb 2001 isid 2001 bvlan 2001 + SAP 1/1/3:2，一 VLAN 一服务。
  • 结论: 服务只建在交付点 BEB；MAC 学在 SPB 域（show mac-learning domain spb）而非 BVLAN。
  • 结果: 客户端跨站 ping 通，MAC 出现在 2001:2001 的 sap/sdp 接口上（c39）。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 新建或扩容 SPB 骨干：规划 BVLAN/ECT/I-SID/SAP 编号与负载分担。
  2. SPB 排障：adjacency up 但服务不通、MAC 表持续 mac-move、不同 VLAN 用户竟二层互通。
  3. 园区 L3 设计：域内租户路由选 L3 VPN 还是边界 VPN Lite；或解释"新交换机插上网线端口自己变成 LAG/UNP"（Auto-Fabric 行为）。

语言信号 (用户的话里出现这些就应激活)

  • "SPB 骨干怎么配 / BVLAN 配几个 / ECT / control-bvlan"
  • "I-SID / SAP / service spb / BEB / BCB"
  • "mac-move / MAC 反复学习 / 不同 VLAN 二层通了"
  • "L3 VPN vs VPN Lite / Auto-Fabric / 端口自动变 LAG"

与相邻 skill 的区分

  • 与 aos-lag-stp 的区别: 传统 STP/MSTP/LAG 冗余设计走 L2 skill；SPB 骨干（IS-IS+BVLAN，无 STP）走本 skill。
  • 与 aos-bgp-vrf 的区别: 手工 BGP 对等与 VRF route leak 走 BGP skill；SPB 域内 VRF 路由由 IS-IS TLV 承载，属本 skill 的 L3 VPN。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 骨干搭建（或核查顺序）
  2. 按四步法输出配置：BVLAN+ECT → 协议 disabled 下配 control-bvlan → ISIS 接口 → enable；强调 BVLAN/ECT/I-SID 全网一致且先配后 enable（ce29）。
  3. 完成标准: 配置序列完整且顺序正确；验证链 show spb isis adjacency → nodes → bvlans → unicast-table → spf 可逐级执行。

  4. 判停条件: 若仅为排障，跳到步骤 3。

  5. BVLAN/I-SID 设计决策

  6. 问清物理等价路径数，BVLAN 数取等（≤16）；每 BVLAN 不同 ECT；坚持一 VLAN 一 I-SID/SAP（ce30）；L3 域内 L3 VPN、边界 VPN Lite（p983）；大流量组播按 Table 1 选 BUM 模式。

  7. 完成标准: 给出 BVLAN/ECT/I-SID/SAP 分配表及 BUM 与 metric（两端同改）建议。

  8. 服务不通排障

  9. 先查一致性（各 BEB 的 I-SID/BVLAN 是否一致、SAP encap 是否匹配、是否先 enable 后改配置——ce29）；再查 MAC 层面（show mac-learning domain spb、mac-move 告警是否指向多 VLAN 映同一 I-SID——ce30）。
  10. 完成标准: 定位到不一致项或设计反例并给出修正。

  11. 判停条件: 若是"端口自动变化"类疑问，跳步骤 4。

  12. Auto-Fabric 行为解释/管控

  13. 用七阶段流水线解释现象（Auto-LACP 单链也建组、Auto-SPB 成功后余口转 UNP、MVRP 仅兜底）；给出 show auto-fabric config 与逐项 auto-fabric protocols ... disable、auto-fabric config-save admin-state enable。
  14. 完成标准: 能把现场现象映射到具体阶段并给出保留/关闭命令。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 未部署 SPB 的传统网络：STP 收敛、LACP 选型、双上行走 DHL 还是 LAG——用 aos-lag-stp。
  • 与外部 AS 的 BGP 互联、手工 VRF route leak——用 aos-bgp-vrf。

作者在书中警告的失败模式

  • 顺序陷阱（ce29）: 先 enable ISIS-SPB 再改 SPBM/BVLAN 配置，邻接在错误拓扑上计算；各节点 BVLAN/ECT 或 I-SID 不一致导致服务单通——"adjacency up 但服务不通"。
  • BVLAN 滥配与 mac-move（ce30）: 配满 16 个 BVLAN 无收益反增 CP 负担；多 VLAN 映同一 I-SID 打通隔离并触发持续 mac-move（虚拟化环境尤甚）。
  • 硬边界（ce31）: 控制 BVLAN 接口不支持 OSPF/VRRP/ARP（IP-MAC 由 IS-IS TLV 解析）；L3 VPN 不能与外部 MPLS 直接互通（需边界 VPN Lite）；双向重分发不加 route-map 会成环；VLAN translation 必须 service 与 SAP 两级同时启用。

作者的盲点 / 时代局限

  • 教材以中小园区拓扑为准，未深入超大规模分层 SPB 与多域互联；Auto-Fabric 默认值随版本演进（8.7R1 起 Auto-SPB 默认 4 个 BVLAN），现场需 show 核对实际版本行为。

容易混淆的邻近方法论

  • SPB L3 VPN vs 传统 VRF：前者路由由 IS-IS TLV 按 I-SID 自动承载、免配路由协议；后者每实例独立协议/leak。
  • LBD vs STP：LBD 检到环直接关物理口需人工恢复，不做阻塞-转发状态机。

相关 skills

  • depends-on（依赖：先学/先配前者）:
  • aos-igp-routing：SPB 控制面就是 IS-IS——不懂 IS-IS 无法排障 Fabric
  • contrasts-with（对比：易混淆/二选一）:
  • aos-vlan-mvrp：Fabric 用 BVLAN+ISID 自动承载业务 vs 逐跳 VLAN+MVRP 手工传播
  • aos-lag-stp：SPB 等价多路径全互联 vs STP 阻塞冗余端口
  • aos-multicast：SPB 用 IS-IS 信令做组播复制（无需 PIM/IGMP-snooping 全网部署）vs 传统 PIM 组网
  • composes-with（组合：实际组网搭配使用）:
  • aos-lag-stp：Fabric 链路用 LAG 聚合——SPB over LAG 是标准组合
  • aos-virtual-chassis：VC 节点可作为 Fabric 成员
