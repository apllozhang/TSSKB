aos-lag-stp

SKILL 来源页码: 220 p223-305 (LAG/STP/MSTP), p377-388 (DHL), p820-833 (ERP)

L2 冗余三角：LAG (LACP) / STP / MSTP / DHL / ERP

R — 原文 (Reading)

"By default, the bridge priority is 32768. Since all priorities are identical by default, the switch with the lowest MAC address is selected as the root bridge." (220 p263) "Only one session per switch is allowed... Spanning Tree is automatically disabled on DHL ports." (220 p380-381)

— ALE Training, OmniSwitch LAN R8 Bootcamp Ed23, p263 / p377-388

I — 方法论骨架 (Interpretation)

接入-核心二层冗余的统一选型框架——按四个维度比方案：链路冗余 / 带宽利用率 / 收敛时间 / 交换机冗余。

  1. LAG（带宽叠加）: 选型两问——对端是否 ALE 交换机且参数两端完全一致？是 → 静态（OmniChannel）；跨厂商（服务器/存储/它牌交换机）→ 动态 LACP（802.3ad，LACPDU 协商，端口靠 actor admin-key 关联聚合组，key 仅本地意义）。建 agg 预留 size 便于扩容；VLAN 挂 linkagg 而非物理口。哈希：brief（仅 src/dst IP）vs extended（加 UDP/TCP 口）；机型默认不同（6900/6465/6360=brief，9900/6860 等=extended）；组播默认走主端口，需 hash-control load-balance non-ucast。
  2. STP/MSTP（防环+冗余）: 默认 per-VLAN(1x1) RSTP、priority 32768、全默认则最低 MAC 当根——必须手工调 priority 定根（如 spantree vlan 20 priority 20000）；1x1 模式可按 VLAN 把根放到不同核心做负载分担。MSTP 七步：spantree mode flat → protocol mstp → region(name+revision) → 建 MSTI → VLAN→MSTI 映射（未映射落 CIST）→ 按 MSTI 设 priority（根分散=分担）→ show 验证；region 三要素必须全网一致；priority 须 4096 倍数。边缘保护三招：restricted-role / restricted-tcn / qos user-port filter|shutdown bpdu。
  3. DHL（免 STP 的 active-active 双归属）: 每机 1 session、仅 linkA/linkB 两条（端口或 linkagg）、必须同一 default VLAN、mobile/802.1x/GVRP/UNI 口不支持、DHL 口自动关 STP。五步：建 session → 绑 A/B → vlan-map linkb N（其余归 A）→ enable → 选 MAC 冲刷（raw / MVRP enhanced / none 默认有黑洞风险）。恢复侧 pre-emption 默认 30s 防抖。
  4. ERP（环网 G.8032）: 全环唯一 RPL，Owner 侧常态阻塞；建环四要素（唯一 ring ID + 两环口 + Service VLAN + MEG level）；WTR 默认 5 分钟；建议每环 ≤16 节点；收敛 ~50ms。

选型结论: 双上行双核心不想跑 STP → DHL；环网 → ERP；对端跨厂商带宽叠加 → LACP；与第三方 MST 域互通 → MSTP。

A1 — 书中的应用 (Past Application)

案例 1: LACP 互联标准化开局 (220 p226-233, c09/c44)

  • 问题: 两核心间带宽扩展且要跨厂商兼容。
  • 方法论的使用: linkagg lacp agg 17 size 2 actor admin-key 17 → linkagg lacp port 1/1/5 actor admin-key 17 → 激活物理口 → vlan 217 members linkagg 17 untagged + IP 接口 → ping 验证。
  • 结论: VLAN 与路由一律挂逻辑 linkagg，扩容零改动。
  • 结果: show linkagg agg 17 port 全 ATTACHED/UP，216 实验 (p309-315) 作为 OSPF 前置模板复用。

案例 2: MSTP 双核心负载分担 (220 p296-303, c11)

  • 问题: 双上行链路想全活且与第三方 MST 互通。
  • 方法论的使用: 两台同 region name/revision；MSTI1 映射 VLAN1-15、MSTI2 映射 VLAN16-20；A 的 cist/msti1/msti2 priority = 4096/4096/8192，B 互换——不同实例的根落在不同交换机。
  • 结论: show spantree mst port 1/1/2 显示 MST1 ROOT FORW / MST2 ALT BLK，两链路分载。
  • 结果: 教材验证分担成立，region 一致性是前提。

案例 3: DHL active-active (220 p385-387, c14)

  • 问题: 汇聚-接入双归属、无 VC/LACP、不想 STP 阻塞。
  • 方法论的使用: dhl 1 → linka port 1/1/3 linkb port 1/1/4 → vlan-map linkb 30 → admin-state enable → mac-flushing raw。
  • 结论: 按 VLAN 分流到 A/B，故障时另一条接管，无 TCN 故需显式 MAC 冲刷。
  • 结果: 教材给出 raw/mvrp/none 三选项及默认 none 的黑洞警告。

A2 — 触发场景 (Future Trigger) ★

用户会在什么情境下需要这个 skill?

  1. 接入交换机双上行/双核心，纠结 STP 阻塞、LACP、DHL 选型。
  2. STP 排障：根桥漂移到接入层老设备、TCN 风暴、未知环路。
  3. LAG 问题：端口加不进 linkagg、Att/Sel 不一致、流量不均、组播打满单链路。
  4. MSTP 区域规划或与第三方 MST 域互通；环网（ERP/G.8032）保护设计。

语言信号 (用户的话里出现这些就应激活)

  • "双上行该用 STP 还是 DHL 还是 LACP"
  • "root bridge 漂移 / 根桥不对 / restricted-role"
  • "linkagg / LACP / admin-key / 端口加不进聚合"
  • "MSTP region / MSTI / 负载分担"
  • "DHL / dual-home / mac-flushing"
  • "环网 / ERP / RPL / G.8032"

与相邻 skill 的区分

  • 与 aos-virtual-chassis 的区别: VC 是把多台变一台（管理面/转发面合一）；本 skill 是独立设备间的链路级冗余。VC+LAG 组合方案两边都提，但 VC 机制归那边。
  • 与 aos-vlan-mvrp 的区别: DHL vlan-map 决定哪些 VLAN 走哪条链路，但 VLAN/trunk 本身的配置语义归那边。
  • 与 aos-spb-fabric 的区别: SPB 用 IS-IS 织构替代 STP 建全活骨干——用户若问"替代 STP 的新架构"应转那边；本 skill 只覆盖传统 STP/LAG/DHL/ERP 体系。

E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

  1. 需求四问定方案: 链路冗余？带宽利用率？收敛时间？交换机冗余？
  2. 完成标准: 明确给出 STP/LACP/DHL(/ERP) 的对比结论并说明理由。
  3. LAG 路径: 选静态（ALE 间）或 LACP（跨厂商）→ 建 agg（size 预留）→ 端口挂 admin-key → 清除端口残留 VLAN 配置再加入 → VLAN 挂 linkagg → show linkagg 验证 ATTACHED/UP
  4. 完成标准: 验证通过；流量不均时按机型核对 brief/extended 默认并给出 hash-control 调整。
  5. 判停条件: 报 "Port cannot be added to Linkagg" → 先 no vlan X members port 清残留（ce09）。
  6. STP/MSTP 路径: 核对 mode（flat/1x1）→ 定根（priority 低于全网）→ 1x1 按 VLAN 分根或 MSTP 七步 → 边缘口上保护三招 → show spantree（Bridge ID==Designated Root 即本机为根；Topology Age/Changes 判稳定；blocking 只剩链路一端）
  7. 完成标准: 根位置符合设计且 blocking 落点可解释。
  8. 判停条件: 配 MSTP 时若在 1x1 模式，先 spantree mode flat。
  9. DHL 路径: 核对硬限制（1 session/2 链路/同 default VLAN/端口类型）→ 五步配置 → 显式选 MAC 冲刷方式
  10. 完成标准: 说明默认 none 的黑洞风险与 pre-emption 30s 的回切延迟。
  11. ERP 路径: 建环四要素 → 全环恰一个 RPL owner → WTR/guard 计时器 → show erp 看 idle/protection/pending
  12. 完成标准: RPL 唯一性确认（无/多 RPL 均为错误配置）。

B — 边界 (Boundary) ★

不要在以下情况使用此 skill

  • 多台合一的管理面冗余（选举/ISSU/脑裂）——用 aos-virtual-chassis。
  • VLAN/trunk/动态 VLAN 规划——用 aos-vlan-mvrp。
  • 网关冗余 VRRP、路由协议收敛——教材属高可用章节但归路由/运维主题。
  • 想彻底摆脱 STP 的大规模全活骨干——用 aos-spb-fabric（SPB 才是 ALE 的"正确答案"）。

作者在书中警告的失败模式

  • ce08: 静态 LAG 只能 ALE 之间且参数两端完全一致；对接第三方必须 LACP，否则乱序/丢包/单通。
  • ce09: 端口残留 VLAN untagged 等配置时加不进 linkagg——售后最高频报错之一。
  • ce10: 1x1 与 MSTP 不能同时配；MSTP 须 flat 模式且用 32-bit path cost，与 802.1d/w 的 16-bit 差 65536 倍，排障勿混。
  • ce11: 不受控 STP 网络 → 错误根桥/隐性环路/广播风暴；全默认时最低 MAC 当根，接入层老设备可能抢根；用户口需 restricted-role/restricted-tcn/BPDU 过滤。
  • ce14: DHL 每机 1 session、每 session 2 链路、禁 mobile/802.1x/GVRP/UNI 口；STP 被自动关 → 切换无 TCN，MAC 冲刷选 None（默认）则流量黑洞直到老化；pre-emption 窗口内不回切易被误判故障。
  • ce26: ERP 环 RPL 必须恰好一个且只能在已停用的环上配；无 RPL 成环风暴、多 RPL 错切流量。

作者的盲点 / 时代局限

  • 教材把 SPB 定位为 STP 的替代答案，本 skill 的三角选型只覆盖传统网络；跨 skill 需要引用 SPB 对比时不应展开。
  • DHL/ERP 的收敛数据为教材标称值（~50ms），未给实测方法。

容易混淆的邻近方法论

  • LACP（链路聚合，防"链路"故障）vs DHL（双归属，防"交换机"故障）vs VC（设备合一）——层次不同可叠加。
  • STP restricted-role（Root Guard）与 BPDU 过滤（qos user-port shutdown bpdu）——前者限角色，后者直接关口。
