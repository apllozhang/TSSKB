精华长文 DIGEST

SPB 售前精华 · 不读全书只看这一篇

目标读者：要见客户、要写方案、要投标答辩的售前工程师。以下内容从 DT00XPS279EN（147 页）蒸馏而来，数字均带页码，可直接引用；引用前记得按最新 AOS 规格书复核（教材 p75 自带免责声明）。

一、一页看懂 SPB

这是什么：SPB（最短路径桥接，IEEE 802.1aq）是一套用 IS-IS 做控制面、用 Mac-in-Mac（802.1ah）做数据面的以太网织物技术。每台交换机自为根，IS-IS 算出对称同构的最短路径树，所有链路同时转发且无环（p23）。

为什么卖：ALE 官方定位是"瑞士军刀"——一套技术同时解决四件事：替换 STP、多租户、微分段、IoT 接入，横跨园区/DC/WAN，用一个方案替掉多技术栈的管理复杂度（p7）。配套卖点还有三条：核心只认 BMAC 不认 IP、不学客户 MAC，天然免疫 IP 扫描/DOS/中间人（p9）；与 802.1Q/QinQ/OSPF/BGP/PIM 互操作，投资保护、分阶段迁移、无需整机更换（p10）；单协议 IS-IS 同时管 L2+L3、IPv4+IPv6，配置只发生在边缘、核心零触碰（p3）。

一句话价值主张："把全网一半被 STP 阻塞的链路解放出来，把逐跳配置变成边缘一次配好，把多套织物技术收敛成一套——规模在 1000 节点以内，收敛约 100ms，不收许可费。"（p23/p25/p75/p22）

二、售前攻防十问

Q1 客户问"STP 用得好好的，凭什么换？" 用 p23 的十维对比页：STP 单树绕根桥、F 到 G 明明相邻却要五跳、一半链路被阻塞浪费、逐跳配置、收敛以秒计； SPB 每台自为根、IS-IS 控最短路径、全链路利用、边缘配置、快速恢复。收尾锚一句可背常数：1000 节点内全链路无阻塞、亚秒级收敛（p1-17/p25）。注意话术精确化：说"核心骨干消除阻塞链路"，别承诺"全网灭 STP"——教材自己的参考设计里接入层上行仍用 STP 或 DHL（p32）。

Q2 客户问"新协议安不安全？" 非 IP 转发论证（p9）：骨干只处理 BMAC，不解析客户 IP 与 MAC，逐项排除 IP 扫描、DOS、中间人。再补一句地址隔离：核心不学客户 MAC，客户侧拓扑对骨干不可见。微分段需求接认证→分类→供给三步流水线讲（p11/p56）。

Q3 客户或标书要求对比 EVPN/MPLS？ 直接掏 p134 七维对比表做一页纸：SPB 在部署难度、培训需求、协议开销（仅 IS-IS）、排障速度四维占优； 扩展性与弹性承认 EVPN/MPLS 更强。行业矩阵（p138）：园区/视频监控/智能交通选 SPB，大型 DC 选 EVPN，铁路电力等毫秒收敛刚需选 IP-MPLS（MPLS 50ms vs SPB 100ms，p136）。客户指定 EVPN 时不硬顶——三技术同一 AOS 全支持，无厂商锁定。

Q4 "SPB 能跑三层吗？" 能，而且是"消灭独立路由层"的论证：BEB 同时当桥和路由器（p78-98）。选型两步走：物理形态三选一（Outline 物理环回线 / 前面板口 inline / service-based 单遍 inline，p82/p92/p95），路由机制两档（VPN-Lite 简版跑静态/OSPF，L3 VPN 全版 IS-IS TLV 传路由，p85）。书中 p84-97 有四套完整 AOS 配置样例可转方案书章节。

Q5 "现网割接，业务会不会断？" 双域并行框架（p13）：SPB 域与 Legacy 域长期共存，按业务分批搬迁（IoT 流量先行），每步可回退。施工细则看 Metz 案例（p120-124）：核心先 SPB 化、遗留环 STP 自治、交界 BEB 双 STP 实例受控桥接、专门建点对点 SPB 服务传 STP 控制帧。结果页写明"迁移期零业务中断"（p124）。

Q6 "规模上限多少？" 设计规模 1000 节点（p1）。细分上限按机型查 p75 表：BVLAN 全系 16 个（推荐只规划 4 个）、IS-IS 邻接 70 或 128 按机型、I-SID 1K-8K、SAP 2K-8K。注意 OS9900 的 I-SID 反而只有 1K——高端不等于每项都高。

Q7 "要买 License 吗？" 不要。AOS 上 SPB 免许可，OS6860E/6860N/6870/6865/6900/9900 全系支持（p22）。报价页可直接写零软件授权成本。

Q8 "有成功案例吗？" 三个案例按客户行业选用（p114-125）：教育选 Linköping 大学（spine-leaf 改造，"配置管理极其简单"高管证言）； 交通选美国 NDOT（路边网络 SPB 到边缘，NOC+光纤环+加固型三层架构）； 政务/智慧城市选法国 Metz（80 栋楼、100km 光纤、200 台交换机，STP→SPB 零中断迁移，叙事最完整）。引用规模数字只用书中量化值，Linköping 无数字，勿自行补。

Q9 "网络怎么管？" OmniVista 2500 图形化全流程（p99-113）：服务创建向导、L2 Profile、SPB Profile 模板（Tag/I-SID/BVLAN/组播模式一次定义多处套用）、拓扑视图含 LACP 明细。配置分两层工单：Core level（NNI 骨干，一次配好基本不动）与 Access level（UNI 服务，日常增删只在边缘）——与 edge-only 论证互为印证（p73）。

Q10 "OV2500 和 SPB 怎么配合交付？" 演示路径（p100-112）：Global Settings 选设备 → 服务创建（Basic 选设备 → 可选 UNP Profiling → 按需 Advanced）→ 拓扑视图看 SAP/SDP/LACP 状态收尾。I-SID 有效范围 256-16777214，避开 0-255 保留段（p109）。注意 OV2500 章只是 GUI 导览，排障深度归售后课，别拿它承诺排障能力。

四、三个可复用论证框架

框架一：STP 十维对比 + F-to-G 反例（f07/p23） 开场逻辑：先立反派再立英雄。左栏列 STP 九条罪（单树绕根、相邻节点五跳、阻塞浪费带宽、逐跳配置、链路利用率低、无最短路径、广播低效、扩展性差、收敛慢），右栏 SPB 逐条映射。F-to-G 五跳反例是全场最有画面感的弹药——两台交换机并排放着，流量却要绕根桥五跳，客户一听就懂。收尾必落常数：1000 节点/全链路利用/亚秒收敛。适用于开场与"凭什么换"答辩。

框架二：互操作三承诺 + 双域并行迁移链（f03/f06/p10/p13） 回应预算质疑的完整论证链："能共存"（L2/L3/组播协议全清单互操作）→"可分批"（SPB 域与 Legacy 域长期共存，IoT 流量先行）→"可回退"（每步可退）→"不换机"（无需整机更换）。四环扣死，CIO 的割接风险与投资作废两大顾虑一次拆完。落地证据用 Metz 五步施工法（p123）。

框架三：技术中立防御 + 七维对比拉回主场（f19/f20/p134/p138） 当客户被竞品带向 EVPN/MPLS：第一步不硬顶，承认三技术各有主场（ALE 同一 AOS 全支持，OmniFabric，无锁定）； 第二步掏七维对比表，SPB 占优的四维（部署/培训/开销/排障）重点标注； 第三步用行业矩阵给客户对号入座——园区/城域/IoT 行天然落回 SPB 主场； 第四步如实写让位场景（超大 DC→EVPN、毫秒收敛→MPLS），反而建立技术诚信。这张表可直接做投标"技术选型"单页。

六、边界与诚实话术（技术诚信底线）

  • 规模超 1000 节点或超大型 DC，主动让位 EVPN。 scalability 一票否决的场景硬应标是给交付埋雷；同一 AOS 双支持，切叙事不换厂商（ce06）。
  • 轨交/电力等毫秒级收敛刚需，主动报 IP-MPLS。SPB 100ms 拼不过 MPLS 50ms；正确话术是把 SPB 定位为"对比 STP 秒级的代代提升"（ce13）。
  • "替换 STP"精确到"骨干消除阻塞链路"。接入层与遗留域仍可能保留 STP/DHL，Metz 迁移期还专门传 STP 控制；承诺"全网灭 STP"会在验收时被打脸（ce14）。
  • BVLAN 别当业务维度用。全网仅 16 个、推荐 4 个；业务扩展全部走 I-SID。给每类业务独立 BVLAN 的方案落不了地（ce05）。
  • 视频类业务必须显式配 Tandem 组播。Head-End 是默认，接收者多时带宽随节点数线性放大，直接打爆骨干；且不开 IGMP snooping 时 IP 组播洪泛所有 SAP/SDP（ce04）。
  • SAP 口边缘特性受限。port-QoS/DHCP Snooping/STP 支持 Limited，L3 设计首选 VLAN UNI（ce01）。
  • 一切规格数字投标前复核最新 AOS 规格书。教材是 2025-02 Issue 05 快照（AOS R8 时代），多处标 8.10 R3/R4 起；p139 的 P/O 图例书中未定义，引用需核实（ce16）。

诚信话术的底层逻辑：让位场景如实讲，反而把 SPB 主场（园区/城域/IoT、1000 节点内、STP 改造）衬托得更可信。
