R（何时使用）

  • 远端建筑/园区无法布线，要在 bridge（纯 LAN 延伸）与 mesh（多节点 + WLAN 覆盖）之间做选型
  • 设计 mesh 集群拓扑：
    root 网关位置、是否双 root 冗余
  • 需要向客户解释 mesh 吞吐为什么每跳减半、backhaul 与客户端业务如何共享带宽
  • 评估 Auto-Mesh 快速开局、WDS 透明桥接对 VLAN 传输的支持

I（核心理念）

Stellar mesh 是"无线 AP 组成的路由器集群"，所有流量经 root 角色的 AP 网关进出有线 LAN（P5-6，原文p5 ）。

Bridge 与 mesh 是两种互斥的配置形态，不能组合（P11，原文p11 ）： - Bridge：单链路 Point-to-Point，只延伸企业 LAN，不广播 SSID，企业内最常用（P6，原文p6 ） - Multi-Point mesh：面向无法布线区域的多节点覆盖，root 和每个 mesh AP 都可广播 WLAN 服务（P6/P10，原文p10 ）

带宽是核心约束：mesh 链路带宽由 backhaul 与无线客户端共享；Multi-Point 模式下每个 mesh 节点同频同射频收发，需回传的数据吞吐逐跳除以 2（P7，原文p7 ）。

WDS 模式用 4 地址帧实现 AP 间透明以太桥接，统一广播域、可承载多个企业 VLAN（P7，原文p7 ）。

A1（决策要点）

  1. 形态选型（P6，原文p6 ）：只延长 LAN 到一个远端站点 → Bridge；多节点区域需要 Wi-Fi 覆盖 + 有线下联 → Multi-Point mesh
  2. 角色规划（P5-6，原文p5 ）：root 角色 = LAN 网关（接有线），mesh 角色 = 无线节点；数据流量全部经 root 转发
  3. root 冗余（P6，原文p6 ）：同一 AP group 可配两个 root，mesh AP 自动选 RSSI 最好的 root 连接——bridge 与 mesh 的 root 都支持双 root
  4. 频段规划（P7，原文p7 ）：双频/三频 Wi-Fi 6 AP 上 backhaul 可配在 5GHz 或 2.4GHz，5GHz 首选；WLAN 服务可在双频同时下发
  5. 开局方式（P7，原文p7 ）：Auto-Mesh——root 连 LAN 激活后，邻居空配置 AP 自动用默认 mesh 链路接入，无需预配置
  6. 管理面（P5，原文p5 ）：mesh 集群既可 Enterprise 模式（OmniVista 2500/Cirrus）统一管理 AP group、RF、VLAN、SSID、QoS、远端端口，也可 Express 模式（家庭场景）

E（场景案例）

  • 两栋楼隔街相望、无法跨公共道路布线：
    Bridge 单链路延伸整个企业 LAN，ENET1 口直接给远端 IP 摄像头供电（P6/P8，原文p8 ）
  • 工厂仓库部分区域布线不可达：
    Multi-Point mesh，root 接有线，各 mesh AP 同时提供 Wi-Fi 覆盖与有线下联口（P6，原文p6 ）
  • 临时活动场地快速开通：
    Auto-Mesh 只需激活 root，周边 AP 上电即自动入网（P7，原文p7 ）
  • LAN 设备经 WDS AP 访问远端桥接设备：
    802.3 帧经 4 地址 802.11 帧中继，两端在 802.3 层建立连接（P7，原文p7 ）

B（限制与坑）

  • Bridge 与 mesh 拓扑不能组合使用，规划时必须二选一（P11，原文p11 ）
  • Bridge 模式不对远端 Wi-Fi 客户端广播 WLAN 服务——需要远端无线上网就选 mesh（P6/P8，原文p8 ）
  • Multi-Point 模式吞吐逐跳 ÷2，多跳链路末端速率会快速衰减，级联深度要克制（P7，原文p7 ）
  • mesh 基础设施一旦定义即固定，不能当动态自组网用（P5，原文p5 ）
  • AP 间距直接影响共享带宽，室内感觉不到的衰减在室外会被距离放大（P7，原文p7 ）
