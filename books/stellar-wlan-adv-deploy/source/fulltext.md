Discover the Remote Lab Topology 
In this part, you will find an explanation about the Remote Lab topology that you are going to use during this 
training.  
2.1. 
Topology of the Stellan Remote Lab Pod 
 
 
This topology contains: clients, Stellar Access points, OmniSwitches, servers and an OmniVista Cirrus. 
It simulates a three-tier end user topology (Access, Aggregation and Core), as well as the clients, servers and 
internet connection to your OmniVista Cirrus. 
2.2. 
Stellar Access Points 
You will manage and configure the Stellar Access Points AP1301 and AP1321 through the OmniVista Cirrus. 
You will configure the network, so they can communicate with the DHCP server and send traffic to the 
OmniVista Cirrus through the internet link. 
2.3. 
Access Layer and Clients 
 
You will manage and configure the wired (Client 05) and wireless client (Raspberry Pi “Wifi client”). 
You will manage and configure both Access OmniSwitches (OS-6360 and OS-2360). 
All the traffic will be switched (L2 switching) at this level. And DHCP, DNS, HTTP,… requests will be 
forwarded to the aggregation switch, then to the servers in our core network.

2.4. 
Aggregation Layer

QoE Analytics 
 
Monitoring QoE analytics allows you to evaluate the actual end-user experience on the network. 
 
OmniVista Cirrus provides six metrics to be monitored:  
- Successful Connects 
- Time To Connect 
- Roaming 
- Coverage 
- Available Capacity 
- Device Uptime. 
 
- Go to Network > Analytics > QoE to open the QoE Analytics dashboard. 
- Make sure that the Site that was created previously which includes all managed devices is selected at the 
top right side of the screen.  
- Scroll down to see all different QoE metrics 
- Look for the Configure Thresholds button to modify the thresholds for some metrics. (Explained below). 
 
 
Successful Connects 
Indicates the number of connections that succeeded in passing all the Authorization, Association, DHCP, and 
Portal phases when a client connects to an Access Point. 
There is no threshold value applied to this QoE metric, as it is just a counter that increases over time. 
 
 
Time To Connect 
Represents the sum of the times you need to pass each connection phases successfully. 
There are four phases of connection: Association, Authorization, DHCP, and Portal Authorization. If the total 
time to connect takes longer than the selected threshold, the connection will be considered as a failure (failure 
to reach the goal). In this case, the phase that took longer than usual will be designated as the cause of the 
failure. 
The threshold can be configured from 2s to 20s. The default threshold value is 2s. 
 
 
 
 
Roaming 
Represents the percentage of successful roams between two Access Points for clients within the defined 
threshold. 
The threshold (which is the max target time it takes for a client to roam) can be configured from 0.2s to 2s. 
The default threshold value is 0.2s. 
 
 
 
 
Coverage 
Represents the percentage of time where the client signal is above the defined threshold.  
When the client signal doesn’t reach the configured threshold value, the failure is classified among the list of 
classifiers: Asymmetry Downlink, Asymmetry Uplink, Weak Signal, or Others. 
The threshold can be configured from -90 dBm to -55 dBm. The default threshold value is -66 dBm. 
 
 
 
 
Available Capacity 
Tracks the percentage of time the available RF channel capacity was greater than the defined threshold. 
The threshold can be configured from 10% to 50%. The default threshold value is 10%. 
 
 
 
 
Device Uptime 
Displays the percentage of average uptime for all Devices within the defined scope.

3.1. 
Topology application - Map 
 
- Under the MONITOR category, go to Network > Topology. 
- Here is what your topology should look like: 
 
- You can find the following icons: 
- 
 Cloud: Your network devices are connected to the device (router, firewall,…) behind this cloud. 
- 
 OmniSwitch: You will find your two OmniSwitchs (OS6870 and OS6360) in the topology. 
- 
 Stellar Access Point: You will find your two Access points (1321 and 1301) in the topology. 
- 
 Unmanaged Network devices: All the network devices not declared but detected in the network. In 
our case these can be OmniSwitch part of the network infrastructure, wired VMs, or other access 
points. 
- To find the name of your equipment, click on the filter icon 
, and activate the "equipment name" 
field. 
 
3.1.1. 
Device Status 
 
The status of a device is indicated by the following color coding of the small circle in the upper-right corner 
of the device icon: 
 
 
- Green - Device connectivity is up and there are no trap notifications. 
- Orange - Device connectivity is unknown or warning/major trap notifications received from the device. 
- Red - Device connectivity is up with critical trap notifications received. 
- Blue - Device connectivity is up with minor or normal trap notifications. 
- No Circle - No management connectivity information or trap notifications received from the device. 
- Solid-Grey Device Icon - Device connectivity is down with no trap notifications.
