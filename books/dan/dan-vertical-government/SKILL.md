## R（何时用）
- 面向政府机构、市政、智慧城市项目方的 DAN 方案宣讲
- 政务痛点：各委办局竖井式重复建设、公共安全摄像头等海量 IoT 接入、网络攻击风险、灾害危机通信
- 查 ALE 智慧城市参考架构（水平共享基础设施 + 服务层）的分层描述

## I（核心理念）
政府 DAN 把"市民体验"放在核心：安全响应的公共服务、更快的应急响应、无处不在的无线连接（<<<PAGE 3>>>）。

**关键论点：智慧城市必须打破组织竖井**——每个垂直应用各建一套基础设施/中间件/应用的竖井架构会推高复杂度与成本；信息要共享、预算要跨部门归集。ALE 参考架构用 DAN 的水平架构提供公共基础设施与服务层，供各用例与应用复用（<<<PAGE 3>>>）。

三支柱在政府语境（<<<PAGE 2>>>）：
- **Autonomous Network**：安全网络的自动开通，连接市民与服务、支撑智慧城市、降低成本与风险
- **IoT onboarding**：IoT containment 简化政府 IoT 组网、提升效率与安全
- **Business Innovation**：降低网络攻击发生与风险、用工作流优先保障危机关键通信与资源、减少维护停机

## A1（选型/决策要点）
1. 项目是"多委办局共建"还是"单部门独建"→ 共建场景主推水平参考架构，共享基础设施与服务层降本（<<<PAGE 3>>>）
2. 智慧城市组网分层规划：接入（Ethernet / Municipal Wi-Fi / Broadband / Bluetooth / Cellular / WPAN / LPWAN / SCADA / IoT 网关）→ 服务层（Analytics / Control / Location / Communications / Management / Security / 数据仓库 / 数据代理）→ 用例（停车 / 交通 / 视频监控 / 垃圾管理 / 照明）（<<<PAGE 4>>>）
3. 底座选型：OmniSwitch LAN + OmniAccess Stellar WLAN，超快收敛、安全接入控制、保证 QoS；单一 NMS 统一管理（<<<PAGE 3>>>）
4. 政府 IoT（传感器、摄像头、遥测）走 containment 三步法 + 29+ million 设备库（<<<PAGE 4>>>）
5. 安全运营：ML 学习 IoT 设备正常行为/用户流量模式/访问权限，发现异常即由 Rainbow 工作流自动处置（<<<PAGE 6>>>）
6. 危机管理（气象/自然灾害/人为事件）：保障一线响应人员通信优先，可定向保住特定监控摄像头直播流等关键资源（<<<PAGE 6>>>）
7. 资产与人员：Asset Tracking 定位防丢 + 占用管理 + contact tracing（<<<PAGE 5>>>）

## E（适用场景案例）
- 多部门共建智慧城市（公共设施、教育、医疗、安保共享一张网）→ 水平架构统一承载停车/照明/垃圾管理/视频监控等用例（<<<PAGE 3>>>/<<<PAGE 4>>>）
- 公共安全视频监控网：CCTV 等 IoT 安全容器化上线 + 持续行为监控（<<<PAGE 4>>>）
- 台风/地震等灾害应急：优先保障 first responders 通信与指定摄像头资源（<<<PAGE 6>>>）
- 政府设施资产管理：设备实时定位、占用密度管控、暴露接触追溯（<<<PAGE 5>>>）

## B（限制与注意事项）
- 彩页提到"Government certified solutions"为总览页营销口径，具体认证（等保/密码等中国合规）需另行核实，不可直接承诺
- 智慧城市分层图为概念架构，具体 LPWAN/SCADA 制式的支持方式需查产品线资料
- 跨部门预算归集涉及行政协调，非技术方案可单独解决，售前应提前管理预期
