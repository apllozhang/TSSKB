# L2/L3 业务开通（VNI / IRB / DAG / RD-RT / 路由类型总表）

## R · 原文引用

> `-> service access port 1/1/7 evpn-ethernet-segment enable`
> `-> service 100 vxlan vnid 1000 bgp-evpn enable`
> `-> service 100 sap port 1/1/7:10`（p67/p69；p71 "Configure the same on remote PE (VTEP)"）

> Since we will be using asymmetric IRB..., it is required to have all the services instantiated in all the switches and to have an operational physical or logical port provisioned for all services.（p105；p109 "Currently, host based Asymmetric IRB model is supported in AOS"）

> All hosts will have .254 as a default gateway... ip anycast-gateway-mac auto... a virtual MAC is (autogenerated) 00:00:5E:00:01:XX（p99）

> Route Distinguisher: RD= <System IP>:<EVI>; Route Target: RT= target:<AS number>:<EVI>（p148）

## I · 方法论骨架

1. **L2 业务三部曲**：①物理口声明 service access port + `evpn-ethernet-segment enable`（自动 ESI、单归属）；②`service <id> vxlan vnid <vni> bgp-evpn enable` 建虚拟桥；③`service <id> sap port <端口>:<VLAN>` 挂 SAP（冒号后 VLAN 即 ETag）。对端 Leaf 重复同样三条。映射惯例：service 100 ↔ EVI/VNI 1000 ↔ ETag 10。
2. **IRB 选型决策表**（p91）：非对称=入端 PE 一次 MAC+IP 查找、无需 routed VXLAN、全 PE 全业务全 ARP、只靠 RT2、简单欠扩展；对称=两端 MAC+IP、需 RT5 强制、业务按需部署、可扩展但 4 变体。AOS 现支持 host-based 非对称；对称 8.10R1 不支持（配置入口 fabric-vpn 仅为示意）。
3. **非对称 IRB 硬前提**：每个 EVI 在所有交换机（含 Spine）实例化 + 每业务有 operational 端口 → Spine 用 dummy 口占位（Lab 1/1/24、指南 1/1/48）。
4. **DAG 三规则**：同一 EVI 所有 Leaf 网关 IP 相同（惯例 .254，任播非冲突）；`ip anycast-gateway-mac auto` 生成虚拟 MAC 00:00:5E:00:01:XX（XX=虚拟路由器 ID，按 VRF 统一）；RT2 同时通告硬件+虚拟 MAC。
5. **RD/RT 公式**：RD=SystemIP:EVI（8 字节 Type-1，基于 Loopback0）；RT=target:AS:EVI；export RT 与接收方 import RT 匹配才导入；ES-Import RT 自动从 ESI 编码、加在 RT4 上。
6. **ETag 服务模型**：VLAN-based（一对一、ETag 恒 0）/ VLAN bundle（多 VLAN 共域、ETag 恒 0）/ VLAN-aware（ETag=VLAN ID）；AOS 实现 bundle+aware 的 hybrid，按 ETag 汇总撤收。
7. **路由类型速查（RT1-RT8）**：RT1 以太网 AD（aliasing/备份/水平分割/批量撤销；RT1A per-ES ETag=0xFFFFFFFF，RT1B per-EVI）；RT2 MAC/IP（主机可达+ARP 抑制）；RT3 IMET（VTEP 发现+BUM 复制）；RT4 ES（同 ES 发现+DF 选举）；RT5 IP 前缀（RFC 9136）；RT6-8 SMET/IGMP-MLD（RFC 9251）。基础通告主要用 RT1-RT4。

## A1 · 书中案例

- Lab2 双业务（p102-108）：service 100/200（VNI 1000/2000）共用口 1/1/7，SAP 1/1/7:10 与 1/1/7:20；验证五连：`show service evpn`（双业务 Up）→ `show service evpn ethernet-segment`（SH[L-A]+SH[R]）→ `debug evpn show bgp route-type rt3`（4 条 IMET）→ `<esi> sap-info`（ETag-EVI 映射）→ `evi 1000 tunnel-ports`（动态 SDP 32768:100 → 远端 1.1.1.2）。
- Lab2 三层叠加（p109-117）：每业务挂 `ip interface <name> service <id> address 192.168.10.1/24`（Leaf1=.1、Leaf2=.2 各自独立），再 `anycast-gateway-address 192.168.10.254`；CE 侧 vlan 10 主机口 untagged、上联 tagged；`sh ip interface` 出现 A=Anycast 标志；Spine 的 evpn-vxlan MAC 表为 0（不学主机 MAC）。
- 课堂最小验证链（p64-74）：单边配置 Oper Down → 对端配完三条 → RT3 互收 → MAC 表 sap/sdp 双侧 → SDP 32768 建起、Oper 转 Up。可当开局 checklist：ES→service→SAP→RT3→MAC→SDP 隧道逐层核对。

## A2 · 触发场景（含与相邻 skill 的区分）

- 触发：新开一条 L2/L3 业务、加 IRB/任播网关、多租户 RD/RT 规划、查"这条路由是什么类型/为什么没导入"。
- 区分：底座与 BGP 会话 → `vxlan-evpn-underlay-bgp-design`；CE 双归/LAG/DF → `vxlan-evpn-multihoming-df`；ARP 抑制/BUM/mac mobility/排障 → `vxlan-evpn-bum-troubleshooting`。本 skill 管"业务怎么开、参数怎么定"。

## E · 可执行步骤

1. 双端 Leaf：`interfaces 1/1/7 admin-state enable` → `service access port 1/1/7 evpn-ethernet-segment enable` → `service 100 vxlan vnid 1000 bgp-evpn enable` → `service 100 sap port 1/1/7:10`。
2. 若需三层：每 Leaf `ip interface <n> service 100 address 192.168.10.<leaf号>/24` + `ip anycast-gateway-mac auto` + `anycast-gateway-address 192.168.10.254`。
3. 非对称 IRB 场景：Spine 用 dummy 口重复 service/sap 两条命令补全实例化。
4. 验证：`show service evpn` Up、`show service 100 proxy-arp config` 四参数、`sh mac-learning evpn-vxlan`、`debug evpn show bgp route-type rt2`（含 MAC+IP 双条目）。
5. 多租户规划按公式算 RD/RT，跨 EVI 互通靠 import/export RT 匹配设计。

## B · 边界与陷阱

- **Spine 漏配业务**（非对称 IRB 最常见翻车点）：忘配 dummy 口则 IRB 路由上下文不完整；规避只能等对称 IRB（8.10R1 不支持）。
- **教材笔误**（p113）：client 9/10 的网关原文误写 192.168.30.254，正确应为所在 VLAN 的 192.168.20.254——照抄必不通。通用教训：主机网关必须逐字等于该业务 anycast-gateway-address，DAG 排障第一步就核这个。
- Anycast 虚拟 MAC 按 VRF 设置，同一 VRF 各子网接口共用一个；漏配导致主机迁移后网关 MAC 漂移。
- 业务默认值（p67）：MTU 9194 / VPN IP-MTU 1500 / Hybrid 组播 / Proxy-Arp Ena / Unknown-Mac-Route Ena / Mac-Vrf-Hw-Lrng Dis——核对 `show service` 输出时按此基线。
- 对远端 ES 执行 `sap-info` 会报 "Not supported for Remote ES"，本地/远端命令选择见 multihoming skill。
